# Windows 路径、云端和回收站安全

## 路径

- 执行只接受 `^[A-Za-z]:\\` 本机路径。UNC、NAS 和网络映射只允许候选发现与盘点。
- 比较路径时先取绝对路径、统一分隔符并移除末尾分隔符；边界判断必须包含目录分隔符，不能只用字符串前缀。
- 枚举和哈希使用 `\\?\` 扩展路径 API。目标 API 不支持扩展路径时，将对应项标为 `hold_unsupported`。
- 来源、目标、审计目录和保护路径不得重叠。不得接受通配符、`..` 穿越或未展开环境变量。

## 目录树

- `merge` 在计划前生成完整目标树。普通资料默认采用浅层分类；代码、独立 Git、论文、实验、原始数据、结果数据和审计记录按实际工作保留必要层级。
- `group` 只增加共同父目录和各项目 `target_name`，项目内部结构保持不变，不自动平铺。
- 最终验收必须与批准树逐项一致。旧套壳路径、额外空目录和未批准根目录文件都视为结构变化。
- `mapping_rules`、目录例外和空目录保留项必须随批准树进入计划哈希，不能在执行后临时补充。

## 重解析点和云端占位

读取 reparse tag。带 Name Surrogate 位的 junction 和 symbolic link 只登记链接本身，不跟随目标。

百度云等占位项可能使用非 Name Surrogate tag。目录可以枚举，但带 `Offline`、`RecallOnOpen` 或 `RecallOnDataAccess` 属性的文件不得打开或哈希，统一 `hold`，等待用户将其完整下载到本地。

加密、稀疏、多硬链接、额外数据流和无法证明语义保持不变的特殊项不得自动复制或移动。

## 回收站

个人和项目文件只通过 Windows Shell 支持的回收站 API 处理。执行前再次核对绝对路径、大小、时间、SHA256、目标副本和批准清单。

测试使用隔离的模拟回收站目录，不得污染真实回收站。技能不调用“清空回收站”；用户手动清空后，重新检查来源路径、保留副本、bundle 和磁盘空间。
