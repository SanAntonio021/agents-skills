# 使用本地 PPT 模板或已有汇报

用户只需说：“以后按这份 PPT 做每日汇报”，并提供本地 `.pptx` 或带样页的 `.potx` 路径。下面的检查与配置由 Codex 完成，不要求用户填写对象编号或制作 JSON。

## 首次使用

1. 读取原文件并记录 SHA-256。在任务过程目录操作副本，保留原稿；微信文件常带只读属性，需要预览时只清除副本的只读属性，不改变原文件。
2. 用 `python scripts/template_deck.py inspect --template <本地路径> --out <过程目录>/template-inspection.json` 列出样页和对象。将副本通过 `libreoffice-runner` 转 PDF 并查看逐页图片；结合视觉和对象清单判断哪些是标题、日期、正文、结果总结、图件和图注。
3. 选择适合本次内容的样页。保留实际物理尺寸、母版、背景、Logo、分隔线和样页文字样式，不套默认粉色总结条。已有汇报中的日期、业务文字和实验图都是待替换内容；不能因为出现在模板里就当成这次工作成果。
4. 在当前汇报项目的过程目录生成 `template-spec.json`，映射本次要用的版式。位置、标题和图文角色可以从样页明确判断时直接处理；只有多种解释会明显改变页面时才询问用户。模板只有母版、没有可用样页时，明确缺少样页，先取得或制作一页供核对，不宣称可以直接套用任意空白母版。
5. 按下文 `prepare` 命令生成标题字号明确的模板副本和新映射，再用 `--template-test` 生成样例。样例必须覆盖映射中的每一种版式，每页自动标明“模板适配测试，非科研结果”；替换旧正文与图件，检查母版风格、文字可编辑性、图片位置及旧内容残留。实际渲染及逐页查看通过后运行 `accept` 保存验收记录。首次选稿可让用户看样例；已有有效记录时复用，不重复确认。
6. 在当前项目已有的汇报说明或记录中记住模板原路径、哈希及映射路径；后续日报在同一项目沿用。模板路径不存在或内容发生变化时重新检查，不直接沿用旧对象编号。模板及映射只保存在用户本机，不提交进公开技能。

## 映射文件（由 Codex 生成）

```json
{
  "template_path": "<实际模板路径或相对本JSON的路径>",
  "layouts": {
    "result": {
      "slide": 1,
      "keep_shape_ids": [],
      "slots": {
        "title": 2,
        "date": 3,
        "summary": 4,
        "body": 5,
        "images": [6, 7],
        "captions": [8, 9]
      }
    }
  }
}
```

上面的对象编号只是说明，必须用检查到的真实编号。`slide` 从 1 开始。只写实际存在的文字槽；正文有内容但缺对应槽时须先补齐映射或选择另一版式，不丢弃文字。`keep_shape_ids` 只列明确要保留的本页装饰对象；母版和版式中的固定元素自动继承。没有被保留或映射的本页对象会移除，以免携带旧成果。

图槽使用独立图片，按顺序填入；图注与图槽一一对应。图件少于槽位时移除多余图槽，超出时拆页或换版式，不强行塞入。默认保持原框并等比放入新图，不继承旧图裁切。此模式复用静态版式，会移除动画和切换效果；用户要求保留动画时应使用其他已支持的 PPT 工具单独适配。复杂页中的表格、图表、SmartArt、OLE 和外链不属于此版本的自动替换范围，出现不支持的保留对象时停止该页，说明需要单独适配。

需要调整局部空间时，在对应版式写 `shape_overrides`，按对象编号指定 `box_emu: [x, y, width, height]`。仅用于已确认的对象，尺寸为正且保持页内；不以它更换全稿母版。比如从普通进展页生成“下一步工作”页时，移除旧图，将已映射的正文框扩展为足够容纳编号列表的区域，再检查渲染。

## 用于日报

deck JSON 增加 `"template_spec": "<prepare 输出的新映射文件路径>"`，各页可写 `"template_layout": "result"` 或自己定义的版式名。末页类型为 `next_steps` 时，映射中也要提供 `next_steps` 版式及足够大的 `body` 槽。用户提供模板的普通日报必须沿用同一个 `render_deck.py` 的原生模板入口；缺少映射、适配失败或验收记录无效时停止正式生成，不静默换用内置模板，也不临时使用 python-pptx 删页或拼接包结构。已有复杂制作工程需要其他工具时单独适配、检查，不能把它当成本入口失败后的自动回退。

原生模板模式与 `profile_path` 二选一。此模式中的字体与对象位置来自样页，默认样式模式的 `font_sizes`、`layout_overrides` 和 `body_fraction` 不用于改写样页；需要改位置时使用映射的 `shape_overrides`，需要改字体时调整本地模板副本。

新稿进展页仍分别提供 `project`（真实项目名称）和 `title`（本页主题），在映射的 `title` 槽中以同一行原生文字呈现，中间三个 ASCII 空格。项目大标题沿用样页标题字号并加粗，本页小标题按 PowerPoint 字号档缩小两次、不加粗，例如 36 → 32 → 28 pt；这是标题内部的层级，不改变模板母版、配色或正文样式。标题槽不足时在副本中调整可用宽度并检查渲染，不能删掉项目名或把两者合并成同样样式。旧稿只有 `title` 时保持单标题兼容；末页 `next_steps` 使用“下一步工作”单标题，不强套项目名。

项目大小标题需要副本样页标题明确设置字号。`prepare` 先读取标题首段首个文字样式和段落默认样式，再检查列表层级、匹配的版式与母版占位符、母版文本样式及演示文稿默认文本样式，仅将能确定的实际字号写入新副本。主题字体名称本身不提供字号，不能据此猜数值。已有字号与配色保持不变，不修改原模板。

## 准备、样例和验收记录

以下操作由智能体完成，路径使用项目过程目录的实际新路径；命令中的文件名只是示意。

```text
python scripts/template_deck.py prepare --spec template-spec.json --output-template template-adapted.pptx --output-spec template-adapted.json
python scripts/render_deck.py --deck template-test-deck.json --output-dir template-test-v01 --base-name template-test --template-test
python scripts/template_deck.py accept --spec template-adapted.json --manifest <样例实际manifest路径> --visual-inspected
```

准备入口输出新模板副本、新映射和标题字号检查结果。新映射保留原模板绝对路径及其 SHA-256、副本路径及准备时的 SHA-256。模板或副本在准备后改变时，重新准备到新的输出路径，再测试；不要求用户清除缓存。命令从映射所在目录解析相对模板路径，不依赖当前工作目录。

标题字号无法确定时，错误会报告版式、页码和对象编号，不输出半适配文件。已有用户指定的实际字号时，增加 `--title-size-pt <实际值>` 重试；没有依据时只询问实际字号。该参数仅补充无法解析的标题，不能重设所有已有字号。副本需要调整标题宽度或明确修改字号时，由智能体先修改副本，再重新 `prepare` 生成新版本，原稿始终保留。

样例 deck 使用 prepare 输出的新映射，覆盖其中所有版式，并使用明确标为合成或演示的图件，不把样例内容写成科研结果。`--template-test` 只允许生成带逐页标识的测试稿，不能用来绕过正式稿验收。正式生成的公共 Python 入口同样检查验收记录，不能靠绕过 CLI 规避。

`accept` 需要版本 3 的实际渲染清单，其中 PPTX 生成、结构、LibreOffice 渲染和 PNG 输出均已通过，每页有对应 PNG，且 PPTX、PDF、PNG 文件哈希匹配；还检查每页测试标识和版式覆盖。只有实际逐页查看后才传 `--visual-inspected`，该参数记录操作者完成查看，不自动判断画面质量。PowerPoint 原生验证独立保留，未执行不记通过。

验收记录默认写在映射同目录的 `<映射名>.adaptation.json`；可以在映射中显式指定 `adaptation_receipt`。显式路径与 `accept --out`（若传入）必须一致，避免记录写到了正式生成不会读取的位置。所有输出均不覆盖已有文件；需要更新验收时，使用新的模板和映射版本，或把映射的验收引用指向一个新文件。记录绑定原稿、副本、映射的规范化哈希，以及样例 PPTX、PDF、PNG 和渲染清单哈希。映射哈希排除 `adaptation_receipt` 引用，避免循环依赖。

正式生成前会检查记录是否存在、版本是否受支持、所有检查是否通过、版式是否全部覆盖，以及模板、映射和样例证据是否仍然匹配。旧映射没有记录、模板变化、映射变化或证据文件被修改／移除时，必须重新适配。有效记录不因生成新一天的汇报而失效。

## 验收

- 原文件 SHA-256 不变，新 PPT 与模板物理宽高完全一致。
- 检查新 PPT 所有页面、图注和包内旧内容；旧页面、备注与不再引用的实验图片不可残留。母版或版式本身含旧业务文字时，先在模板副本中清理再映射；它们会被保留，不能假定全部是装饰。
- 核对新日期、标题、正文、图件与用户确认内容；标题和正文是原生文字，图片可以独立移动替换。
- 核对进展页项目大小标题同一行、三个 ASCII 空格及字号和加粗层级。结果句准确区分仿真、离线或实测后，删除重复防御性句子；保留会改变结论的条件和解释限制，后续实机安排集中末页。
- 逐页查看实际 PPT 渲染，确保无溢出、遮挡、缺图或默认样式混入。预览宽度为 1600 像素，高度随模板比例计算，不把 4:3 页面拉伸成 16:9。
- 分别记录结构、LibreOffice 渲染与 PowerPoint 原生验证结果，未完成的检查如实注明。
