# 资料与选材

本文件负责事实、选材和图文证据；页面写法见 [中文表达](chinese-style.md)，确认与授权见 [主流程](../SKILL.md)。

## 采集本期记录

日报先盘点本期会话和项目记录，形成供用户审阅的概览依据；此阶段不定向搜图、读取飞书素材或索要文件。完成记录盘点后只问一次遗漏的口头补充，收到回答后展示总览，按主流程依序完成总览与展开清单两道确认。用户主动限定的日期、项目或来源优先。周报沿用用户确认的范围，范围不明时先询问，不自行盘点后决定讲什么。随附采集器只读取本地文件，不主动联网。Windows 需安装 `tzdata`；从技能根目录运行：

```text
python scripts/collect_sessions.py --mode today --out "<project-root>/过程文件/<任务>/brief.json"
python scripts/collect_sessions.py --mode week --out "<project-root>/过程文件/<任务>/brief.json"
```

指定项目加 `--project-root <project>`，只取该项目及子目录，不混入名称前缀相似的其他项目。已知素材目录用可重复的 `--asset-root <directory>`，已知照片用 `--context-image <photo>`；先从项目记录定位，不要求用户每天重新指定。

默认读取：

- Codex：`%USERPROFILE%/.codex/sessions/**/rollout-*.jsonl`，以及 `session_index.jsonl` 在时间窗口内更新的归档条目。按 session ID 匹配归档文件，不对整个归档目录执行 stat。仅用户要求排除归档时用 `--no-include-archived`。
- Claude Code：`%USERPROFILE%/.claude/projects/**/*.jsonl`。自定义位置用 `--codex-root`、`--claude-root`，不扫描其他账号。

事件时间转换为 `Asia/Shanghai`，跨日会话按实际事件纳入。按 `root_id` 归并，子智能体记录作为辅助证据，不列成独立工作。

采集器保留用户消息及有用结果，过滤系统提示、hidden reasoning、token telemetry、命令回显和工具内部信息，并遮盖常见凭据。结果关键词只用于找候选，不能替代科研价值判断。不要打印原始会话或放入 PPT；采集摘要只用于当前任务，不提交公开仓库。

日报完成记录盘点后、展示总览前，只问一次：“还有记录里没提到、但本期需要汇报的工作吗？比如帮老师做的事。” 用户已在当前对话主动补充时不重复问。把回答作为本期工作来源并纳入待确认总览；素材搜寻和详细事实核对延至两道确认后，只有关键事实不清且影响表述时才追问。

采集为空时检查可读性和来源范围，再使用用户提供的记录与图件，不据此判断当天没有科研工作。

## 核实事实与状态

会话说明与项目记录、实际产物交叉核对，后续可靠证据和用户更正优先，删除已解决问题。已完成须有对应产物；进行中或遇到问题按实际进展和现象表达；下一步须为用户或项目记录已确定的安排。

区分方案、仿真、离线验证、原型和实测；软件通过不等于硬件通过，计划不等于结果。旧数据可用于本期分析，但采集与分析时期分别表达，不从文件时间或常识推断事实。核对具体参数的方法见逐页核对表，必要信息的取舍见中文表达参考。

## 决定讲什么、讲到什么程度

优先汇报有证据的结果或技术判断、研究问题与方法的实质推进、关键障碍，以及有科研价值的交付或实验能力。论文明确研究贡献、方案确定物理关系、程序实现新的实验能力，都可按实际状态纳入，不要求先有定量结果。

常规改字、格式、编译、保存重绘和检查次数通常简述或留记录。账号、代理、磁盘、一般软件排障和技能维护排除在候选、正文及附录之外；行政事项须代表科研或项目里程碑。实验代码按科研作用判断，不一概排除，也不罗列按钮和接口。

完整盘点入选工作，按科研问题归并重复运行。在已有过程记录中保留“工作、本期推进、来源、取舍及理由”，确定页面后补页码：

- **展开**：有总览之外值得解释或讨论的内容，并有材料支持。
- **总览简述**：值得交代进度，但无需展开，或用户指定简述。
- **留记录**：重复材料、内部执行检查及无关事项，保留原始依据。

已确认必须讲的内容不能遗漏，但盘点不等于全部展示；不按会话、图片、产物数量或固定每项目页数安排。仅在理解本期工作需要时回溯原因、背景和历史限制；关键缺口查不到再问，其他工作继续，不强制追问每项动机或猜后续计划。

## 复用与核对素材

两道确认均完成后，集中核实入选工作的关键事实和素材一次。先查实验记录、会话引用及已有分析，再按项目定向补充结果图、实物照片、系统图和适用的历史对照。特别查找相关飞书文档中的测试照片、结果图和系统框图；飞书正文、表格和画板用对应技能实际读取，PPT/PDF 图件用相应技能提取并保留页码。展开页优先采用能直接支撑本页结论的真实图件。现稿及用户修改优先于过期副本。

图片搜索限于相关项目。采集器把 5 秒、2,000 个文件预算分配给各目录，排除依赖、技能资源和符号链接；不足时定向进入已知产物目录，不遍历同步盘。运行时图标、Logo 不作为实验素材，`role`、`period`、`status=unverified` 仅是候选标记。

清晰、准确、适用的材料直接复用；缺失、过密或不能说明当前问题时才裁切、标注、重绘或补写。加工副本保留原件及关键标签，不为统一风格重画，不用生成图片替代实验或文献曲线，新示意图不作为实测证据。

## 排版前逐页素材核对

在已有过程记录或素材清单中按页记录以下信息，供内部核对，不要求用户填写或逐页审批：

| 核对项 | 记录内容 |
|---|---|
| 页面重点 | 标题与拟用的一句结论；无配图页记录正文依据 |
| 图片来源 | 实际文件或文档入口、页码/图片位置、版本和内容哈希 |
| 对象与条件 | 图中设备或系统、测试位置、时间、驱动/本振/接收条件，以及仿真或实测状态 |
| 图内小字与参数 | 放大读取与结论相关的型号、端口、频率、单位、功率、带宽、状态和图例，与原记录对照 |
| 支持的结论 | 图直接显示什么，哪些判断还需要文字记录或对照证据；不把观察自动写成原因 |
| 核验状态 | 已核对、存在冲突或待核实，以及具体缺项与处理方式 |

实际查看每张候选图并与文字、记录交叉核对；相似文件名、外观或较新日期不能证明适用，旧台架照片也不因时间早而排除。放大读小字后，仍须确保成稿整页可读。裁切、换图或改结论后更新相关记录。来源、哈希和核查过程留在清单，不默认写上页面。

例如发射输入与接收本振频率须分别核实，不能把正文统一改过的频率套到所有端口。

冲突或缺图先查原记录及最新证据；手工稿也须核对参数和图注。仍无法核实且影响页面含义时只问关键缺口，其他页面继续。不用相似图、长段文字或占位图代替必要证据。用户允许留空时可保留插图区域，缺图记在内部清单并说明未完成，不在正文堆占位解释或当作完整结果交付。
