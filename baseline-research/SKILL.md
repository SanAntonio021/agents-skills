# 基线调研

## 作用

这份 skill 把基线研究做成“可继续、可暂停、可复核”的项目工作流，而不是一次性抓取。

## 流程与产物

1. 读取已有任务说明、比较口径和证据记录；沿用项目现有文件，不默认新建任务池、设计单和多个账本。
2. 在大量扩展前核对目标、范围、维度、关键指标和证据标准。已有明确口径直接使用；尚未确定字段或单位时，用少量真实样本验证。
3. 样本暴露实质歧义时只询问该项；已确定口径不再暂停，也不与 `product-research-workbook` 重复确认。
4. 继续扩展并补全关键指标来源，记录无法核实的缺项。工程产品参数表交给 `product-research-workbook`，证据充分后的报告正文交给 `research-report`。

需要新增记录时可参考现有 task_pool_template.md 和 design_sheet_template.md，不强制模板齐套。

## 证据规则

- URL 不是证据本身。
- 每条关键记录尽量落到可访问页面、页面标题和支持摘录。
- 证据链未闭合时，明确标为待复核，不假装已验证。

## 浏览器复核

静态抓取弱、受阻或页面逻辑复杂时，切到 Playwright 交互式抓取（经 `web-access` 技能提供的浏览器能力）。

常见触发信号：

- `403`
- `404`
- 只落到首页
- JS 渲染导致静态内容缺失
- 跳转异常
- 指标记录和引用页面互相冲突

## 边界

- 不用于持续监控。
- 不用于没有项目产物承接的泛文献综述。
- 不把它当成一次性查事实的普通 skill。
- 证据标准未定前，不跳过 sample 阶段。
- 已有证据需要组织成行业、市场、技术或政策调研报告时，由 `research-report` 接管内容结构和写作。

## 汇报方式

每轮结束时，至少说明：

- 当前阶段
- 新建或更新了哪些文件
- 哪些记录仍有来源冲突或证据缺口
- 尚需决定的实质问题（没有则省略）

## 维护

- 保持它专注于分阶段基线调研，不外溢成泛用研究 skill。
- 如果项目模板变化，优先改模板，再回到这里保持正文简洁。
