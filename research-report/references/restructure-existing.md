# 旧稿重构

## 原则

旧稿重构的目标是重新分配信息职责，不是在原模板上换标题、删套话或逐句改写。读取当前原稿并保留用户修改，新稿沿用已确定的主稿和交付形式；Word 使用 `docx`，PPT 使用 `pptx`，不强制先制作 Word。

正式新稿只写有已核实事实支撑的内容。无依据内容、来源待补项和编写者的后续取证任务转入内部调研台账或重构映射表，不能用更委婉的措辞留在新稿。`evidence_report` 不新增决策安排，原稿中的行动建议转入内部记录；`decision_report` 保留有依据、适用条件和风险边界且在本轮授权范围内的建议，并按 [decision-report.md](decision-report.md) 处理。模式允许建议不等于用户授权新增建议；局部润色、形式调整或提取摘要不自动扩大为决策安排。

两种模式都保留有材料支持、确实影响判断的对象状态和适用限制，例如未验收、未测试、非销售版本。它们不是编写者的取证待办，不能因含“尚未”“不能”等词而删除，也不能改成已完成或新的执行条件。摘要只保留限制其结论的必要状态，不逐项复述核对过程。

## 1. 固定源文件

开始前记录：

- 绝对路径、文件大小、修改时间和 SHA-256；
- 能否安全读取以及使用的提取方式；
- 图片、表格、脚注、批注和修订的数量；
- 用户明确要求保留的部分。

不要覆盖原稿。DOCX 读取和导出遵守 docx，不因“只是重构内容”而启动或接管 Word。

## 2. 建立内容清单

按段落或逻辑块核对内容去向；复杂重构需要映射表时，按需选用以下字段，简单修改复用原稿批注或现有记录：

| 字段 | 含义 |
|---|---|
| source_location | 原章节、段落或表格位置 |
| primary_type | D/F/J/R/U |
| claim | 该块真正想表达的内容 |
| evidence | 原有引用、数据或文件位置 |
| reader_value | 对目标读者是否必要 |
| action | 保留、移动、拆分、合并、压缩、删除、转入内部台账 |
| ledger_id | 关联的内部台账记录；正式稿不出现该编号 |
| new_location | 新稿位置或删除理由 |

内容清单用于防止重构时静默丢失已核验事实。删除项要有理由，例如重复、超出范围、无证据、与当前模式不符的行动建议或只是在解释常识。

R 表示原稿中的建议或行动语句。在 `evidence_report` 中，映射表的 action 记录为“删除”或“转入内部台账”，并写明理由，不把行动建议改写为“结论成立所需的证据条件”后保留。在 `decision_report` 中，有依据且在授权范围内的建议可保留、移动或拆分，记录其依据和新位置；无依据或超范围内容仍转入内部记录。已批准安排的来源事实与作者提出的新建议要分别判断，不能只凭行动词归类。

优先复用原稿引用和已有来源记录，按需补齐真实题名、发布主体或作者、日期、文号、DOI、URL、本地文件位置和原稿内部编号；复杂映射才另建来源清单。S-01 等编号只用于新旧稿映射；正式稿引用必须落到真实来源条目。来源信息或事实尚未闭合时，在已有记录中标明待核实项，不根据上下文补造，也不进入正式稿。

## 3. 找出混写

重点检查：

- 摘要大部分篇幅在解释名词；
- 主体发现段重复“X 是……”的术语定义，再接事实或判断；
- 同一段先解释术语，再列公开进展，最后加入开发行动指令；
- 产品清单、技术原理和市场判断交替出现；
- 法规原文与作者的合规判断写成同一句；
- 工程设想用肯定语气写成已经验证的结果；
- 同一结论在摘要、章节开头、章节小结和全文结论重复出现。

完整报告需要脚本审计时，按当前报告模式选择一条命令：

    python scripts/audit_report.py extracted.md --mode evidence-report --json
    python scripts/audit_report.py extracted.md --mode decision-report --json

脚本输出只用于定位候选问题，不以零命中作为验收目标。即使警告文字要求“删除”或“移入内部台账”，也要结合模式、授权、来源和当前判断复核：保留必要的真实状态与限制，保留决策稿中有依据且获授权的建议；删除无信息作用的防御性套话。脚本允许行动词也不能替代用户对新增建议的授权。

## 4. 重建信息顺序

结合已有提纲梳理以下问题；需要说明结构变化时简要记录，不固定另写文件或页数：

1. 读者先要知道哪些结论；
2. 哪些定义会改变这些结论的含义；
3. 每条结论需要哪些已闭合事实支撑；
4. 哪些技术背景应移到单独章节或附录；
5. 哪些行动建议按当前模式和授权保留，哪些应删除或转入内部记录；
6. 哪些原稿内容应转入内部台账并继续调研。

不要沿用原章节数作为约束，也不要为了“像报告”补齐市场规模、竞争格局、趋势预测和战略建议。

这些问题只用于内部重建顺序。正式目录要把它们转换为对象明确的名词短语或结论句，不直接使用“这份报告要判断什么”“当前应如何推进”等口语问题式标题。

## 5. 按职责重写

推荐顺序：

1. 先写事实段，保留来源、时间和适用范围；
2. 再单独写综合判断，明确它依赖哪些已经写明的事实；
3. 按当前模式和授权处理行动建议，决策稿中保留的建议与来源事实分段；
4. 将无依据数字、未闭合来源和后续取证事项转入内部台账；
5. 最后补最少必要定义，并写摘要。

摘要概括可确认的事实和已形成的结论，保留确实限制该结论的对象状态和条件；决策稿按本轮授权概括有依据的建议，不自行增加建议。摘要不写编写者的资料缺项、引用元数据状态或后续取证安排，也不把章节首句、四字短标签或连续否定拼成清单。

表格只保留可比较项。不同版本、不同统计方式或不同时间的参数不能因为列名相同就并排比较。

## 6. 全文去重

对每个重复结论只保留一个完整展开位置：

- 摘要保留结论，不展开定义和论证；
- 主体章节保留证据和分析；
- 附录保留术语、方法和详细表格；
- 内部台账保留过程记录，不作为报告附录。

删除“本节主要介绍”“通过上述分析可以看出”等没有增加信息的句子。

## 7. 验收

生成新稿后核对：

- 原稿中每条已核验关键事实都有新位置或删除理由；
- 引用仍支持它旁边的事实，没有因移动段落而错配，也没有新增来源或补造元数据；
- 正式稿已将 S-01、S01 等内部来源编号转换为真实来源对应的脚注、尾注或参考文献编号；内部编号只留在映射表或台账中；
- 摘要中没有成组的名词解释；
- 摘要使用连贯自然段，没有把研究对象、主要发现和结论写成逐段短标签；
- 定义只在范围或背景位置出现一次，主体发现段不再重复名词解释；
- 正式标题没有照抄口语化读者问题；
- 正文目的陈述使用评估对象、判定事项或比较对象等专业表述，不写“帮助团队判断”“供读者弄清”；
- 事实段不以作者的行动建议收尾；证据稿不含决策安排，决策稿的建议有依据且在本轮授权内；
- 工程方案、模拟结果和实测结果的状态没有被改写；
- 无依据论断、待补来源元数据和编写者的取证任务只在内部记录可见；真实且必要的对象状态和适用限制仍在对应判断处保留；
- “尚未公布、尚不能说明、不宜、建议、下一步”等词已经过语境复核，不按词语一律删除，也不为消除脚本命中而改变事实或授权范围；
- 正式稿没有“不是没有、并非不存在、不能不”等连续否定，也没有“在一定程度上、相对而言、某种意义上、不排除”等无证据作用的弱化限定语；
- 无背景读者能说出报告问题、主要发现、正式引用和综合判断。

正文协作沿用 [writing-router 的文稿协作](../../writing-router/references/collaborative-writing.md)，再进入所需文件技能的制作和检查流程；已有明确正文和模板时复用，不为跨技能交接重复确认。
