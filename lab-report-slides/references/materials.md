# 资料与选材

开始核实材料、选择工作和详略前读取本文件。完整盘点用于内部防遗漏，汇报按研究推进取舍。这里负责事实、来源和哪些工作值得讲；选定内容怎样组织成页面见 [内容与中文表达](chinese-style.md)，授权沿用 [主流程](../SKILL.md)。

## 采集本期记录

随附采集器只读取本地文件，不主动联网。Windows 需安装 `tzdata`；从技能根目录运行：

```text
python scripts/collect_sessions.py --mode today --out "<project-root>/过程文件/<任务>/brief.json"
python scripts/collect_sessions.py --mode week --out "<project-root>/过程文件/<任务>/brief.json"
```

指定项目加 `--project-root <project>`，只取该项目及子目录，不混入名称前缀相似的其他项目。已知素材目录用可重复的 `--asset-root <directory>`，已知照片用 `--context-image <photo>`；先从项目记录定位，不要求用户每天重新指定。

默认读取：

- Codex：`%USERPROFILE%/.codex/sessions/**/rollout-*.jsonl`，以及 `session_index.jsonl` 在时间窗口内更新的归档条目。按 session ID 匹配归档文件，不对整个归档目录执行 stat。仅用户要求排除归档时用 `--no-include-archived`。
- Claude Code：`%USERPROFILE%/.claude/projects/**/*.jsonl`。自定义位置用 `--codex-root`、`--claude-root`，不扫描其他账号。

事件时间转换为 `Asia/Shanghai`，跨日会话按实际事件纳入。按 `root_id` 归并，子智能体记录作为辅助证据，不列成独立工作。

采集器保留用户消息及有用结果，过滤系统提示、hidden reasoning、token telemetry、命令回显和工具内部信息，并遮盖常见凭据。结果关键词只用于找候选，不能替代科研价值判断。不要打印原始会话或放入 PPT；采集摘要只用于当前任务，不提交公开仓库。

采集为空时检查可读性和来源范围，再使用用户提供的记录与图件，不据此判断当天没有科研工作。

## 核实事实与状态

会话说明须结合实际项目记录和产物核对。后续可靠证据、用户当前更正优先，删除已解决的问题，不从常识补齐缺失细节。

| 状态 | 依据 |
|---|---|
| 已完成 | 记录及实际产物支持所声称的完成内容 |
| 进行中 | 有真实工作，但尚无最终结果 |
| 遇到问题 | 有明确现象、失败或未解决的差异 |
| 下一步 | 用户已确认或项目记录已确定的安排 |

进一步区分方案、仿真、离线验证、原型和实测。软件检查不能证明硬件通过；计划不能写成结果。旧实测可以支持本期分析，但采集时期与分析时期分别表达。

选用的数字、单位、设备、端口、条件和状态必须准确。原始数据、文件名、错误与核查过程保留在来源记录中，是否进入页面由其对当前判断的作用决定。证据缺口在内部记录标明，页面按必要信息判断处理，不把全部缺口搬成免责声明。

## 决定讲什么、讲到什么程度

先看听众需要了解的研究推进，再决定用哪些产物说明。优先选择：

1. 有证据支持的科研结果、比较或技术判断。
2. 研究问题、方法、方案或论证的实质推进，以及需要导师讨论的关键障碍。
3. 有科研价值的交付或实验能力进展，包括直接解除科研阻塞且已经验证的支撑工作。

没有定量结果不等于没有进展。论文明确了研究问题或贡献、方案确定了关键物理关系、程序实现了此前做不了的实验，都可按实际内容汇报。常规改字、同步格式、编译成功、保存重绘、检查次数通常只需概述或留在记录中，不能凭产物数量提升优先级。

账号、代理、磁盘清理、一般软件排障和技能维护排除在科研候选、正文及附录之外。行政事项只有代表实质科研或项目里程碑才纳入。代码涉及实验或分析时按实际科研作用判断，不一概排除开发，也不把按钮和功能清单当作研究进展。

范围明确后，完整盘点入选项目的实际工作，按科研问题归并重复运行。在已有过程记录中保留简短取舍：工作、本期推进、来源、展开/总览简述/留记录及理由；确定页码后补页码，不为每个产物预分一页。

- **展开**：有值得单独解释或讨论的内容，且材料足以支持。明确本页重点，再选图和条件。
- **总览简述**：值得交代进度，但没有需要展开的新内容，或用户指定仅简述。
- **留记录**：重复材料、内部执行与验证细节、无关事项；保留原始依据，不搬进汇报。

已确认必须讲的内容须有对应表达，可以合并；不得凭几张醒目图片漏掉其他重要进展。盘点完整也不要求全部展示。详略由内容价值、用户选择和理解需要决定，不按会话条数、图片数量或固定每项目页数安排。

仅在理解本期工作需要时回溯原因、背景或历史限制。查不到会改变事实或关键范围的信息时补问该缺口，继续其他已明确工作，不为每项强制追问动机或猜测后续计划。

## 复用与核对素材

优先读取已有实验结果、分析、飞书正文和表格、飞书画板、系统图及旧报告。采集器不自动读取飞书；发现相关入口后使用对应技能读取实际内容。先核对版本、对象、条件和适用性，现稿及用户修改优先于过期副本。

准确、清晰且适用的材料直接复用已有结论。只有缺失、过密、不清晰或不能表达当前问题时才裁切、标注、重绘或补写；加工副本不覆盖原件，不为统一风格另画一套。裁切保留影响判断的标签和条件，新示意图不作为实测证据。

图片搜索先查会话引用，再按项目有界补充。采集器默认把 5 秒、2,000 个文件预算分配给各目录，排除代码依赖、技能资源及符号链接；扫描不足时定向进入已知产物目录，不遍历整个同步盘。

图件选择顺序：

1. 记录直接引用且已核对的结果图。
2. 项目中对应本期工作的曲线、分析图或实物照片。
3. 能解释当前装置的系统图、台架照片及明确标注时期的历史对照。

逐张实际查看；近期文件不自动成为新结果，旧台架照片也不因时间较早而排除。`role`、`period` 和 `status=unverified` 只是候选标记。运行时图标、Logo 等界面资源不作为实验素材。

已有 PPT、PDF 或报告中的图片用相应技能提取，保留文件与页码来源。缺少支撑结论的必要图件时先定位，确实缺失则说明具体缺项，不用长段文字、无关图片或占位图凑成品。

每张采用的图都须服务于本页重点。来源路径、内容哈希和角色留在制作清单，不作为页面默认文字；真实图的完整来源保留，正文只展示理解当前判断所需的部分。
