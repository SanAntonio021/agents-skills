# 外部 skill 对比格式

外部 skill 检索默认作为内部判断依据，审查稿通常只用一句话说明是否有候选会改变结论。只有候选会实际影响新建、修改或不改的选择，或者用户要求详情时，才按下面格式展开。没有数据时写明原因，不补脑。

## 需要展开时的表头

| skill | 来源 | 链接 | GitHub stars | 下载/安装指标 | 匹配度 | 可吸收内容 | 本地落点 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `owner/repo@skill` | Skills CLI / skills.sh / GitHub / SkillsMP / 其他 | URL | 数字；没有就写 `未提供` | 优先写周下载量；没有周下载量就写总安装量/总下载量，并标清指标名 | 高/中/低 | 具体判断标准、字段、模板结构或测试场景；没有就写 `无` | 本地 skill 及 `SKILL.md` / reference / template / script / eval；没有就写 `无` | 可吸收 / 只可参考 / 不适合 |

## 字段规则

- `来源` 写清楚是从哪里发现的，不要只写"外部"。
- `GitHub stars` 优先查源仓库；查不到源仓库或页面不提供时写 `未查到`。
- `下载/安装指标` 优先写"一周下载量"。技能市场只给总安装量或总下载量时，可以写 `总安装量：N`，但不能说成周下载量。
- `匹配度` 只评价它和当前要沉淀经验的重合程度，不评价工具本身好坏。
- `可吸收内容` 写能改变本地候选的具体内容，不写"整体思路""值得借鉴"这类空话。高 stars 或高安装量不是可吸收内容。
- `本地落点` 必须先定位本地负责该行为的 skill；外部候选没有适合本地的内容时写 `无`，不建议为了利用检索结果而安装或照搬。
- 涉及自动监听、遥测、自动写入、自动安装、自动提交等超出当前授权的机制，在结论后用一句话列为不吸收边界。
- 候选太多时，列 3-5 个最相关的；其余用一句话说明已排除的类别。
