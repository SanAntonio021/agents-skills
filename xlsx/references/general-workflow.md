# 通用表格工作流

## 1. 判断任务类型

- `read`：读取、回答、提取、核对，不产生新工作簿。
- `create`：从零建立 `.xlsx`。
- `edit`：修改既有简单工作簿并输出新版本。
- `analyze`：筛选、聚合、透视、统计或比较。
- `convert`：CSV/TSV/XLS/XLSX 间转换。
- `preserve`：复杂模板或严格允许变化，转入 [high-fidelity-workflow.md](high-fidelity-workflow.md)。

## 2. 依赖与作者工具

先使用当前环境提供的依赖加载器。若平台规定某个表格 API 必须用于作者任务，遵守该规定；本 reference 不覆盖更高优先级的运行时契约。

没有强制作者工具时：

- `openpyxl`：读写 `.xlsx/.xltx/.xlsm`、公式、样式、表格、图表、验证和打印设置；
- `pandas`：批量清洗、聚合和表格数据转换；
- Python `csv`：需要精确控制编码、分隔符和引号时使用；
- LibreOffice CLI：隔离重算、旧 `.xls` 转换和 PDF 导出。

不要为一个小任务混用多套作者工具。每次整包保存都可能改变工作簿结构。OfficeCLI、常规库、OOXML 工具和 LibreOffice 只写任务独占临时目录中的不存在候选路径；最终路径统一按 [output-lifecycle.md](output-lifecycle.md) 发布。

## 3. 只读读取

公式与显示值需要两次加载：

```python
from openpyxl import load_workbook

formula_book = load_workbook(path, data_only=False, read_only=True)
value_book = load_workbook(path, data_only=True, read_only=True)
```

用相同工作表和坐标配对公式与缓存值。`data_only=True` 的对象只读，不保存。

读取时记录：

- 工作表名称和可见状态；
- 已用范围、表头、单位、日期期间；
- 关键值及其公式；
- 合并、筛选、冻结窗格、表格和图表；
- 空缓存、错误值和外部链接。

回答计算问题时，给出输入、公式和结果，不只给最终数字。只读任务不保存、不重算，也不默认生成预览或核验文件；用户明确要求检查已有 PDF 时，检查该文件。缓存缺失、可能过期或存在错误时说明其位置及对答案的影响，不把现有缓存直接当作已核实结果。

## 4. 新建工作簿

先设计：

1. 工作表职责；
2. 输入区、计算区、输出区；
3. 表头、单位、数据类型；
4. 公式与假设；
5. 更新者以后需要编辑的位置；
6. 打印或屏幕阅读方式。

写入原则：

- 标题和表头写一次；
- 数据连续，不在数据表中插装饰性空行；
- 数字、日期、布尔值使用对应类型；
- 派生结果写公式；
- 表格区域可用 Excel Table、筛选和冻结窗格；
- 使用 Excel Table 时由 Table 自身的 `autoFilter` 管理该范围，不得同时设置与任一 Table 范围相交的工作表级 `autoFilter`（`openpyxl` 中为 `ws.auto_filter.ref`）；
- 只在有比较价值时添加图表；
- 来源写入来源列或单元格批注。

新建公式后，用 LibreOffice 或平台计算引擎在新候选路径实际重算并核对结果；纯数据表不需要重算。新增的文字、样式和图表按第 8 节检查呈现，不默认追加打印验收。候选通过必要验证后再用 `scripts/publish_output.py` 发布到正式路径。

## 5. 常规编辑

开始前读取目标区域上下至少两行、左右至少两列，并检查同列公式和样式模式。

常见动作：

- 新增行：复制相邻行必要样式，调整公式、表格范围、验证和条件格式；
- 新增列：确认标量、文本或公式语义，更新筛选、图表和命名范围；
- 改公式：先在少量单元格验证引用，再批量填充；
- 改样式：只改用户指定或确有缺陷的范围；
- 改打印：同时检查打印区、重复标题、方向、纸张、缩放和分页。

保存到任务临时目录的新候选路径后比较源文件与候选文件。复杂对象多或差异超出预期时，放弃该候选并转高保真路线。不得让作者工具直接覆盖已存在的正式路径。

选保存方法前判断计算影响：分类名称可能被 `SUMIF`、查找或条件公式引用，不能因改的是文字就省略重算。公式及计算输入未变化、已有缓存可靠时，选择能保留公式与缓存的路径，并在保存后核对；常规库整包保存可能清掉缓存，不能仅凭公式文本未变宣称结果保留。无法确认依赖或发现缓存缺失、可能过期时，按第 8 节处理。

## 6. 分析与清洗

先保留原始数据副本或原始工作表。清洗步骤应可追溯：

- 去重前明确主键；
- 缺失值不擅自填充；
- 日期、金额、比例和单位先规范再计算；
- 文本标识符保留前导零；
- 分组合计与全表合计相互核对；
- 排序、筛选和连接后检查行数变化；
- 统计结论保留样本数和口径。

若用户要交付工作簿，把关键计算留为可审计公式或清楚的结果表，不只交脚本输出。

## 7. CSV/TSV

读取前检查 BOM、编码和分隔符。输出时明确：

- UTF-8 或用户指定编码；
- 逗号、制表符或其他分隔符；
- 包含换行、引号和分隔符的字段如何转义；
- 日期和小数格式；
- 是否保留表头。

CSV/TSV 不支持样式、合并、公式缓存、图表或多表。需要这些能力时输出 `.xlsx`。

## 8. 重算与验证

按实际影响选择检查，保持现有校验器的公式、缓存和结构检查严格性：

- **计算变化**：新增或修改公式、数值输入、被引用的文字、范围或依赖时，实际重算并核对代表性输入、结果及错误值。公式文本相同不代表结果仍有效。
- **计算未变**：公式与计算输入未受影响、缓存可靠且保存后仍完整时，保留已有结果即可；纯数据表没有重算步骤。有效缓存数量只能证明缓存存在，还需结合依赖和代表性结果判断是否可靠。
- **缓存不可靠**：已有缓存缺失或可能过期时，完成已授权的必要重算；外部链接、宏或不支持的公式先核对兼容性与所需依赖。只读任务仍只报告，工具受阻时明确未完成项，不把失败或省略的检查标为通过。
- **数据检查**：按实际数据核对数量、唯一键、空白、类型、合计及受影响的公式、图表和验证范围。
- **呈现变化**：新增或改变文字、样式、图表、行列布局时，查看受影响区域及周边；仅数据处理且未影响呈现时不强制渲染。打印或 PDF 交付检查实际分页、裁切和完整页面。

需要重算时，常规文件可使用 `scripts/libreoffice_headless.py recalc` 在任务临时目录生成新的重算候选；复杂模板按高保真流程重算隔离副本，再回填缓存。重算、缓存回填和渲染是分别按需选择的步骤。所有作者和重算输出路径在调用前都必须不存在。

## 9. 交付

1. 在任务独占临时目录完成候选及本次需要的数据、计算和视觉检查。
2. 正式目标不存在时，用 `publish_output.py <candidate> <destination>` 创建当前任务草稿并记录返回的 `published_sha256`。
3. 修正尚未交付的当前任务草稿时，生成新候选，再使用 `--replace-existing-if-sha256 <上次记录值>`；成功后更新草稿哈希。
4. 目标属于用户、已交付、已接管或归属不明时，不传入临时现算哈希绕过保护门，默认改用未占用的递增版本路径。只有用户在当前轮明确授权覆盖准确路径时，才能重新读取当前哈希执行一次受控替换。
5. 最终回复只突出正式表格路径、主要变化和验证结果。第一次在最终回复链接后，该文件立即转为已交付和受保护状态。

临时脚本、重算副本、渲染图和中间 JSON 默认不作为交付文件，也不在 commentary 中链接。用户要求提前查看时，先把拟链接路径转为受保护状态；后续修改使用新版本。正式文件自动发布到项目根目录并验证后，保留过程材料，等待用户显式触发 ChatNote 清理。
