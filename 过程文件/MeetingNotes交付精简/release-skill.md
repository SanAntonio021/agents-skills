# 会议纪要

## 入口

从 [writing-router](../writing-router/SKILL.md) 接收：

- `document_type=meeting_notes`
- `mode=discussion|action|mixed`
- `edit_scope`、`language`、`loaded_refs`

建立或沿用写作上下文后、处理正文前，读取[文稿协作](../writing-router/references/collaborative-writing.md)，按其中的范围和例外选择处理方式，并将实际路径记入 `loaded_refs`。直接调用本技能时同样执行；本轮已读且处理方式未变时沿用。会议转写整理属于直接处理，沿用本技能流程整篇交付。

读取 [共同质量规则](../writing-router/references/common-quality.md)。完整纪要、结构重写、终稿审校或 `audit_only` 再读取 [AI 气味目录](../writing-router/references/ai-smell-catalog.md)。

私有样稿为 `D:\BaiduSyncdisk\.agents\writing-samples\meeting-notes.md`；只读取 `status: approved` 的正文，候选区不作为写作依据。

## 事实边界

原始转写和用户补充是唯一事实来源。文件名、所在目录和旧项目背景只能帮助识别对象，不能用来补决定、共识、任务、负责人或截止时间。

按以下条件判断模式：

- `discussion`：主要交换观点、比较方案、解释问题或保留分歧。
- `action`：主要形成决定和明确分工。
- `mixed`：讨论为主，同时有少量明确任务。

只有同时出现执行动作和执行方，才能写成任务。时间没说就省略时间，或在用户要求任务表时写“未明确”。“还需比较”“还缺数据”“建议验证”“下次再讨论”本身不是任务。

## 跨会议核对

用户本次同时提供或明确指定同一议题的早期纪要时，按议题核对决定和任务，不自动扫描其他会议目录。每项决定保留决定内容及其证据位置；原文明说新决定取代旧决定时写清替代关系，新旧决定不同但没有明确取代关系时，列为待核对冲突，不自行认定旧决定失效。

任务完成、延期或取消，只按后续纪要中的明确报告或用户确认更新。没有新的状态证据时保留原记录，不补造期限、前置条件或状态，也不对决定变化添加“摇摆”等评价。

## 结构

标题跟着实际内容走，不固定四段，也不补空栏目。可选内容包括：

- 会议主题和必要背景；
- 已确认事实或决定；
- 主要观点及其依据；
- 分歧和未决问题；
- 已明确任务。

讨论型可以只保留“议题—观点—分歧”；行动型可以直接使用决定和任务表；混合型先交代影响决策的讨论，再列已明确任务。某类内容不存在就不设该标题。

材料合并、来源记录和交付细节见 [workflow.md](references/workflow.md)；分类、结构和整理标准以本入口为准。

## 整理方法

1. 合并同一场会议的全部转写分片。
2. 按议题和发言人识别事实、观点、异议、决定、未决问题和任务。
3. 同一观点没有新增条件、证据或结论时只保留一次。
4. 个人判断、建议和确认注明发言人或一方；原文写“主持人确认”时保留主持人，不能把“甲提出比较”改成“会议提出比较”。有人异议时不得写成会议共识。
5. 任务表只保留动作、执行方，以及原文明确的时间或条件。
6. 删除寒暄、口头重复和转写噪声，但保留会改变结论的限定语。

## `audit_only`

按共同质量规则分点报告问题，依据指向原始发言或用户补充的位置。另查：

- 个人观点是否被升级为会议结论；
- 未决问题是否被写成任务；
- 负责人、截止时间或共识是否由整理者补造；
- 同一观点是否跨节重复；
- 不同发言人的真实分歧是否被合并掉。

上述事实升级或补造直接判 `fail`。

## 输出

默认在对话中以 Markdown 交付；明确要求保存或已有指定主稿时，按准确授权写入并回读，飞书主稿无需额外维护本地副本。要求 Word 时，按 [Markdown 到 DOCX 交接契约](../writing-router/references/markdown-docx-contract.md) 直接完成纪要整理、审校和导出，不额外等待正文确认；用户明确要求先审阅或分步确认时遵从。材料足够时直接交付第一版；只有无法自行查明且会改变决定、任务或文稿用途的缺口才问一个关键问题，其余已明确内容继续处理。

## 完成条件

- 每项事实、观点、决定和任务能回到转写或用户补充；
- 标题均有实际内容，无空栏目和填充句；
- 重复观点已合并，真实分歧仍保留；
- 任务都有执行动作和执行方；
- `loaded_refs` 与实际读取一致。
