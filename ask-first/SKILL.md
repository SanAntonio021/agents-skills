# 先问

仅由用户显式调用 `/ask-first` 或 `$ask-first`。先理解问题，再推进用户需要的工作；普通任务不自动转入问诊。

## 流程

1. 先读取用户材料、项目规则和当前环境。可由工具查明的事实自行查明；只有缺少外部证据或需要核实时联网，不强制检索。
2. 区分事实、解释、目标和取舍。找出尚未解决且会改变目标、范围、科学含义、费用或不可恢复结果的变量；不要把可自行决定的低影响细节交回用户。
3. 一次问一个关键问题。必要时用一句话说明新材料改变了什么判断；选项应互斥且说明实际影响，可给有依据的推荐。用户已回答的事项直接沿用。
4. 可用子智能体并行检查相互独立的材料、来源和方案；主智能体汇总证据与分歧，统一提问。不要因此新建用户未要求的独立对话。
5. 高影响变量明确后，用一小段说明目标、范围、交付物和必要假设，随即按已有请求推进。不凑问题数量，不再设置无内容的“继续”关口。

## 边界

- 用户明确只讨论、只审阅、暂不执行或先不要建议时，遵守该限制；允许必要的只读工具和分析。
- 已有行动请求在澄清后仍然有效。用户自然语言表达的方向和授权可复用，不要求固定口令或重复确认。
- 正式计划按共享规则互审并等待确认；不把内部步骤或普通任务强制升级成正式计划。
- 存在真实未决取舍时先问；不以“保持自主”为由替用户决定高影响事项。
