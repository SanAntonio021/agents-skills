# 技术表达合同

生图前先把技术含义写清。合同用于约束图片，不是申报书正文。

## 单图合同

```markdown
# <图名>

- 用途：基金申报 / 工程申报 / 答辩 PPT / 论文概念图 / 内部讨论
- 权威依据：<本地文件、章节、日期或用户确认内容>
- 对应正文标题：<去除章节编号和 Markdown 标记后的当前标题；没有则写“无”>
- 图题：<默认与对应正文标题逐字一致；经用户确认的概括性图题需注明例外>
- 核心主线：<一句话说明图要表达的技术关系>
- 必须出现：
  - <对象、模块、阶段或信号流>
- 可以简化：
  - <不影响技术含义的细节>
- 禁止出现：
  - <旧方案、越界职责、未经确认的功能或数值>
- 准确标签：
  - <短中文或英文标签>
- 词表核对：<已加载的 style-vocab 词表、命中项、替换结果及用户确认的例外>
- 物理集成关系（只在设备爆炸图或内部结构图中填写）：
  - 外部总成：<设备、机箱或阵面等最外层对象>
  - 内含部分：<封装、芯片和已集成功能；写明“装在谁里面”>
  - 独立模块：<不属于上述封装或芯片的模块>
  - 整机支撑部分：<供电、散热、结构等；写明支撑哪个总成或机箱>
  - 工作方式和方向：<收、发或双向；没有则写“无”>
- 设备对外接口定义（只在集成设备或工程样机图中填写）：
  - 无线空口：<由哪个天线或阵面承担；输入、输出或双向>
  - <有线接口名称>：功能 <对外承担什么功能>；方向 <输入、输出或双向>；配置 <标配、选配或预留>；设备位置 <标注线应指向的位置>
- 允许的定量信息：
  - <已经确认且适合放图内的数值；没有则写“无”>
- 待确认：
  - <确认前不能让模型自行决定的问题>
```

设备对外接口定义中的每个有线接口单独列一项，使图中标注能够与设备接口位置一一对应。连接器类型、接口数量、协议、速率和其他未经确认的接口不得由模型自行补全；无线空口不能自动改画成机箱侧面的射频接口。

物理集成关系用来约束爆炸图的拆分层次。总成内的封装、芯片和已集成功能不能再画成同级外置模块；独立模块不能被画成封装内部器件。供电、散热和结构等支撑部分应围绕它们服务的总成或机箱组织，不能只为版面整齐而与电子模块并列。双向收发关系只按已确认工作方式表达，不据此增加未确认的接口或模块。

## 系列视觉合同

```markdown
- 图片数量：<N>
- 画幅：<例如 3:2 横版>
- 像素：<例如 1536 x 1024>
- 背景：纯白或接近纯白，无装饰性背景
- 主色：深蓝、蓝灰、黑灰
- 强调色：最多 1-2 种，只表示风险、关键节点或闭环结果
- 标题：同一位置、字号和层级
- 模块：统一边框、圆角、阴影和图标风格
- 连线：主信号流最突出，辅助控制流次之
- 文字：只保留短标签，不放说明段落
- 最终目录：只保留 N 张当前选定图
```

## 技术复核

逐项回答“是/否/不适用”：

- 图中每条主箭头都能在技术依据中找到对应关系。
- 图中没有模型自行增加的系统能力。
- 图中没有把备选方案画成核心实现。
- 图中没有把后续课题或实验验证职责画进当前课题。
- 所有数值、频段、速率、编码、阵列规模和距离均有依据。
- 标签和当前术语表一致。
- 图题与当前正文标题逐字一致；经用户确认的概括性图题已在最终清单中记录例外。
- 图题和全部图内标签已按文稿类型通过 `style-vocab` 核对；用户确认的新规则已进入对应词表。
- 设备爆炸图的各层与物理集成关系一致；没有把已集成功能画成独立模块，也没有把支撑部分误画成同级电子模块。
- 收、发方向与已确认工作方式一致，且没有因此增加未经确认的接口或模块。
- 集成设备或工程样机图已区分无线空口与设备外部有线接口。
- 每个外部接口标注都指向设备上的对应接口位置，且没有增加未经确认的接口。
- 图片仍符合最新技术方案；若不符合，已标为候选或待修正，而非最终图。
