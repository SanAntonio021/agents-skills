# 科研日报与组会 PPT

从会话、项目记录和真实图件整理导师日报或组会汇报，交付可编辑 PPTX。支持 Windows + Codex；采集器也支持 Claude Code 会话，macOS/Linux 完整流程尚未验证。

## 开始使用

在 Windows 本机 Codex 中提供本页链接，说“请按页面流程完成安装”。执行者须读取 [安装与配置](references/installation.md)，连续完成依赖安装和实际样例验收。默认安装 `lab-report-slides`、`pptx`、`writing-router`、`style-vocab`；组会沿用 LibreOffice 兼容渲染，使用组会流程时还需安装 `libreoffice-runner`。日报默认不调用它。

安装后可以说：

- “生成今日汇报，只看这个实验项目，先列出科研进展让我选择。”
- “生成本周组会汇报，曲线在 results 目录；下一步只写已经确定的安排。”
- “把候选 1、3 做成 PPT，不写 2。使用项目里的汇报词表.md。”

日报先广泛盘点本期会话、本地项目记录和相关飞书文档/任务的文字更新，再核实拟入首页的事实。首次展示须列出完整首页草稿，以及所有有汇报价值但未入首页的候选，说明状态、依据和取舍，不按固定数量截断；只排除纯操作、工具维护和无关记录。随后只问一次口头补充或草稿修改意见，用户可同时完成两者。草稿不设固定项数，每项正文都写明项目名，并把材料中已有的直接前因、当天动作和结果或当前状态自然串联；同一项目、同一科研问题的连续动作合并表达；总览只概括主动作，不逐条列测试顺序、检查过程或文件名。关键前因缺失且影响理解时，只追问一个具体问题，不自行补造；每项最多保留一个关键数值。首页放不下时用“总览（续）”，不缩字号、不删结论。草稿变化后重示完整首页并确认，随后依次确认仅含拟展开事项的清单，以及每项的原始素材与生成方式，只有素材确认完成后才制作。跨日累计稿用今日总览替换旧总览，同一项目按主题合并并在项内标注日期范围；旧展开页保留并按主题相邻重排。组会逐部分讨论确认，每部分正文同样写明项目名、直接前因、本次动作和结果或状态。日报默认只做轻量文件检查和一次 PowerPoint 原生打开/PNG 导出，快速检查遗漏、错图、不可读、裁切和严重遮挡；不做审美评判。

## 模板与个人配置

首次未指定模板时选择内置样式或本地 `.pptx`／带样页 `.potx`，以后在同一项目沿用并可随时更换。原模板保留，适配与验收见 [本地模板流程](references/local-template.md)。

个人词表放在项目根目录 `汇报词表.md` 或指定其他文件，使用“不建议、建议、例外”三列。没有词表也能执行基础表达检查。模板、项目名、交付目录和词表保存在本机或项目中，不随公开技能分发；作者私人样稿不可用时跳过，不阻断制作。

日报只生成 PPTX 和 manifest，不调用 LibreOffice 或生成 PDF；随后通过 PowerPoint 原生打开并一次导出全部页面 PNG。文字是原生文本框，图件可独立移动和替换，图内数据仍是像素。组会保留原兼容渲染流程；PDF 交付仍仅按用户要求，HTML 仅显式请求时生成。

采集脚本不联网，但模型如何处理材料取决于所用服务和账号；本地采集不代表模型完全离线。原始会话、来源清单和私人图件不提交公开仓库，自动凭据遮盖不能替代人工检查。
