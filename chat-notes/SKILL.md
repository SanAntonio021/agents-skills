# 对话收尾与经验整理

## 触发、范围与授权

仅在用户显式调用 `$chat-notes` 或明确要求按本技能收尾时执行五项工作。先确认实际项目、本轮任务、当前材料与用户限制，再分别判断需要做什么；按依赖关系执行，逐项核验后报告。一项无需更新、待确认或受阻，只暂停依赖它的操作，其他独立的已授权工作继续。

只讨论、只审查、指定文件范围、不清理、不提交、不推送、不发布、计划模式及宿主权限限制优先于默认动作。未受这些限制时，调用包含本任务过程材料的可恢复清理，以及本轮已确认、可隔离成果的提交推送；已获准的技能修改还包括检查、发布和运行副本复查，按第 5 项完成。不扩展到父工作区、其他项目、外部链接目标或整个资料库。技能行为修改仍须有具体建议的确认，已有准确授权不重复询问。

判断、操作与依据留在工作上下文，不为收尾新建总结、台账或核验报告。没有新事实仍须检查本轮涉及文档的职责和引用；没有实际问题则保持原样，不制造改动或待办。

## 五项工作

### 1. 项目 Markdown

**判断**：完整读取本轮涉及的 README、AGENTS、SKILL.md 和接续入口；关联专题只读受影响内容与必要引用。核对当前成果、状态、限制、待办、重复、错位、失效内容，以及文档之间的主要维护位置；不扫描或改写无关历史文件。

Markdown 的职责、结构、引用、历史整理和通用验收按 [Markdown 文档维护规范](references/markdown-maintenance.md) 执行；句子与段落质量（事实保护、重复判断、修改强度、停笔条件）按 [common-quality.md](../writing-router/references/common-quality.md) 执行，本技能不重复维护这些通用条文。

| 载体 | 主要职责 |
|---|---|
| README 等项目入口 | 项目用途、结构、使用入口、当前有效成果、进展、待办及影响后续使用的限制；必要的安装、配置和运行步骤可以保留 |
| AGENTS／SKILL.md | 各自负责的执行约定和使用流程；通用规则沿用全局规范，专项细节有明确引用 |
| 专题说明、实验记录及验收记录 | 按主题保存详细方法、参数、条件、结果和追溯依据；同一详细内容确定一个主要维护位置 |

依据实际问题选做法，而不是按篇幅决定：

- **无需更新**：内容准确、各段有用途、职责和引用清楚；长文也不必改。
- **局部更新**：仅少量状态、参数或用法过时，合并到已有位置，替换失效结论；不用日期流水重复追加。
- **整合**：同一事项分散、重复，或内容放错位置，合并重复并归回适当载体，更新相关引用。
- **重构**：历史流水、混杂职责或重复内容打断当前入口，妨碍找到有效操作与接续状态；调整受影响结构，把详细内容交回其维护位置。

**执行**：先确定保留内容及落点，再原位修改。保留有效参数、不同条件的差异、失败结果、恢复依据、用户手工内容和无关工作；保留信息不等于必须保留在原位置。已有有效专题时，入口概括必要结论、限制并链接；没有合适位置且详情确有后续用途时才建必要专题。先核对迁出详情的后续用途：影响判断、复现或恢复的信息才归位；已解决且没有后续用途的调试流水合并或删除，不另存历史。不为缩短入口转存冗余正文、复制证据或新建历史总日志。日期可以组织实验批次与汇报索引，不据文件名或日期推断成果已确认。

**验收**：读回改后的完整入口及关联段落，确认当前状态、待办、职责和引用一致，迁出内容没有重复维护，必要事实与证据仍可定位。缺少原机或外部材料时保留来源及未核验状态，不把路径存在于文字中当作证据可用。只补入新事实、没有完成结构和引用检查，不能报告此项完成。反馈注明实际做法和一条判断依据。

### 2. 飞书与实验文档

**判断**：从项目入口定位用户指定主稿、当前步骤和批次，核对已有原始材料与真实执行状态。区分计划、实测、离线回放和推测；没有新结果或结构问题时无需更新。

**执行**：同批次结果写回对应步骤、表格或单元格，不在末尾重复追加；不同批次分别记录。条件、动作、结果和证据紧跟对应步骤，保留接线、参数与单位、测量点、次数、判据、图片、原始数据及下一步。参数名与单位分开，一格一个参数，人填／AI 回填标记沿用原表，未知值留空。图片和附件放在对应结果之后，需要实验电脑补交时明确所需内容；不把本机不可访问的实验室路径当作已读证据。

保留有效差结果与失败记录，不因结果差而删除。只有已证明采集无效且用户同意移出正文时，才按已有归档位置保留原因。未开始的实验保持计划；软件通过、接入或文件传输通过不写成硬件采集或通信性能通过。不将 AI 写作规则、调试流水或没有信息的“无异常”填入实验正文。

**验收**：按实际记录工具读回，核对步骤顺序、批次、条件、数值、单位、附件、引用和结论范围。新结果有对应材料支持，原有效结果未被覆盖，后续未执行步骤未被升级；缺材料或主稿不可达时只保留相关待办，继续其他独立项。

### 3. 经验与技能缺口

**判断**：先读相关规则和实际过程，核对适用条件、执行动作及结果，再判断原因，不因条款存在就预先归为执行遗漏。

- 清楚且适用的条款未执行：执行遗漏，沿用规则，不追加同义警告。
- 缺少触发、判断、操作或完成条件，或分散／歧义使正确动作无法明确确定：技能缺口，可提出具体改进。
- 两者可以并存；材料不足时说明原因未确定，不断言单一根因。

再判断哪些内容有后续用途，先拆分通用方法与场景特例，再确定主要维护位置：

- 项目参数、路径、版本和当前状态归相应项目记录；一次性试错、普通发布经过或已解决报错不形成长期规则，除非仍影响使用、恢复或判断。
- 可跨场景复用的方法归对应技能，入口维护通用流程，较长细节复用已有参考；已有清楚且适用的方法直接引用，不重复新增。
- 站点、设备或平台特例归技能内对应说明，只保留特有条件、差异步骤和有效例外，并引用通用方法；尚未证明跨场景适用的做法不提升为通用要求。

**执行**：先确定归属，按第 1 项选择无需更新、局部更新或整合；确有新内容且现有位置无法承接时才新增，不因分层就新建文件。文档归位、去重和引用检查沿用第 1 项。

技能行为建议明确写出目标技能及链接、具体问题与适用条款、拟增加／删除／替换内容及对应验证场景；标为“建议修改”，未确认不写入、不提交、不发布。含义不变的去重、归位和引用修正在授权范围内直接做，涉及技能源码按 [skill-creator](../skill-creator/SKILL.md) 检查；获批行为修改按其流程独立试跑，再进入第 5 项。确认一项不扩展为确认其他项。

**验收**：原因判断能指向已读条款与实际过程，建议对应具体缺口；核对适用范围、主要维护位置和引用，项目事实没有写成通用规则，通用流程没有复制到各场景说明，特例没有扩大适用范围，有效差异和例外没有因去重而丢失。分别报告建议、已修改和未验证部分，不把“提出建议”说成已生效。

### 4. 过程文件清理

**判断**：仅盘点本任务及明确属于本任务的过程目录和散落产物。核对成果、当前或待确认工作稿、对比版本、原始输入、源码与测试、实验数据、编辑源、验证证据、依赖及活跃文件；按用途和后续依赖判断，不能只凭名称、目录、版本号或修改时间删除。先按对象分类：用户过程资料、草稿、截图和实验中间材料使用可恢复清理；本次工具生成的临时 clone、缓存、锁目录和可重建的比较目录，在确认绝对路径、用途、依赖和进程占用后直接删除。

**执行**：遵循项目现有结构，先将必须保留的内容归位，更新入口、登记和真实引用，并验证打开、重绘或构建所需依赖。执行清理前确认目标不再被引用、正式成果和必要依赖已归位；对工具临时目录还要先核对绝对路径、用途、进程占用、只读属性、锁文件和 worktree 状态，确认临时 clone/worktree 无用户改动；仅释放本任务创建的锁和句柄，并在删除前解除目标树内阻止删除的只读属性。不强关用户正在使用的应用。落点、跨目录范围无法确定时仅保留相关项待确认；已授权且位置明确的整理直接完成。需要确认的跨目录归入先列成果、依赖、目标、旧位置和范围，确认后按 [project-organizer](../project-organizer/SKILL.md) 执行；不为此次收尾搬动完整工程、申报包、原始数据或其他项目。

仅可恢复清理已证实无用途的被替代稿、预览、临时截图、转换文件及重复报告；用户资料没有可恢复入口时，保留原文件，只有针对准确文件取得永久删除许可后才能删除。已核对且不再使用的工具临时 clone、缓存、锁目录和比较目录可直接删除，不要求进入回收站或另建垃圾目录。正式成果及复现依赖不能继续依赖待清理目录；引用或可用性验证失败时保留相关文件。不得把全部过程材料搬到新归档目录冒充清场，不把临时材料写入正式正文。清理对象按已选定的方式执行一次；不要用盲目循环重试代替清理前准备，发现准备条件不满足时先保留对象并记录原因。

**验收**：核对目标实际状态和正式成果引用。只有目标原路径消失且有实际回收或恢复证据，才算清理完成；执行失败或只完成一部分，就如实报告未完成或部分完成，不把用户手动处理算作智能体已完成。若临时移动后失败，先恢复原路径。正常反馈只写清理结果；残留、恢复失败或正式文件受影响时再补充原因。

### 5. 提交、发布与运行时同步

分别核对项目成果、技能源码和运行副本，包括本轮已批准但尚未完成的提交或发布；没有改动和待发布内容则无需更新。只处理本轮已确认且可隔离内容，保留无关未提交改动。未定稿、无远端、冲突无法安全处理或用户限制时，只暂停依赖的提交／发布。核对远端后精确暂存，不整库暂存、不强制重置、不强推、不覆盖用户文件。

#### 项目成果提交

**触发与执行**：项目成果有已确认改动且允许提交推送时，按默认授权或既有准确授权完成提交、推送；已完成的步骤不重复执行。

**完成标准**：推送后读回准确远端提交，确认包含本次成果；提交与推送分别报告。

#### 技能修改发布

**触发与执行**：技能修改已获准且未限本地时，按 [skill-creator](../skill-creator/SKILL.md) 完成必要检查，再按 [技能发布操作](references/skill-edit-followup.md) 和 [agent-rules](../agent-rules/SKILL.md) 依次完成精确提交、推送、定向后台同步及完全相同参数的 `-VerifyOnly`。已提交或已推送的改动继续检查并完成尚未完成的发布步骤，不重复请求逐步批准，不手改数据库、运行副本或改用前台点击。

**完成标准**：读回准确远端提交；技能同步、复查均退出 `0`、返回 `runtime_active`，来源登记有效，且提交源码与 CC Switch、目标应用运行副本的完整文件集合及原始 SHA-256 一致，才算技能发布完成。源码推送成功不能代替发布完成；源码推送、运行副本同步及新会话加载分别表述。失败保留准确提交、完整目标集合、失败阶段及恢复依据，继续其他独立的已授权工作。

## 五项反馈

按实际结果简短回复，以下五项不能省略；不再重复展开前面的验收条款：

1. **修改的 Markdown**：实际修改的文件链接、整理做法（无需更新／局部更新／整合／重构）及一条依据；没有修改写“无”，并说明检查依据，只读文件不列为修改。
2. **成果**：最终文件、实验记录或回填位置及实际状态；未定稿仍待确认。分别说明项目与技能的检查、提交推送和运行时同步结果，不混为一项完成。
3. **经验整理**：有依据的原因判断、写入的项目记录、已修改技能或待确认建议；无新增经验说明无需更新及理由。
4. **清场**：第 4 项的实际状态和依据。
5. **待办**：只列确实未完成、待用户决定或受阻事项；没有则写“无”。
