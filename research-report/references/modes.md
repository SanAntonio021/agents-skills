# 工作模式

## 选择规则

一次任务只选一种主模式。正式报告、内部调研台账和审查意见是不同工件，不能在一个文件中混合。

| 模式 | 适用情况 | 主要产物 |
|---|---|---|
| new-report | 只有主题、读者或研究问题，证据尚未形成 | 研究约定、内部调研台账、候选结构 |
| evidence-to-report | 已有闭合的来源清单、证据表、来源笔记或结构化数据 | 报告主稿、真实来源清单、内部映射 |
| restructure-existing | 已有长稿，信息大体可用，但结构、重复、混写或语言有问题 | 重构映射、内部台账、Markdown 新稿 |
| audit-only | 用户只想知道哪里不对或是否还要改 | 内部审查意见，不改正文 |

## new-report

1. 确定读者、用途、调研对象、资料截止日和必须回答的问题。
2. 为每个问题列首选证据、可接受的次级证据和正式引用规范。
3. 先取少量样本验证定义和证据可得性；持续性取样转 baseline-research。
4. 把未闭合事项记录在内部调研台账，不开始正式正文。
5. 全部必答问题通过研究闭合门后，再按读者问题拟定章节。

## evidence-to-report

1. 读取来源记录，确定哪个文件是当前事实基线。
2. 核验每个正式结论都能回到真实来源，并且引用信息满足选定规范。
3. 把材料归入定义、事实、判断、原稿行动语句和内部未闭合事项五类；旧文件中的作者判断不能自动升级为事实。
4. 任何未闭合内容转入内部台账，不进入报告、摘要、脚注或参考资料说明。
5. 先写证据最完整、最影响读者判断的部分，摘要最后写。
6. 先在范围与术语节完成必要定义；发现段直接写来源事实和综合判断，不重复名词解释。用“定义—事实—判断”三栏自检每个主体段，发现混写时拆段。

## restructure-existing

先读取 [旧稿重构](restructure-existing.md)。

重构不是逐句润色。先保存源文件哈希和内容清单，再重新安排信息职责和章节顺序。Markdown 是内容主稿；用户确认后再通过 docx 生成新的 Word 版本。

## audit-only

1. 保持只读，不生成改写稿。
2. 先判断结构问题、证据问题还是语言问题，避免把所有问题归结为“AI 味”。
3. 按影响分级：
   - A：会误导结论、破坏证据关系或让读者无法判断；
   - B：造成明显重复、混写或阅读阻力；
   - C：局部措辞和格式问题。
4. 每个问题给原文位置、原因和修订方向；没有必要时不逐句重写。
5. 缺失证据、来源冲突和未闭合问题写入内部审查意见或台账，不能当作正式报告内容。
6. 专门检查摘要是否存在四字标签链、术语解释挤占发现、连续否定和弱化限定语；可运行 scripts/audit_report.py 提供启发式线索，但人工结论优先。

## 读者测试

报告接近完成时，用一个没有当前对话背景的读者进行测试。给测试者的材料只包括：

- 报告文件；
- 主要读者；
- 读完后应能说明的结论及其适用范围；
- 少量无法从正文推断的格式限制。

测试者应回答：

1. 这份报告要解决什么问题？
2. 最可靠的三条发现是什么？
3. 哪些句子是来源事实，哪些是作者判断？
4. 每项结论由哪些发现和引用支撑？
5. 报告的研究对象、地区、时间和资料截止日是什么？

如果测试者必须依赖作者口头解释，先补闭合证据或重写正文；不要用更长的摘要、未完成状态或免责语句掩盖问题。

## 语义边界复核

形式审计通过后仍要做一次人工复核：

- 定义是否只出现一次，且没有在发现段重复解释；
- 摘要是否把多个章节首句拼接成清单；
- 连续否定是否可以改成直接陈述；
- “在一定程度上”“相对而言”等限定语是否有明确证据作用；
- 结论是否真正提炼了事实关系，而不是只把数据换一种说法再列一遍。
