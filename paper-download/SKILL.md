# 论文 PDF 下载

## 目标

把 Zotero 作为统一文献库：先查重，再获取出版社当前提供的正式发表版，将 PDF 补到对应论文条目下。用户明确指定其他版本时遵从。已有预印本、作者接收稿或未完成编辑的早期稿，不代表正式版下载任务完成。

范围限于本次下载触及或用户明确指定的条目，不扫描清理整个文献库。每条默认只保留一份已核验的当前正式版正文 PDF；按下方流程可恢复地清理重复及过时附件，有批注或版本不明时保留例外。

## 什么时候用

- 用户还在问“有哪些论文”“哪些方向重要”“帮我筛代表作”时，先走 `paper-search`。
- 用户给出题名、DOI、URL、作者主页、出版社页面、论文列表或检索结果并要求下载时，进入本流程；只问访问状态时保持只读。
- 用户要“下载并总结”时，先获取 PDF，再按请求整理；Zotero 笔记使用现有 Zotero 插件，技术疑问核对使用 `paper-review`。
- 用户已有本地 PDF 并要总结时，按请求直接整理；需要核对技术内容时转 `paper-review`，不默认生成本地文档。

## 输出

- 默认交付 Zotero 论文条目及已校验的 PDF 附件，返回题名、保留版本、移入回收站数量、暂留原因和便于库内搜索的关键词；已有任务分类时说明分类名称，可附条目链接。文件路径用于明确的本地交付或排错，不要求用户记住 storage 目录或条目 key。
- 当前下载请求覆盖该论文必要的新建条目、补附件、版本查重与下述可恢复去重步骤，复用已确认的资料库和分类；未指定时使用个人资料库，不猜测当前选中的收藏夹。多个候选无法区分时才问。
- 明确要求项目文件时，从 Zotero 导出到指定目录；用户明确只要本地文件、不入库时遵从。项目副本不建立另一套默认文献库。
- 不默认创建或更新 `paper_index.md`。仅用户明确要求或有效项目约定需要时沿用本地索引，保留历史内容。

明确为一篇文章或持续调研收集文献时，按 [paper-search 的任务分类流程](../paper-search/SKILL.md#按研究任务组织文献) 创建或复用一个分类；检索传来的 libraryID、collection key、条目和版本要求继续有效。已有 PDF 也应核对是否已加入任务分类，缺少归类只添加关系，不复制附件。单篇无任务背景下载仍使用个人资料库，不强制建分类。

阅读时复用已有笔记，必要时补充文献本身的方法、结果、局限和原文位置；当前文章的引用用途、章节安排与待核问题留在文章工作区已有材料，不写进通用文献笔记，不默认重做精读或新建引用账本。

## 查重、入库与完成

1. 通过现有 Zotero 工具检查可用性。先按 DOI 或其他稳定标识找条目，再结合题名、作者、年份和版本确认。通用搜索未必覆盖 DOI 字段，空结果时改用题名、作者等找候选，再读取实际 DOI 核对；不要仅凭一次空结果判定库内没有，也不要只凭相似题名合并。
2. 对照出版社当前文章页和 PDF 内容核实已有附件版本，按下方“版本选择与去重”选择保留附件；已有当前正式版且可读时优先复用有批注的同版本附件。只有预印本、作者接收稿或旧早期稿时，继续补正式版到同一已确认条目，新版核验完成前不清理旧版。条目不存在时，使用已核实元数据建立一次。
3. 复用已核实的题名、DOI 等信息，缺口由 `paper-search` 补齐。未知字段保持空缺，不能为了入库猜数值。
4. 下载到本次任务暂存目录，校验 PDF 后通过现有 Zotero 接口添加到准确的父条目；采用 Zotero 管理的附件，操作要点见 [references/zotero-storage.md](references/zotero-storage.md)。
5. 回读父条目、附件版本和文件，检查正文身份、可读性及入库前后内容一致。只有条目而没有所需 PDF 时，报告“条目已建，PDF 未取得”；仅有临时稿时报告“临时稿已保存，正式版待补”，不宣称正式版任务完成。批量结果分别统计当前正式版、其他版本和待补数量，不以“每篇都有 PDF”代替验收。
6. 新版入库或已有附件复用核验成功后，按“版本选择与去重”重新检查批注及附件笔记，通过 Zotero 原生接口把符合条件的冗余正文附件移入回收站，再回读保留文件、分类、标签及笔记。正常完成要求一份当前正文 PDF；暂留例外逐项说明，不把正式版已取得等同于去重已完成。
7. 最后清理本次可识别的临时下载；已用移动方式入库则核对临时路径消失。入库失败保留有效 PDF 供续做，不删用户原文件。写入结果不明时先查条目和附件，再决定续做，避免重复导入。

Zotero 不可用时继续能独立完成的检索和下载，保存暂存 PDF 并报告“待入库”，不改用另一套长期索引、不将暂存当成最终入库。

## 版本选择与去重

- 先区分正文、补充材料、更正文件和其他附件。只对同一论文的正文 PDF 去重；独立材料和笔记保留。
- 同哈希可证明文件相同；不同哈希不能证明版本更新。结合出版社版本状态、卷期页码、修订说明和 PDF 正文、公式图表判断；下载日期、文件名或同一 DOI 都不能单独决定新旧。下载页脚或元数据变化可导致同版本不同文件；证据不足时暂留并报告。
- **同一版本**：优先复用已有批注的可读附件；无批注时优先保留有附件笔记的已有附件，其次复用已有可读文件，不为较新的下载时间替换。多份附件均有批注或附件笔记时，保守暂留并报告，不自动合并或搬运。其他无批注、无附件笔记的重复正文可移入回收站。
- **确有更新**：确认当前正式版入库且可读、内容与下载源一致后，无批注和附件笔记的旧正文移入回收站。有批注或附件笔记的旧版暂留，新版作为阅读目标，报告旧版待迁移原因；本流程不跨版本迁移批注，也不按页码或坐标盲搬。
- 批注保护覆盖 Zotero 批注、PDF 内嵌批注及附件自身/关联笔记；读取失败或无法确认是否存在时，按未知处理，不推定为零。父条目独立笔记不删。
- 清理前保存准确的资料库、父条目、保留/待清理附件标识、版本依据及文件哈希；再次读取状态，有新增批注、附件变化或版本依据失效时重新判断。只调用原生移入回收站接口，不永久删除、不清空回收站、不直接改数据库或 storage。
- 入库失败时保留旧附件和有效下载；写入或清理结果不明时先回读，仅处理仍未完成且重新核验安全的对象，不盲目重试。具体执行和回读要求见 [Zotero 存储说明](references/zotero-storage.md#版本去重执行)。

## 能接收什么

- DOI
- arXiv ID、PubMed ID 或论文 URL
- 论文题目、作者主页、出版社页面
- 用户手写论文列表
- `paper-search` 返回的标题、摘要、链接或引用信息

如果一篇明确论文都识别不出来，只问一个问题：这次要下载的是哪几篇？

## 怎么下载

1. 先复用库内条目和核实结果，补足识别论文及版本所需信息，再下载。
2. 版本优先于来源。先访问出版社当前文章页，确认当前正式 PDF；已有卷期版时不以旧的 Early Access 或作者稿替代。公开获取失败后，继续实际尝试已配置且获授权的机构渠道。工具报错、代理故障、浏览器服务未启动或未检查机构权限，都不能据此判定正式版不可获取。
3. 来源不是第一判断标准。公开机构库或作者主页副本，经核对与出版社当前正式版相符时可以复用；仓储标签、DOI 或双栏外观本身不足以确认版本。
4. 实际确认无机构权限、只能购买/申请全文，或机构渠道在当前宿主权限内无法继续时，记录具体访问结果或工具阻塞，保留正式版待办。可保存合法临时稿供阅读，但不算正式版完成；不得绕过访问控制或宿主工具限制。
5. ResearchGate 更适合当线索来源，不把它当默认主下载源。
6. 按文件核验需要检查正文或页面；不额外交付截图、文本、BibTeX 或中文总结，除非请求包含这些成果。

## 下载工具

统一使用浏览器访问论文页面和下载入口；复用日常浏览器的登录态、机构授权和页面会话。公开 PDF、出版社页面、机构登录和动态下载按钮都在浏览器中处理，下载后再按文件头、题名、作者、DOI、页数和版本标记核验。

将网页和下载结果映射到 Zotero 对应的题名、作者、日期、发表源、DOI 和 URL；附件记录来源与版本，不把平台原始字段、临时令牌或浏览器凭据塞进笔记。

本机已配置 PaperAccess 时，机构访问优先使用[稳定助手入口](references/publisher-download-playbook.md#本机-paperaccess-助手)，先检查服务和会话，再执行已授权流程。接口以助手当前 `--help` 为准。指定工具未加载时先发现当前可用工具；工具故障与机构无权限分开记录，不因前者降级完成标准，也不绕过宿主限制。

Connector 识别网页并保存 PDF 的流程可在当前工具确实支持时使用，但不能仅因浏览器已安装扩展就认定可调用。无法触发时，走网页取得 PDF 后原生入库的已验证路线；两者都要先查重并回读附件。

## 怎么判断版本

1. 先核对出版社文章页，并用 DOI、题名和作者确认发表身份，记录 `publication_status=published`。这描述论文是否发表，不代表手中 PDF 是正式版；Crossref、OpenAlex 等可辅助查找，不能取代附件版本核验。
2. 对 `published` 条目，先下载正式发表版本。优先 DOI/出版社正式页、出版社开放 PDF、PMC/Europe PMC 正式全文、Unpaywall 指向的 published PDF。
3. 作者主页、机构库、课程页、实验室页面或 Google Scholar 指到的公开 PDF，只要能确认是最终发表形态，也可作为正式版来源，在附件中记录来源。
4. 公开和已配置机构渠道的实际结果按上方下载流程记录。临时预印本标 `temporary_preprint`，作者接收稿标 `accepted_manuscript`，均保留正式版待补状态；存在本地索引要求时同步记录。未实际尝试机构渠道时，不写“机构渠道无法获取”。
5. 如果只能确认预印本、没有正式发表线索，标为 `preprint`，不要写成正式版。
6. 如果同一论文同时出现多个候选，优先保留 DOI 和正式来源；预印本的 ID、URL 和下载结果作为 `alternate_version` 记录。

## 怎么判断是不是正式版

- 标题、作者、DOI 能和正式论文对应上。
- 版面是期刊或会议正式排版，而不是 arXiv、投稿稿、接收稿或网页打印稿。
- 核对出版社当前版本的卷期、页码或文章号、年份、期刊/会议信息。出版社仅提供已编辑正式 Early Access 时，可按当前正式版记录并注明尚无卷期版；出现“author’s version”“not fully edited”等标记时按作者稿处理，不能因来自出版社而标为正式版。
- 文件不是补充材料、勘误、封面页、摘要页或 HTML 网页另存。

页面上写 `FULL ACCESS`、`Full Text` 或能阅读全文，只能说明网页正文可读；这不等于已经获取到正式 PDF。仍要点击或请求 PDF 入口，并确认下载文件开头是 `%PDF-`。

## 文件命名

Zotero 管理的文件沿用库内附件命名设置，不直接重命名 storage 下的文件。明确交付本地 PDF 且项目无既有约定时使用：

`年份-期刊名-标题名.pdf`

命名细则：

- `年份` 用正式发表年份；只确认预印本时用预印本年份，并标明版本。
- `期刊名` 优先用正式论文里的期刊全名；会议论文用会议名，预印本用 `arXiv` 或对应预印本平台名。
- `标题名` 保留英文原标题的主要单词和大小写；清理 Windows 文件名不适合的字符，如 `\ / : * ? " < > |`。
- 同一论文存在多个版本时，在标题名后、扩展名前追加最小版本后缀，如 `(official)`、`(accepted-manuscript)`、`(temporary-preprint)` 或 `(arXiv)`。
- 遇到超长标题时，保留年份和期刊名，标题名只做可读截断，Zotero 条目保留完整标题和 DOI。
- 本地输出重命名后更新当前任务引用和已有授权记录；有索引要求时更新对应路径。

## 什么时候用浏览器

遇到下面这些情况，默认切到浏览器路线，而不是盲目重试命令行：

- `Security check required`
- Cloudflare 或行为风控
- `Download` 按钮不是直链，而是前端事件
- PDF 依赖浏览器会话、Cookie、短时令牌或在线阅读器
- 机构登录要走统一身份认证
- 直链、命令行或普通网页请求返回 403、HTML 页面、登录页，但用户在浏览器里能看到下载按钮或阅读全文

默认复用日常浏览器已有学校登录态和自动填充。通过现有浏览器工具在本任务页面操作；浏览器原生保存信息下拉框不一定向网页工具开放，不把点击账号框视为自动填充成功。已有准确授权和本机安全凭据助手时，可复用后台登录路线，具体边界见 [机构授权说明](references/publisher-download-playbook.md#机构授权边界)。密码只在本机助手内传给核实过的 HTTPS 登录表单，不进入模型、工具文本、源码或日志；不提取浏览器密码库或导出 Cookie、令牌。

到真实机构登录页，账号与机构已明确且填充就绪时，继续点击登录；已有登录态则继续进入 `Institutional Login`、`China CARSI`、`Continue`、`View PDF` 等已授权步骤。只检查就绪状态，不取字段值。需手工输入凭据、扫码、验证码、二次验证或账号机构不明时交给用户；新服务条款、信息发布范围、购买及新增权限绑定按具体授权处理，相同接收方和信息范围的已有授权继续有效。交接按浏览器工具流程暂停页面操作，用户完成后继续。

用户完成授权后，沿原浏览器页面和当前下载任务继续，不重新建立重复条目或重复下载。

下载完成后，先检查文件头是不是 `%PDF-`。如果返回的是 `text/html`、`<!DOCTYPE html>`、学校登录页、验证码页或出版社外层网页，就不能当成论文 PDF 保存。

站点经验按需读取 [references/publisher-download-playbook.md](references/publisher-download-playbook.md)。

固定状态值：

- `version`：`official`、`accepted_manuscript`、`preprint`、`temporary_preprint`、`unresolved`
- `publication_status`：`published`、`preprint_only`、`unknown`
- `access_status`：`open`、`institutional`、`request-only`、`unresolved`
- `download_status`：`downloaded`、`pending`、`failed`、`skipped`（仅表示对应文件的下载状态）
- `official_status`：`obtained`、`pending`、`not_applicable`（当前正式版已核验并按请求入库/交付、仍待补、用户指定非正式版或确认仅有预印本）

## 边界

- 多篇文献综述、代表作筛选：先用 `paper-search`。
- 投稿文章、引言综述、申报书材料：转 `writing-router` 或 `project-writing`。
- 论文技术内容、图表公式和笔记准确性核对：转 `paper-review`；Zotero 笔记读写使用现有 Zotero 插件。

## 会用到的工具

- 上游查找：`paper-search`
- 网页访问和动态页面：`web-access`
- 浏览器协作：`browser-use` 或当前可用的浏览器工具
- PDF 后处理：`pdf`
- 原文核对：`paper-review`；Zotero 条目、附件和笔记：现有 Zotero 插件及已配置后台桥接
- SCI 论文精修和术语核查：`ieee-manuscript-edit`

## 以后怎么维护

- 站点经验按需读取；只在用户要求维护时更新本技能，不因下载或排错成功自动回写。
- 如果改变文件命名习惯或目录规则，再改对应规则，不要把一次性项目目录写死。
