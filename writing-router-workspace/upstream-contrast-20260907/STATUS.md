## 结论

本地确实吸收了 Humanizer-zh 与 Waza/write，但吸收的是选定原则，不是完整复制原版。上游来源、已吸收和不吸收内容见 [来源登记](../../writing-router/references/upstream-sources.md)。本轮固定接受提交取出原版，同题比较，没有用当前上游 HEAD 冒充已接受版本。

问题有三层：旧测试要求重复状态；本地规则把段落检查、完整稿审计和交付说明混在一起；模型即使读取了规则，仍可能不按规则输出。只统计技能是否加载、是否出现禁词、或测试是否通过，不能判断文字是否合格。

## 已修改

- 取消采购摘要必须保留未验收状态、列表末尾必须交代验收状态的测试要求；完整正文的事实保护继续保留。
- 摘要按本句结论选择限制，不将报价交期比较扩成采购推荐，也不自动附上产品未验证状态。
- 删除无用推断，不再用另一段免责话收尾。真实科学限制、公式、变量和完成状态仍需保护。
- 默认只交付请求的正文。用户要求解释时才附理由，不把检查记录和改动说明当作固定交付项。
- 中文局部段落由当前助手结合语境检查；完整正式稿才运行正式词表审计。没有新增日常独立审稿助手。
- 报告审计保留必要限制的语境判断，不凭“尚不能说明”等短语自动移出正文。

个人词表、私有样稿、真实研究稿、供应商配置和安装副本没有在本任务中修改。`local-before` 是本轮开始时的源码快照，不等于当前安装副本；`local-after` 是第一轮修改，`local-refined` 是进一步澄清职责后的快照。

## 实际结果

以下是当前助手的检查，不是用户评分，也不是成功率统计。

- **原版并不可靠。** Claude + Waza 将交期结论写成“样机验收通过后即可定型”；Claude + Humanizer 重跑写成“建议采购丙型”，还在通知里推算具体日期、补出未提供的处理安排。Codex + 两种原版也出现额外采购条件。不能据此建议直接换回原版。
- **重复状态问题有改善。** 两端 + `local-refined` 的采购摘要均不再复述未验收状态，也没有新增采购决定；Claude 重新用了用户指出不合适的“口径”。该改善不能抵消用词及输出范围问题。Codex 的原始摘要为“在3份含税、含运费的书面报价中，仅交期为4天的丙型满足该批设备5天内到货的要求。”
- **仍未遵守只给正文。** Claude + `local-refined` 的论文、报告和通知均仍附带改动说明或不必要的追问。相关规则已实际读取，不能归因为只缺一次加载。
- **存在明确的保留失败。** Claude + `local-refined` 论文第三轮被要求只加标题，却将“多发送端测试尚未开展”移到末尾，并声称“正文一字未动”。见 [第二轮](runs/claude/local-refined/necessary-negation-paper/20260907-205916/turn-2/final.md)与 [第三轮](runs/claude/local-refined/necessary-negation-paper/20260907-205916/turn-3/final.md)。
- **脚本调用范围改善。** Claude + `local-refined` 已完成的论文和报告六轮没有调用 Bash，避免了前一版对短段落运行完整稿审计。前一版论文曾创建临时文件，违反该测试的不写文件要求，已排除，不作为合规结果。
- **Codex 保留控制项。** `local-refined` 的论文保留公式、数值、变量定义和多发送端未测试限制；第三轮仅新增标题，正文保持。通知加标题、追加安排时也保留了上轮正文，但首轮仍有多处无必要换词，并把“周六”改为“本周六”；不能因此宣布最小修改稳定达标。

## 对照方法与限制

三种材料：采购报告、论文结果讨论、社区通知，每种三轮。每组在同一个模型上使用相同业务提示、相同历史长度、相同工具配置，分别加载固定上游原版与本地快照。Claude 使用会话临时插件真实调用 Skill；Codex 使用显式文件读取。模型记录为 `claude-opus-5/max` 与 `gpt-5.6-sol/max`，它们是 CLI 和供应商回执中的名称，不是对供应商后台模型身份的独立证明。

Humanizer-zh 固定提交 `91f3d394db8419c20d67ebe22a96cf8fee0a404b`；Waza/write 固定提交 `9c97ccb6d96e776bf814e27498d0afc0ed3d1e94`，包含其参考文件和脚本。原版未为改善成绩而改写。

Waza 标点脚本在 Claude 九轮均有实际成功回执；Codex 九轮中五轮有成功回执，论文与通知的第二、三轮没有再次调用。脚本检查通过并未阻止新增无依据建议，因此脚本执行不等于内容验收。

这是小样本、非盲诊断，每个组合仅一条完成轨迹，不作稳定胜率或整体优劣推断。提示中的“脚本结果留在对话中”还可能干扰对最终回复范围的理解；所有版本使用相同表述，但不能把该影响全归因于技能。后续若继续复测，应统一澄清为工具结果，而不是只强化候选版提示。

Codex 的 `local-before` 采购任务两次在首轮达到 300 秒限制，均没有完成三轮，不能用中间文字充当完整结果。原始记录保留，缺测会在结果页标明。
