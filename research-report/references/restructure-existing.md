# 旧稿重构

## 原则

旧稿重构的目标是重新分配信息职责，不是在原模板上换标题、删套话或逐句改写。原稿保持只读，新稿默认以 Markdown 建立，再按需要导出为新的 DOCX。

正式新稿只写已经闭合的研究问题。原稿中的无依据内容、来源待补项、行动安排和后续取证任务转入内部调研台账或重构映射表，不能用更委婉的措辞留在新稿。

## 1. 固定源文件

开始前记录：

- 绝对路径、文件大小、修改时间和 SHA-256；
- 能否安全读取以及使用的提取方式；
- 图片、表格、脚注、批注和修订的数量；
- 用户明确要求保留的部分。

不要覆盖原稿。DOCX 读取和导出遵守 docx，不因“只是重构内容”而启动或接管 Word。

## 2. 建立内容清单

按段落或逻辑块记录：

| 字段 | 含义 |
|---|---|
| source_location | 原章节、段落或表格位置 |
| primary_type | D/F/J/R/U |
| claim | 该块真正想表达的内容 |
| evidence | 原有引用、数据或文件位置 |
| reader_value | 对目标读者是否必要 |
| action | 保留、移动、拆分、合并、压缩、删除、转入内部台账 |
| ledger_id | 关联的内部台账记录；正式稿不出现该编号 |
| new_location | 新稿位置或删除理由 |

内容清单用于防止重构时静默丢失已核验事实。删除项要有理由，例如重复、超出范围、无证据、行动要求或只是在解释常识。

R 表示原稿中的建议或行动语句。它不在正式稿中保留：映射表的 action 记录为“删除”或“转入内部台账”，并写明理由。不要把它改写为“结论成立所需的证据条件”后留在正式稿。

另建来源清单，逐项记录真实题名、发布主体或作者、日期、文号、DOI、URL、本地文件位置和原稿内部编号。S-01 等编号只用于新旧稿映射；正式稿引用必须落到真实来源条目。来源信息或事实尚未闭合时，登记内部台账，不根据上下文补造，也不进入正式稿。

## 3. 找出混写

重点检查：

- 摘要大部分篇幅在解释名词；
- 主体发现段重复“X 是……”的术语定义，再接事实或判断；
- 同一段先解释术语，再列公开进展，最后加入开发行动指令；
- 产品清单、技术原理和市场判断交替出现；
- 法规原文与作者的合规判断写成同一句；
- 工程设想用肯定语气写成已经验证的结果；
- 同一结论在摘要、章节开头、章节小结和全文结论重复出现。

可先运行：

    python scripts/audit_report.py extracted.md --mode formal --json

脚本输出只用于定位候选问题。每个标记都要回到原文人工判断。

## 4. 重建信息顺序

先写一页结构说明，回答：

1. 读者先要知道哪些结论；
2. 哪些定义会改变这些结论的含义；
3. 每条结论需要哪些已闭合事实支撑；
4. 哪些技术背景应移到单独章节或附录；
5. 哪些行动性语句应删除；
6. 哪些原稿内容应转入内部台账并继续调研。

不要沿用原章节数作为约束，也不要为了“像报告”补齐市场规模、竞争格局、趋势预测和战略建议。

这些问题只用于内部重建顺序。正式目录要把它们转换为对象明确的名词短语或结论句，不直接使用“这份报告要判断什么”“当前应如何推进”等口语问题式标题。

## 5. 按职责重写

推荐顺序：

1. 先写事实段，保留来源、时间和适用范围；
2. 再单独写综合判断，明确它依赖哪些已经写明的事实；
3. 删除原稿中的行动指令；
4. 将无依据数字、未闭合来源和后续取证事项转入内部台账；
5. 最后补最少必要定义，并写摘要。

摘要概括可确认的事实和已形成的结论。它不写关键缺项、资料未列明、引用元数据状态或后续调研安排，也不把章节首句、四字短标签或连续否定拼成清单。

表格只保留可比较项。不同版本、不同统计方式或不同时间的参数不能因为列名相同就并排比较。

## 6. 全文去重

对每个重复结论只保留一个完整展开位置：

- 摘要保留结论，不展开定义和论证；
- 主体章节保留证据和分析；
- 附录保留术语、方法和详细表格；
- 内部台账保留过程记录，不作为报告附录。

删除“本节主要介绍”“通过上述分析可以看出”等没有增加信息的句子。

## 7. 验收

生成新稿后核对：

- 原稿中每条已核验关键事实都有新位置或删除理由；
- 引用仍支持它旁边的事实，没有因移动段落而错配，也没有新增来源或补造元数据；
- 正式稿已将 S-01、S01 等内部来源编号转换为真实来源对应的脚注、尾注或参考文献编号；内部编号只留在映射表或台账中；
- 摘要中没有成组的名词解释；
- 摘要使用连贯自然段，没有把研究对象、主要发现和结论写成逐段短标签；
- 定义只在范围或背景位置出现一次，主体发现段不再重复名词解释；
- 正式标题没有照抄口语化读者问题；
- 正文目的陈述使用评估对象、判定事项或比较对象等专业表述，不写“帮助团队判断”“供读者弄清”；
- 事实段不以行动指令收尾，原稿中的行动句已删除；
- 工程方案、模拟结果和实测结果的状态没有被改写；
- 未闭合事实、来源元数据、缺失字段和后续取证任务只在内部台账可见；
- 正式稿不用“尚未公布、尚不能说明、不宜、建议、下一步”等防御性或行动性表达；
- 正式稿没有“不是没有、并非不存在、不能不”等连续否定，也没有“在一定程度上、相对而言、某种意义上、不排除”等无证据作用的弱化限定语；
- 无背景读者能说出报告问题、主要发现、正式引用和综合判断。

用户确认 Markdown 内容后，再进入 docx 的新文档创建与渲染验收流程。
