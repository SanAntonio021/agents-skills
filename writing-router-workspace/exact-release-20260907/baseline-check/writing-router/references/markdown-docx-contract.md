# Markdown 到 Word 交接

内容技能先按[文稿协作](collaborative-writing.md)完成本轮正文与必要审校，`docx` 承接格式、结构、分页和成品检查。分批协作时使用已确认正文，会议整理等直接处理任务使用本轮完成的正文。用户要求导出 Word 就是导出授权；仍有待确认正文时先完成该部分讨论，不在导出时补写。

- 核对当前主稿、指定模板和图片的版本，读取本轮变化的内容，保留用户手工修改。同一任务中已读取且没有相关变化的规则、模板和脚本直接复用。本地 Markdown 直接读取；飞书主稿通过对应平台技能回读，转换所需的临时材料不作为另一份长期主稿。已确认正文直接回填，格式阶段不自行改写正文，不重复通用风格审校。
- 复用当前文件、模板或预设、输出路径及真实排版约束。格式参考已明确时直接采用；无指定时使用受管默认值。仅在多个候选会实质改变结果时询问。
- 默认生成新 Word；保护源稿、模板和已有交付物。页数、字号、行距或图片尺寸约束必须来自当前请求、模板或提交要求，不为自定页数压缩内容。
- 普通段落小改使用 `docx/scripts/edit_paragraphs.py finalize source edits output --allow-office-com`：严格段落编辑产物/记录与随后刷新全文已有相关内部域的交付物/记录分开保留。`apply`/`check` 仍是严格的底层段落阶段，不能代替有域文档的最终收尾。不为小改临时编写项目脚本、重新生成整稿或自动生成 PDF/PNG；无相关域时不启动 Office。
- 整稿导出对所有应编号的图、表、公式建立 `SEQ`/`REF`，无编号对象不加号，局部修改不转换无关纯文本引用。统一命令、全文各区域（story）的覆盖、安全刷新及未完成处理见 [编号与交叉引用](../../docx/references/numbering-references.md)；该页列出已批准的源码接口约定，文档更新本身不表示脚本已实现或运行时已发布。整稿导出在转换和模板格式处理之后、最终生成版本与哈希记录之前接入统一 finalizer，不再修改已检查的产物。
- 首次制作整稿、修改模板或版式（含图表布局）、明确要求排版检查时，使用一个适合目标应用的真实渲染器。新整稿或全局变化检查全文，局部变化检查受影响页及前后分页衔接；范围不明时扩大到完整相关内容。单纯域刷新不增加渲染要求。Word 为目标时优先安全调用 Word；不能隔离时继续文件级或适用的 LibreOffice 排版检查，但不能用 LibreOffice 替代原生域刷新。
- OfficeCLI 的结构验证不证明版式。保留静态检查与实际 Word/LibreOffice 渲染的真实结果；不要求双渲染器串联、批准的栅格基线、固定口令或用户逐页签字。
- 图片按 [图片引用与图题检查](../../docx/references/figure-integration-gate.md) 核对。PDF 按用户请求从本轮已检查的 Word 导出，无须用户再宣布 Word 为最终版本。
- 相关域的原生刷新失败或未完成，或明确要求的原生验证尚未完成时，保留候选并说明未完成项，不宣称最终通过。分别记录内容/样式、引用结构、原生刷新及排版结果；手动刷新建议不是完成证据。历史 manifest 和回执只作为历史证据，不自动升级状态，也不继续六阶段审批状态机。

使用对应文档的已有检查记录保存本轮实际采用的主稿、模板/profile、图片和 Word 的内容指纹；
没有记录时由 Word 工具生成对应检查记录；局部编辑的两阶段记录按上述约定分别保留。按需维护当前版本指向，不另建审批状态机，也不因更新 Word 自动创建整套快照、页面图片和多份说明。具体调用见 [Word 版本检查](../../docx/references/document-version-checks.md)。

恢复任务或复用结果前，由工具自动核对版本。文件未变时复用已通过的对应检查；输入材料变化时更新
产出并检查受影响内容，只有 Word 被手改时检查当前 Word。影响范围不明时重查完整相关内容。
无法对应旧记录时重新检查本轮交付文件。保留用户手改，需要重新生成时另存文件；真实内容冲突再询问。

版本核对复用当前授权，由智能体和工具完成；`loaded_refs` 沿用实际读取记录，不伪造用户确认。
