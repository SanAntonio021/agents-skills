# Windows 路径、云端和回收站安全

## 路径

- 执行只接受 `^[A-Za-z]:\\` 本机路径。UNC、NAS 和网络映射只允许候选发现与盘点。
- 比较路径时先取绝对路径、统一分隔符并移除末尾分隔符；边界判断必须包含目录分隔符，不能只用字符串前缀。
- 枚举和哈希使用 `\\?\` 扩展路径 API。目标 API 不支持扩展路径时，将对应项标为 `hold_unsupported`。
- 来源之间、来源与目标以及保护路径不得形成操作范围冲突。新任务的 `audit_root` 默认放在系统临时目录，在来源和目标之外；配置 `1.1` 仅保留对历史目标内专用子目录的兼容校验，不能等于目标、成为目标祖先或进入来源。不得接受通配符、`..` 穿越或未展开环境变量。
- `OutputDir` 必须归属 `audit_root`；若兼容处理目标内子树，进入前核对其真实路径和祖先，不经过链接或云端占位，不与业务输入、输出及已有业务文件混用，且只排除精确本轮子树及必要的空祖先记账。

## 目录树

- `merge` 在计划前生成完整目标树。普通资料默认采用浅层分类；代码、独立 Git、论文、实验、原始数据、结果数据和审计记录按实际工作保留必要层级。
- `group` 只增加共同父目录和各项目 `target_name`，项目内部结构保持不变，不自动平铺。
- 最终验收必须与批准树逐项一致。旧套壳路径、额外空目录和未批准根目录文件都视为结构变化。
- `mapping_rules`、目录例外和空目录保留项必须随批准树进入计划哈希，不能在执行后临时补充。
- 整合输出替代相应输入形成最终目录树；过程日志可正常增长，但已经绑定的准备文件、覆盖说明、检查报告和恢复副本仍逐项核验。

## 整合部署

部署前重新核对输入、准备内容和已有目标状态。改写原件先在正式恢复位置或本轮 `audit_root` 保存并核验；在目标盘写入临时文件、校验后替换。发生未记录修改时保留当前文件；中断恢复不以备份覆盖用户后来的编辑。完成动作必须与实际最终哈希一致。

## 同卷整目录移动

完整工程内部结构不变、源与目标位于同一实际卷、目标目录不存在时，使用 `[IO.Directory]::Move($source, $destination)` 做一次目录改名。先核实绝对路径和父目录边界、重解析点及特殊文件，保留文件清单和所需 Git 恢复包；这些检查与迁移授权不因整目录移动而省略。目标已经存在或需要合并、改写内容时，继续使用原有逐文件计划，不套用整目录改名。

移动前检查源目录下运行的程序及文件占用，等待相关写入结束，不强关用户程序。程序退出可能保存设置或日志；重新比较清单，保留新增或修改的内容，查明差异后更新基线再移动。目录改名不是写入锁，有些共享句柄允许改名，不能把移动成功当作没有占用的证明。

不要用 `Move-Item` 递归移动整个工程：遇到隐藏项或被占用文件时可能只搬走一部分。`Directory.Move` 抛错后，检查源、目标是否存在及内容是否完整，保留实际状态，不自动改用逐文件搬运、覆盖目标或删除源目录。解除已查明的阻塞后重新核对基线，再重试受影响单元。成功后确认旧路径消失，并逐项复核目录树、文件 SHA256、大小、修改时间及 Git 状态，再更新入口和真实依赖路径；不将这种同卷操作推广为跨卷原子移动。

## 重解析点和云端占位

读取 reparse tag。带 Name Surrogate 位的 junction 和 symbolic link 只登记链接本身，不跟随目标。

百度云等占位项可能使用非 Name Surrogate tag。目录可以枚举，但带 `Offline`、`RecallOnOpen` 或 `RecallOnDataAccess` 属性的文件不得打开或哈希，统一 `hold`，等待用户将其完整下载到本地。

加密、稀疏、多硬链接、额外数据流和无法证明语义保持不变的特殊项不得自动复制或移动。

## 回收站

个人和项目文件只通过 Windows Shell 支持的回收站 API 处理。生成清理计划和执行前再次核对来源、最终目标、恢复材料和清单；整合输入使用最终输出及绑定版本的实际检查结果验收，不强求改写后仍等于旧源哈希。执行前全量重新枚举来源，发现未计划新增文件或已退役路径重新出现时停止；`1.1` 最终验收重新检查完整业务目标树及保留文件，不能只凭迁移输出仍存在就宣称完成。

测试使用隔离的模拟回收站目录，不得污染真实回收站。技能不调用“清空回收站”；用户手动清空后，重新检查来源路径、保留副本、bundle 和磁盘空间。
