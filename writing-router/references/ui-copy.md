# 界面文案检查

只处理用户看得到的文字。先从当前页面及源码确定文字出现的位置、对应操作和实际状态，不对孤立字符串猜测功能。

1. 说清对象与动作：让用户知道当前测什么、要做什么；避免省略对象的内部简称。专业指标保留准确含义、单位及设定值/实测值区别，不把误包率改成误码率，不把无包改成失锁。
2. 统一术语：同一操作在步骤、按钮和提示中同名；相似词先核对是否同义。项目已确认定义优先；不确定的技术含义查配置或实现，仍缺证据则报告待核实，不凭润色补出结论。
3. 删除无用文字：主界面保留影响当前理解、判断或操作的信息；保存格式、实现说明、重复演示声明等按需要移入详情或帮助；没有独立作用的说明直接删去，不为保留控件而换一句话填满。短标签只负责命名，公式、定义和长操作说明放入按需查看的详情，不把解释全部塞进标签或按钮。故障、发射状态、换线条件等必要信息不能因“精简”删除。
4. 写清状态：区分等待、采集中、暂停、完成、失败和未确认。暂停与关闭发射等行为不同的操作不能合并命名；提示与真实行为一致。
5. 结合语境加载 `style-vocab` 的适用词表后复核。无需将整份代码当正式文稿审计；不机械替换专业术语，也不把没有词表命中当成文案合格。

修改只落在已授权的可见文字。保留变量、函数、控件 ID、配置键、协议值、路径及其他内部字符串；展示文字兼作逻辑键时，先由实现者安全分离显示映射并验证行为。只审查时不写文件。

文案检查结束回到界面任务；设计实现者核对真实窗口的文字可读性和截断。记录实际核验范围即可，不向用户堆叠检查术语。源码审查、截图检查和功能测试分别报告证据，未执行的项明确留待验证。
