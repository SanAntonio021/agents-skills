# XLSX 输出生命周期与受控发布

本规则只改变“智能体在当前任务内创建的输出如何落位”，不放宽源文件、用户文件或已交付文件的保护边界。内容作者工具仍只写不存在的候选路径；已有路径只能通过 `scripts/publish_output.py` 受控发布。

## 1. 四种状态

| 状态 | 判定 | 默认规则 |
|---|---|---|
| `protected` | 用户原文件、任务开始前已存在的文件、用户已打开/编辑/接管的文件，或归属无法确定的文件 | 默认不覆盖，生成递增版本；只有用户在当前轮明确授权覆盖准确路径时，才重新取得当前 SHA-256 并通过发布器保护 |
| `task draft` | 当前任务创建、尚未交付、未向用户链接、未被用户接管，并且当前任务记录了上次发布 SHA-256 的文件 | 可复用原路径，但每次替换必须提交上次记录的 SHA-256；成功后立即更新记录 |
| `delivered` | 首次在最终回复中作为正式结果链接的文件 | 立即成为受保护文件；后续修正默认生成递增版本，不再沿用草稿替换权限 |
| `temporary` | 候选文件、LibreOffice 重算副本、渲染图、PDF、补丁 JSON、核验 JSON 等中间产物 | 放入当前任务独占临时目录，不向用户链接；正式文件发布并验证后，在最终回复前只清理当前任务确认拥有的临时产物 |

任何状态不明、任务中断后无法恢复草稿记录，或不能证明文件由当前任务创建时，一律按 `protected` 处理。

## 2. 状态转换

1. 作者工具在任务独占临时目录生成 `temporary` 候选，不得直接写正式路径。
2. 第一次发布到不存在的目标路径后，该目标成为 `task draft`，并在当前任务上下文记录返回的 `published_sha256`。
3. 修正同一草稿时，作者工具生成新的临时候选；发布器只有在目标当前哈希仍等于上次记录值时才替换。成功后以新哈希更新记录。
4. 第一次在最终回复中链接该文件时，状态从 `task draft` 转为 `delivered`。
5. 用户在正式交付前要求查看、打开、编辑或接管草稿时，先把该路径转为 `protected`，再在 commentary 中链接；链接之后不得继续原路径替换。
6. `delivered` 文件需要修正时，默认选择未占用的递增版本名，例如 `report.xlsx` 后使用 `report_v2.xlsx`，`report_v4.xlsx` 后使用 `report_v5.xlsx`。

最终回复是正式交付边界。草稿不得为了展示进度而在 commentary 中链接；一旦用户能访问并可能修改该路径，就不能再假定它仍由智能体独占。

## 3. 受控发布命令

新建目标：

```text
python <skill-root>\scripts\publish_output.py <candidate> <destination>
```

替换当前任务草稿：

```text
python <skill-root>\scripts\publish_output.py <candidate> <destination> --replace-existing-if-sha256 <64个十六进制字符>
```

现有目标没有当前任务记录的草稿哈希时，不得为了通过保护门而临时现算哈希并冒充“上次记录值”。这类文件按 `protected` 处理。只有用户在当前轮明确授权覆盖准确路径时，才能为该次授权重新读取当前哈希；授权不延续到后续修改，路径或文件状态变化后必须重新确认。

发布器的成功 JSON 固定包含：

```json
{
  "ok": true,
  "action": "created",
  "candidate_path": "C:\\task-temp\\candidate.xlsx",
  "destination_path": "C:\\outputs\\report.xlsx",
  "previous_sha256": null,
  "published_sha256": "64-character lowercase SHA-256"
}
```

替换成功时 `action` 为 `replaced`，`previous_sha256` 为替换前哈希。失败 JSON 固定包含 `ok=false`、`error`、`message`、`candidate_path` 和 `destination_path`。

退出码：

- `0`：发布成功；
- `1`：未分类内部错误；
- `2`：参数错误，包括畸形哈希，或目标不存在时却携带替换哈希；
- `3`：保护门拒绝，包括无哈希替换、哈希不符、路径/状态不允许或并发竞争失败；
- `4`：复制、`fsync`、权限、锁定或原子移动等文件系统/发布失败。

## 4. 发布器保护门

- 候选与目标必须是不同路径、不同文件；目录和硬链接到同一文件均拒绝。
- 候选、已有目标、目标父目录及其路径链不得是符号链接、junction 或其他 reparse point。
- 目标父目录必须事先存在；发布器不自动创建目录。
- 目标不存在时禁止提供替换哈希，并用不覆盖语义完成首次创建。
- 目标已存在时必须提供当前任务上次记录的 SHA-256；发布器在预检和最终原子移动前各校验一次。
- 发布器在目标同目录使用 `mkstemp` 建立暂存文件，复制后执行 `flush` 和 `fsync`，再用 Windows `MoveFileExW` 原子落位。
- 两个进程竞争创建同一目标时，最多一个成功；失败者不得覆盖胜者。
- 发布失败保留候选和原目标，只清理由本次发布器创建的暂存文件。

最后一次目标哈希校验与原子移动之间仍有极小的外部抢占窗口。发布器对可检测的状态变化全部失败关闭，但不能把这一窗口描述为事务锁或所有文件系统上的绝对并发保证。

## 5. 临时目录与清理

- 每个任务使用独占临时目录；候选、重算文件、渲染结果和中间 JSON 不散落到正式输出目录。
- 临时文件名可稳定复用，但作者工具仍须写新的候选路径；需要复用正式草稿路径时只调用发布器。
- 发布器本身不删除候选。正式文件发布并验证后，由调用智能体在发送最终回复前删除其明确拥有的任务临时目录或逐项清理已登记的临时产物；随后最终回复中的首次链接完成正式交付。
- 发布失败、验证失败或交付尚未完成时，保留诊断所需候选；不得清理用户文件、共享目录或归属不明的产物。
- 清理只按当前任务的明确归属执行，不使用宽泛通配符，不递归删除共享根目录。

UNC、非 NTFS 和真实低磁盘条件不在本工具的默认验证声明内；首次在这些环境使用前需要单独烟雾测试。
