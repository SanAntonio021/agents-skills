# 资料定位与更新

## 私有定位

Windows 从非空、绝对且实际存在的 `USERPROFILE`，macOS/Linux 从相同条件的 `HOME` 解析启动用户主目录，读取 `.agent-rules/local.md` 的“规则维护目录”。不能拿隔离运行账户目录替换启动用户目录。再在该目录下读取 `docs/lab-resources/library.json`，不把真实内容复制到公开技能、样例或测试结果中。

该文件只负责定位，不是设备数据库。约定包含：

- `schema_version`：配置结构版本，首版为 `1`。
- `base_url` 与 `base_token`：默认资料库链接与稳定标识。
- `tables`：`submissions`、`models`、`devices`、`experiments`，以及存在时的 `projects`；每项包含 `table_id` 与 `fields`。
- `fields`：语义键到实际字段 ID 的映射；语义键以私有文件为准。执行前查当前字段类型、关联表和选项，不能只凭名称写入。
- 可附加 `display_name`、`home_url`、`upload_url` 和 `validation.team_access` 等定位或验收信息。它们描述实际部署，不授权新增受众，也不替代当前权限检查；`not_verified` 表示尚未完成相应验收。

兼容性未知、映射失效或字段类型变化时，只暂停依赖该字段的写入并说明差异。用户本次提供了明确目标时可以直接解析该目标，不必创建配置；维护定位文件只在维护任务已获授权时进行。

## 同源去重与失败续做

本节用于已授权的资料整理，只处理当前提交范围。普通资料查询不写处理状态、不更新指纹或补建关联。

在既有提交记录的处理字段中保存以下信息，使用现有等价字段即可，不强制添加一列对应一项：

1. 来源：提交记录 ID、原始附件/文档标识、设备与项目关联。
2. 源版本：文档 revision 或正文 SHA-256，附件内容 SHA-256 与稳定文件 ID；对提交文本和关联可用稳定排序的 JSON 摘要。签名下载 URL、本地缓存路径、整理状态、处理时间及输出业务字段不加入输入摘要。当前源指纹与上次成功处理的指纹分别保存，输入变更后标为待重新整理；成功读回前不更新已处理指纹。
3. 目标：型号、实物及实验的目标记录 ID、写入字段或文档位置。
4. 处理：整理方法版本、各目标的完成/失败情况、处理时间、读回结果及错误摘要。

一个提交涉及多个目标时逐目标记录，全部读回确认后才算完成。重跑时先核对已有目标和源版本；部分已成功、部分失败时只恢复失败部分。远端修改时间、文件名或链接相同不能单独证明文件内容未变；版本或内容无法取得时标为“源版本未核实”，不要声称已可靠去重。

## 实验索引与设备反查

“测试与维护”复用现有实验主记录、所属项目及器件关联字段；不新增独立实验台账，也不删改历史测试、维修字段。设备资料表单只补交手册、规格书、厂家说明；实验文档直接承载接线、设置、数据、截图、代码和结果。

以下维护步骤用于新建、续写实验或已授权补关联；仅查询设备与历史实验时直接按第 5 步读取，不补建索引。实验正文由 `lab-notebook` 维护，本节只处理关联。

1. 新建、续写实验或用户提供已有文档要求补关联时，先读取主记录，确认实际项目与参与实物。云文档解析为稳定文档 token（知识库入口需解析实际文档），忽略分享参数和块定位差异；本地用实际解析的准确绝对路径，不能只用文件名或实验标题去重。文档改名不新建索引；本地迁移只有确认仍是同一主稿时才更新原索引路径。
2. 查询既有实验索引并核对主记录标识。匹配一条则复用；没有则建立一条；多条匹配先列为待核实，保留原记录，不任意合并、删除或再建一条。查询未完成或无权限时不按“未找到”新建。
3. 按具体设备记录 ID 补充已实际参与的实物，可关联多台设备和多个模块。拟用或备选设备不加入。既有参与列表与新确认的参与实物合并去重；更换模块的时间、阶段和条件写在主记录，旧模块仍保留在参与列表中。同型号无法区分到实物时留待核实，不把同型号全数关联。
4. 只更新索引的主记录入口、项目和参与关联等必要字段；接线及结果直接读取主记录，不自动回填一份正文。写前重读受影响字段，写后核对记录 ID、主记录标识及参与列表。结果未知时先读回，不能直接重建。保留现有人工备注、测试维修内容和原始附件。
5. 按设备反查时，以具体设备 ID 筛选实验索引的器件关联，完整取得匹配记录，再读取当前用户有权访问的主记录。从实验查设备使用同一关联字段，无需维护另一套反向表。关联设备或项目不会授权阅读实验，遇到受限文档只报告当前可访问范围，不扩大权限。

飞书索引不可用不阻止独立的本地实验记录续写；在当前任务报告留下待补关联项，恢复后按相同主记录标识查询再补。无需另建同步正文、持久队列或定时扫描。只有索引和主记录都已核对时才报告关联完成。

## 修改前后的核对

- 保留首次读取的目标字段或片段作为预期旧值。写前重新读取，仅对相关字段或片段比较，避免把无关字段变化误判为冲突。
- 对相同来源生成确定的追加内容，能定位既有内容时更新该片段，不能每次在文末再追加一份。未知写入结果先读回确认目标；查询仍无法判定时标为待验证，不盲目重试。
- 飞书 Docx 使用 `lark-doc` 当前文档支持的基准 revision 与局部 block 操作，避免默认以最新版本号直接覆盖旧草稿；每轮后重新取得 block ID。revision 参数及其冲突语义以当前工具说明和实际响应为准，不承诺跨多次操作的事务。
- Base 写前重读与比较是冲突检测，不能宣称等同于服务端原子 compare-and-swap。只更新必要字段；已有证据表明同一字段正在同时编辑且接口无条件更新能力时，保留待合并内容并暂停该字段覆盖。无关条目照常处理。
- 飞书原生 Markdown 的局部 patch 最终仍全量覆盖文件。若发现远端变化，先重新取得最新全文合并；不能保证协作编辑已暂停时，不用旧全文覆盖。必要时交付待追加片段，主记录保持原位。
- 本地文件也须在写前重读，按最新内容局部追加；检测到被外部改动时重新合并，不拿先前读到的全文直接回写。
- 完成本轮变更后按工具的异步生效特点统一读回。接口成功响应、最终内容验证和权限验收是不同结果，分别记录。只重试可恢复的临时错误；权限、身份和配额问题按对应飞书技能处理。

## 交付最小证据

查询直接给答案、来源位置和相关限制；整理结果给出源记录与目标链接，并核对本次目标的读回结果。两者均不自动要求整库审计或普通成员测试。

共享或访问排障核对本次材料和受众；完整设备—实验查询路径验收才要求取得至少一台设备和一项实验的必要材料。只有管理员测试时如实标明团队访问尚未验证，不据此否定已完成的资料查询或局部更新。

临时下载、快照和核对结果放当前项目的 `过程文件/任务主题/`，不在技能目录保留真实资料。只有样例测试通过时不要声称真实设备、共享权限或硬件复现已经验收。
