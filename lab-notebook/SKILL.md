# 实验准备与记录

把讨论形成的方案写成现场可执行的步骤，实验时在对应位置记录结果，让换电脑或换人的接续仍有依据。普通仿真日志和已有结果整理直接走记录流程，不要求补做实验规划。

## 开始与范围

1. 从用户指定位置或项目已有入口定位本次实验主记录，按需读取相关步骤和结果。沿用已有本地或飞书主稿；已有飞书方案时，详细操作和结果统一在飞书维护。确实没有且用户未指定在线位置时，用 [简短模板](assets/labbook-template.md) 在具体实验目录建立本地主稿，不默认创建全项目持续追加的 `labbook.md`。多处记录无法确定主稿且影响写入时，只确认主稿位置。
2. 续写前读取当前内容，保留用户手改和历史条目。默认用中文，沿用已有格式和目录，不自动重排旧记录。写前再次核对相关片段；出现并发修改时基于新内容合并，冲突未明不覆盖。
3. 实验正文开头简要写明目标和关键条件，已有内容不重复介绍。同一实验续做时更新对应步骤和批次；新的实验或测试轮次沿用项目已有产物结构分别保存，不向全项目总日志追加。用户要求停止时立即停止。
4. 按关键实验、重要修改或判断变化更新记录。讨论中的假设和建议不写成已批准方案；确认后的选择及时写入，结果产生后及时补充。普通操作不要求前后各写一遍，也不等全部工作结束才追记。

## 正文、入口与轮次材料

- 实验正文按步骤连贯呈现条件、操作、结果和结论。影响复现、结论或后续操作的重要失败及获准调整简要保留；正式结果表中的失败观测仍保留，不把每次报错和排查尝试逐条堆进正文。
- 本地入口只负责定位：优先在已有 README 放主稿链接和必要的数据位置；已有 `lab.md` 入口可沿用，不另建入口，也不在入口重复维护目标、结论、进度或详细操作。使用“直连比较实验方案”“本轮结果表”等链接名称，能定位具体步骤、文件或运行编号时不只给大目录。已有含正文的历史 `lab.md` 不自动拆分、删除或迁移；未获迁移授权时保留旧文，只维护定位链接，不再追加总日志。
- 入口按目录页写：用简短标题和链接说明“有什么、在哪里”，需要时注明“原始数据在实验室电脑”等获取信息。适用条件、验证限制和整理经过放在对应记录或恢复说明，不在入口重复铺陈“不能证明”“不代表”“本次未……”等防御性说明。会影响打开材料或选择下一步的实际缺项，直接写清具体问题；不把未经核实的位置或状态改成确定事实。
- 数据、配置、运行日志和排查依据归对应测试轮次，复用现有文件。日志未覆盖且对复现、判断或接续必要的信息，才补到该轮已有说明；没有合适载体时在该轮目录建简短排查 Markdown，不每失败一次新建文件。同一问题的连续尝试合并说明，保留关键条件变化、失败证据、处理结果及未决问题；跨轮排查互相引用，不复制整段经过。必要的轮次记录属于长期实验材料。
- 飞书暂不可达或回填受阻时，将已产生但尚未写入的信息留在对应轮次，注明目标文档、步骤和待回填内容，不另建长期同步正文。恢复后重读目标位置、合并并读回核对，标明已回填，避免重复追加。缺少当前方案时暂停依赖该方案的操作，不凭本地历史猜测继续实验。
- 没有飞书主稿时，本地具体实验正文承担相同职责；纯仿真和软件验证同样按具体测试保存，不强制创建飞书文档。

## 逐步准备实验

- 先读已有方案、结果及当前问题涉及的设备资料；涉及实物能力时配合 `lab-resources` 查来源。一次讨论一个影响做法的问题，能从资料查明的不重复问用户。
- 先拟好一个小实验的完整步骤，包括接线、设置、测量、记录及进入下一步的条件。按 `technical-writing` 的实验操作单写法展示，经用户确认这部分正文后写入主文档，再展开下一部分；认可整体结构不等于确认全部正文。
- 操作用编号列表，每条写一个主要动作，接线、设置、采集分开。写明参数、单位、测量点及顺序、每点采集次数和判断标准。已确定的数值直接写入，不用“较低／较高”“多测几次”代替；未知参数先查明或提出具体建议供用户判断，不自行补造。
- 人工填写项每行指明一个具体信息，内容格留空；无单位的文字信息用“填写项｜内容”，含带单位参数时用“填写项｜单位｜内容”。在标题标“（人写）”，照片单独留位置。用户也可在对话中提供信息，由AI代填，不要求重复手写。
- 在对应步骤后留出“（AI写）”结果、图片和数据位置。人写、AI写的参数均用表格，每个结果格只放一个参数；I/Q、译码前后、均值与标准差分别列项。没有结果时留空，不加下划线、占位空格或“待回填”。计划设定与实测结果分开，图片和分析结论单独放，不强制表格化。
- 名称与单位分开：每列一个参数的表，第一行写名称、第二行写单位，第三行起填数据；每行一个参数的表，单设“单位”列，采用“参数｜单位｜内容”或“参数｜单位｜第1次｜第2次”等结构。无单位的单元格留空；名称和数值中不重复附单位，原始标签、型号和文件名保持原样。新旧批次采用相同字段与单位布局，已有数据不因调整表头而错位。
- 表头写清设备或位置、具体量以及设定／回读／实测来源，多通道或多阶段时注明通道、阶段；通用命名和两行表头示例见 [实验指标表](../standardize-test-project/references/experiment-tables.md)，示例列不强加给所有实验。设定值保留实际设置精度，测量值按仪器分辨率或实验需要显示；不统一保留两位小数。BER 默认三位有效数字科学计数，实际零保留，完整数值另存。
- 主结果表逐次记录，同次采集的不同通道共用观测序号、分行记录，失败保留、缺失留空。均值、标准差等跨观测统计只在事先设计好方法，或取得逐次结果后另行讨论确定时填写。整轮总览的指标、坐标、布局和图数在具体实验时设计，复用“实验规范”的公共程序；单次采集图组沿用已有规范。
- 格式与回填规则用于指导AI，不作为“填写规则”等说明写入实验主文档；正文只呈现实验步骤、条件、记录与结果，保留简短的人写／AI写标记。
- 幅度核对类实验分别记录I/Q的幅度设定、实测峰峰值、实测RMS和带内积分功率，注明实际统计口径与积分范围；无关实验不强加这些项目。补算峰峰值使用对应次完整原始采集的max(x)−min(x)，保留削顶等异常说明；缺少原始数据时留空，不用设定值替代或为补表重测。
- 表格过宽时拆成设置表与结果表，用相同测量点或运行编号对应，不靠一个格子合塞多个参数缩短表格。公用设置按主题分小标题；已经写明的固定接线不要求人工重复填写，只记录实际通道和变化。
- 保留公式、必要条件和操作动作，删除重复解释、无动作的提醒及讨论中的反复纠偏。记录和判断跟随步骤，不集中堆在文末；选做扫描和异常排查放在主流程之后。

## 现场推进与回填

- 先核对当前步骤及已批准条件；只有用户已授权上机且现有安全检查通过，才由 `link-test` 或项目程序执行仪器操作。写好方案本身不授权连接或开启仪器。
- 方案明确允许的调节和复测按约定执行并记录，不逐点重复询问。需要改变参数范围、次数、接线、处理方法或测试顺序时，先说明原因、拟改内容及影响；经用户确认后更新方案，再执行。不把建议提前写成当前操作指令。
- 异常可以先暂停，必要安全处置沿用仪器操作规则；暂停排查不等于获准更改方案继续测试。保留异常数据和已完成进度。
- 读取本次真实数据、配置和日志后，在对应步骤回填数值、判断、代表图片及可定位的数据引用，不用计划值、历史结果或推测代替实测。保留失败及获准调整的过程，不为使结果看起来完整而删掉不利记录。
- 每轮按本步骤判据判断继续还是排查；只有实际完成的步骤才记为完成。文档写入后读回核对，回填受阻时保留已保存的结果和待更新位置，不重跑测量来解决文档问题。
- 整理已填写表格时逐项搬移原值，保留精度、单位、统计口径、数据来源和图片，写后逐项核对。含义不明确的数据不猜拆，不将空白补为零；文字分析中的多个数值不因此机械拆表。
- 不同模式、线缆或批次分别记录，同类结果采用相同章节顺序、表格字段和单位；测量点及条件差异如实保留，不强行配成对照实验。每组集中放置条件、结果表及必要说明、图片、数据与异常，历史排查不穿插打断，正式对比结论放在各组之后。保留历史失败及被修正的判断，不把旧批次结论套用到新批次；改变工作点建议或科学判断前先核对依据，再请用户确认。

## 换电脑或对话接续

- 先沿本地入口定位主文档，读取当前步骤、上次停下的位置及相关结果，再按当前问题读取对应轮次的配置、日志、排查依据及必要代码版本和依赖；不默认通读所有历史。继续尚未完成的步骤，不重新规划整套实验或另建重复记录。沿用现有表格、单位和批次对应关系回填；需要调整表格结构时先说明，不自行改成大段流水记录。
- 只核对缺失或变化的信息：当前接线、设备占用、代码与依赖、实际控制能力及本轮操作授权。历史接线和上机授权不自动当作当前事实；能从现场已有配置和材料查明的不要求用户重新口述。
- 跨机材料用接续电脑可获取的仓库版本、附件或共享数据位置定位；旧电脑的绝对路径不能单独作为可用交接依据。缺少材料时说明具体缺项及影响，不凭旧环境验证结果声称现场已就绪。

## 随实验维护设备关联

- 涉及设备或模块的实验，新建、续写主记录时配合 `lab-resources` 查找并维护现有“测试与维护”索引：主记录链接或路径、所属项目、已实际参与的具体实物。同一云文档按稳定 token、本地按准确绝对路径查重，续写复用原索引。成员自行创建的文档在提供链接后补关联，不要求再上传实验资料。
- 接线、设置和结果写在实验正文，截图、数据及代码引用对应材料；详细排查留在测试轮次。设备索引只负责定位和关联，不自动复制正文，不删改既有测试、维修内容。按设备反查实验时沿同一关联读取原文档。
- 拟用设备不写成实际参与设备。同型号实物不明确时标为待核实；更换模块时在主记录记下变化，索引保留之前和本次实际参与的实物。
- 关联不扩大文档及附件权限。索引受阻不阻塞记录，待补关联项留在对应轮次；飞书不可达按上方待回填方式处理。恢复后先查重再补，不另建同步正文或定时任务。纯仿真等无实际设备参与的记录不强行关联设备。

## 飞书主记录

- 在线文档用 `lark-doc`，原生 Markdown 文件用 `lark-markdown`；读当前正文及版本后再更新，保留人工新增内容和附件引用。联网按 `web-access` 处理。
- Docx 优先指定刚读取的基准 revision 和 block 局部追加或修改；版本冲突时重读核对，不能将旧草稿改用最新版本号强行覆盖。每轮写后读回，后续使用新的 block ID。
- 原生 Markdown 的 `+patch` 是完整下载后替换、再整文件覆盖，不是原子更新。发现远端变更先合并；无法安全排除并发覆盖时，保留待追加片段并说明冲突，不覆盖主记录。请求结果不明确时先读回，避免重复追加。
- 本地代码、数据和飞书记录互相引用即可，不自动同步两份正文。设备资料查询和阶段共享交给 `lab-resources`；共享时检查必要文件能否由获授权者从云端取得。

## 轮次补充记录

已有操作单时按步骤回填实验结果；必要的排查依据未被现有材料覆盖时，在对应轮次补记，用问题或关键变化作标题，时间按需注明：

- **操作与条件**：实际改了什么、测了什么，以及影响结果或复现的参数、单位、配置或代码版本。
- **结果与产物**：关键数值、统计口径、样本范围或失败现象，并链接实际数据、配置、日志或图件。
- **判断与后续**：结果支持什么判断、还有什么未确定；确有后续动作时再写。

这些是内容提示，不是必填栏目。本地轮次记录与飞书正文共用下方排版要求，默认以表格组织参数、结果和多项排查，短文补充解释；不再另用长段日志写法。小标题按实际内容命名，操作单中已约定的空白填写区保留；人写／AI写标记只用于需要分工填写的操作单。

开头用一句话交代本轮做了什么，并注明仿真、离线回放或实测；结果紧跟对应条件和证据。结论直接写结果支持的判断，必要限制用具体事实表达，例如“本轮完成软件回放，实机效果待测”，不在每段重复“不等于”“不能证明”“不代表”。真实反例、负收益和会影响后续操作的限制仍须保留，观察与推测分开；不能为了语气简洁而删掉失败或扩大结论。文档提取、整理日期、保留原值及未重跑等维护经过统一放在来源或恢复说明；轮次正文只需引用可定位的来源，不重复开场声明，也不把同一段声明搬到文末。

## 正文与更新方式

- 本地 Markdown 与飞书正文采用同一套表格和文字要求：沿用“逐步准备实验”中的参数分格、名称与单位分开、设定／回读／实测来源、逐次记录、缺失留空及宽表拆分规则。格式规则只约束写法，不因共用格式复制两处正文。
- 参数与条件用“参数｜单位｜内容”等表格；多次观测或多组结果逐行记录，同类参数分别列项。多项排查优先用“问题｜处理｜结果”表，同一问题的连续尝试合并，一格只说一个要点。表内出现多个数值时，按参数另列小表，用测试编号对应，不把长段落塞进单元格。
- 先定位对应步骤和测量批次，再回填表格或更新该处的当前进度；不在文档开头不断堆新段落。同一批次由“待解调”变为“已完成”时更新进度摘要，重要的中断及恢复经过留在排查记录；换线、换配置另列批次，不覆盖旧结果。
- 操作用编号列表，一条一个主要动作；分析、结论和下一步用短文，只有一两句且无比较关系时直接写文字。结果说明紧跟对应表格，图中趋势的解释紧跟图，证据链接紧跟对应结论；不在正文重复表内数值，不单设“结果判断”栏目。每段只说一件事，长路径用可读链接表示。
- 参数、采集次数及逐点数值放对应表格；功率增量、偏差等数值注明比较基准后入表，首点无基准时留空。过宽时拆成以测量点或运行编号对应的小表，不在正文重复数值。必要测量条件、统计口径和积分范围仍须保留；线缆型号、仪器设置及结束状态存入本批次配置或程序记录。
- 正文在相关步骤后简述重要异常的影响、处理及最终状态，并链接对应轮次证据；会阻止下一步的未解决异常在该处明确说明。逐次报错、连续调参和详细排查保留在轮次材料中，不在正文重复展开，也不因精简删除失败依据或被修正的判断。
- 只记新增信息，不反复写背景、总目标、完整路径清单或已有结论。没有新结果或重要变化时不追加流水账；写后检查有无重复段落、过期的当前状态或混入其他批次的数据。
- 完整命令、参数配置和原始日志已有文件时，引用可定位的文件或运行编号，不整段粘贴。没有相应记录时补上必要的命令和条件，避免复现信息缺失。
- 图件默认给文件链接和简短说明；需要直观看到差异时才嵌入关键图片。同一产物的路径、图片和说明不在多个栏目重复。
- 不逐项报告正常状态；检查照做，完整状态保留在程序记录中，正文只补充异常、偏离预期及影响下一步的发现。明确的验收结果或必要交接状态仍可简记，不省略安全动作、必要操作条件或异常处置。不设机械字数上限。

## 边界

- 仪器操作、读回验证和异常收尾由 `link-test` 或项目程序负责，本技能负责方案讨论、推进协调与主记录。仅准备方案或整理已有实验、仿真或分析记录时，不触发实际仪器操作，也不连接仪器。
- 只记录实际动作和已有材料支持的结果，保留失败、未完成和暂时判断。
- 本地或飞书主记录用于阅读和接力，复用既有运行日志与配置，不代替或删改原始数据、机器记录。
- 周报、跨项目复盘和汇报按用户另行提出的请求处理。需要 Word 时交给 [docx](../docx/SKILL.md)。
- 维护本技能时优先精简现有说明和模板，不另建记录状态机或默认增加自动化。
