# 正式引用核验工作流

只在用户要求 IEEE、BibTeX、正式参考文献、引用核验或引用纠错时读取本文件。普通论文检索继续使用 `SKILL.md` 的快速流程。

BibTeX 解析、规范化和一致性检查思路本地化自 K-Dense `citation-management` 2.0；精确提交和许可证见 `upstream-source.md`。IEEE 文本格式独立依据 IEEE 官方 Reference Guide，不把两项来源混为一谈。

## 1. 逐篇登记

为每篇论文保留原始顺序和原始引用文本，再登记可核实字段：

- 题名与作者列表；
- 来源类型，以及期刊名或会议论文集名；
- 年、完整发布日期、卷、期、页码或文章号；
- 出版者、DOI、PMID、ISBN、arXiv ID；
- 正式页面、其他版本页面和访问日期；
- 每个重要字段来自哪个页面；
- 原引用或原 BibTeX 与核实结果的具体差异。

字段没有可靠来源时留空。问题说明直接写“未查到页码”“作者列表在两个来源中不一致”，不要用模糊的完整度分数代替实际问题。

作者序列中出现同名项时保留原顺序并报告重复姓名。不同作者可能同名，不能在没有来源依据时静默删除。

需要保留字段级来源时，`field_sources` 可使用 `字段 -> [{"source": "来源名", "value": "该来源给出的值"}]`。同一字段出现两个不同的非空值时保留两项并报告来源冲突，不静默覆盖。

## 2. 来源顺序

按以下顺序核对，并实际读取所用页面：

1. 出版商页面、IEEE Xplore、期刊页、正式会议页或论文直接页；
2. DOI 注册元数据，以及 Crossref、PubMed、OpenAlex 等权威索引；
3. 作者或机构页面，用于确认预印本和正式版本的对应关系；
4. 搜索结果、聚合页和摘要只用于发现，不能作为最终引用字段的唯一依据。

来源顺序不是机械覆盖规则。若直接来源字段明显缺失，而权威元数据补充了该字段，可以使用补充值并记录来源；若两个可靠来源给出不同值，标为“来源冲突”，不要猜选。

## 3. 版本与去重

- DOI 相同的记录视为同一工作。
- DOI 不同或其中一条没有 DOI 时，再用规范化题名、作者和年份判断；题名相似但不能确认时保留两条。
- 预印本与正式发表版本能确定对应时，以正式版本作为主条目，保留预印本 URL、arXiv ID 或其他标识。
- 勘误、撤稿和原论文不是可静默合并的普通重复项；保留状态并说明引用风险。
- 输出重复对应关系，让用户知道原清单中的哪些编号被合并；不要让条目无说明地消失。

## 4. BibTeX 对照

对照已有 BibTeX 时先按规范化 DOI 匹配；没有 DOI 再按规范化题名匹配。逐项比较题名、作者、年份、期刊或会议名、卷、期、页码或文章号和 DOI，分别报告：

- `missing-field`：原 BibTeX 缺少来源中已经核实的字段；
- `value-mismatch`：原值与已核实值不一致；
- `source-conflict`：可靠来源之间互相冲突，无法安全自动修正；
- `unmatched-entry`：无法把 BibTeX 条目可靠对应到论文记录；
- `parse-warning`：复杂宏、交叉引用或语法无法保守解析。

只用已核实字段生成修订结果。无法解析的条目保留原文并说明，不强行改写。使用 `--bibtex-input existing.bib` 传入需要对照的 BibTeX 文件；JSON 和 Markdown 输出会保留逐条问题。

## 5. IEEE 输出

格式以 IEEE Author Center 的 [IEEE Reference Guide](https://journals.ieeeauthorcenter.ieee.org/wp-content/uploads/sites/7/IEEE_Reference_Guide.pdf) 为准。至少区分：

- 期刊论文：作者、题名、期刊名、卷、期、页码或文章号、日期、DOI；
- 会议论文：作者、题名、会议或论文集名、地点、日期、页码和 DOI；
- Early Access 或预印本：按其真实发表状态输出，不能把预印本写成已有卷期页码的正式期刊论文；
- 图书章节：章节作者与题名、书名、编辑、出版地、出版者、年份和页码；
- 标准或报告：机构作者、题名、标准或报告编号、出版者和年份；
- 网页资料：作者或机构、页面题名、网站、日期、URL 和访问日期。

作者姓名使用名缩写在前、姓在后。作者不超过六名时全部列出；超过六名时列第一作者后加“et al.”。缺少字段时省略该片段，并在引用下方说明缺了什么，不输出空占位符或虚构内容。

## 6. 交付与写回

- 默认在聊天中按输入顺序给出编号后的 IEEE 引用，再列每条仍缺少或有冲突的信息。
- 用户明确要求文件时，再用整理脚本生成 IEEE、BibTeX、JSON 或 Markdown。
- 用户要求修正远程内容时，先确认 Wiki 节点实际承载的是文档还是多维表格，并保存写前版本信息。文档转 `lark-doc`，多维表格转 `lark-base`；只替换用户指定的引用字段、引用区块或记录，回读后核对条目数量、顺序、题名和 DOI。
- 本技能不下载 PDF、不总结全文、不替代论文审稿，也不检查整篇稿件的正文引用覆盖关系。
