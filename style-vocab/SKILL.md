# style-vocab

## 数据位置

词表数据不在本技能目录。使用绝对路径读取和维护：

- 核心表：`D:\BaiduSyncdisk\.agents\vocab\vocab-core.md`
- 全集表：`D:\BaiduSyncdisk\.agents\vocab\vocab-full.md`
- 专业术语库：`D:\BaiduSyncdisk\.agents\vocab\scientific-terminology-bank.md`
- 盘点候选：`D:\BaiduSyncdisk\.agents\vocab\ai-word-candidates.md`
- 受控学习候选：`D:\BaiduSyncdisk\.agents\vocab\writing-memory-candidates.md`
- 结构化例外：`D:\BaiduSyncdisk\.agents\vocab\writing-memory-exceptions.md`

`vocab-core.md` 是生成时约束；`vocab-full.md` 是通用词级规则的唯一依据；`scientific-terminology-bank.md` 是专业术语唯一活数据源，支持状态机（候选/已确认/已拒绝/冲突待审）、领域过滤、目标期刊和用户审阅；`ai-word-candidates.md` 只在盘点模式读取。`writing-memory-candidates.md` 不是生成约束，只有用户确认后才可迁入正式词表。

## 适用范围

只管交付文稿正文，包括论文、申报书、审稿回复、正式函件和对外说明。

不管普通对话、代码、注释、commit message、引用原文、参考文献、文件路径、URL、LaTeX 命令和 citation key。

## 先分诊

1. 用户给的是通用文风词、AI 味词、个人偏好替换词时，用本技能。
2. 用户给的是领域概念、指标名、缩写、仪器名、论文专用术语，转 `ieee-manuscript-edit` 的活数据术语库流程。
3. 用户要求整体去 AI 腔、改句式、改结构，按语言转 `humanizer`（英文）或 `Humanizer-zh`（中文）；论文/申报书稿件优先转对应写作技能。本技能只处理词级偏好和交付前扫词。
4. 分不清“文风词”还是“专业术语”时，只问一句：这个词是你所有交付文稿都想避开，还是只在某个专业领域固定翻译？

## 受控学习确认门

从用户本轮修改差异、已确认的前后句，或外部正式论文提炼新词条/表达模式时，先问用户是否启动“学习本轮表达”。没有用户明确同意，不提炼、不联网取样、不写候选台账。每轮最多展示 3 条高价值候选。

- 候选先写入 `writing-memory-candidates.md`，状态为 `候选`，不能影响当前或后续生成。
- 用户确认后才转为 `已确认`，并把完整记录写入对应正式词表（通用词写入 `vocab-full.md`，专业术语或表达模式写入论文活数据词库）；候选台账同时填写 `迁入位置`。用户拒绝则转为 `已拒绝`，保留拒绝理由、关联推荐词和日期，后续不得静默重新出现。
- 已确认规则与新证据冲突时转为 `冲突待审`，不得覆盖旧规则；先展示冲突再询问裁决。
- 外部论文只允许提炼术语、标准搭配或抽象短语模式；不保存完整句子、连续长片段、图注或方法描述。

## 模式一：收录

触发语例：`以后别用 X，用 Y`、`这个词太 AI，换成 Y`、`记住这个用词`、`收录领域术语`。

流程：

1. 读取 `vocab-full.md`、`vocab-core.md`、`scientific-terminology-bank.md` 的最新内容。
2. **强化分诊提问**：
   - 通用文风词、AI 味词、个人偏好替换词 → 本技能收录到 `vocab-full.md`
   - 领域概念、技术名称、架构术语、标准缩写、指标名、仪器名 → **新增收录路径**：收集必要字段后写入 `scientific-terminology-bank.md`
   - 实验装置名、特定配置、局部约定 → 提示用户在对应论文工作区建立 `terminology.md`
   - 分不清时问："这个词是你所有文稿都要避开（通用文风），你的研究领域内论文都会用（领域术语），还是只在这篇论文里固定翻译（项目专属）？"
3. **领域术语收录补充字段**（交互式询问）：
   - 适用领域（必填）：如"THz 通信"、"THz 前端架构"
   - 中文术语、推荐英文、可接受变体、慎用写法
   - 目标期刊（可选）：如"IEEE Trans."、"Optics Express"
   - 章节功能（可选）：如"系统描述"、"实验方法"
   - 来源（必填）：如"IEEE Trans. THz Sci. Technol. (2024)"、"用户指定"
   - 用户审阅：展示完整 15 列记录后，等待用户明确确认，不设默认值
   - 例外覆盖用户禁用（默认"否"，除非用户明确说明该术语必须覆盖之前的禁用）
4. 查重（在对应层级）：
   - 通用层查 `vocab-full.md`
   - 领域层查 `scientific-terminology-bank.md`（按领域过滤）
   - 同一术语已有记录时，只更新字段，不重复追加
5. 查冲突：
   - 新替换词和旧替换词不同时，先展示差异，询问是否覆盖
   - 跨层冲突（如通用词禁用 X，但领域术语要求用 X）：旧记录继续保持 `已确认` 并生效；新规则作为关联旧记录 ID 的候选记录写入台账，状态为 `冲突待审`；仅在用户明确裁决后才更新旧记录
6. 生成 `匹配模式`：
   - 中文词用字面子串。
   - 英文词用 `(?i)\b...\b` 和常见词形变化。
   - 不使用 lookaround，保持 `rg` 和 .NET 正则兼容。
7. 写入对应数据源。
8. 询问是否进核心表（只有通用文风词可进 `vocab-core.md`；领域术语和项目专属词不进核心表，避免跨域泄漏）；核心表满 30 条时先建议移出一个低频项。
9. 写完后重读对应文件，确认格式、重复项和核心标记一致。

## 模式二：盘点

触发语例：`盘点词汇表`、`看看还有哪些 AI 词该收录`。

流程：

1. 读取用户指定目录或文件；未指定时，优先最近正在处理的交付文稿，不扫描整个磁盘。
2. **叠加加载**三层词表和候选表：
   - `vocab-full.md`（通用层）
   - `scientific-terminology-bank.md`（领域层，按 `domain` 过滤）
   - 项目 `terminology.md`（如果存在）
   - `ai-word-candidates.md`
   - `writing-memory-candidates.md`（含拒绝记录，用于去重校验）
3. 跳过代码块、行内代码、URL、文件路径、LaTeX 命令、citation key、引用原文、参考文献列表和词表文件自身。
4. 输出候选表：`候选词 | 语言 | 命中次数 | 所在文件 | 建议替换 | 来源层级（已在通用/领域/项目）| 是否建议入表`。
5. **新增：写入时询问层级**
   - 用户确认候选后，问"这个词是通用文风、领域术语还是项目专属？"
   - 通用文风 → 直接写入 `vocab-full.md`
   - 领域术语 → 收集必要字段后写入 `scientific-terminology-bank.md`
   - 项目专属 → 提示在对应论文工作区建立/更新 `terminology.md`

## 模式三：检查

触发语例：`交付前扫一遍用词`、`按词表检查这篇`、`检查用词`。

流程：

1. 优先检查 Markdown / LaTeX 源稿；`.docx` 先调用 `docx` 技能提取纯文本或确认可编辑源。
2. **统一加载器**（新增）：
   - 通用层：始终加载 `vocab-full.md` 中 `场景` 匹配的词条
   - 领域层：根据项目 `domain` 字段或用户指定，加载 `scientific-terminology-bank.md` 中 `状态=已确认` 且 `适用领域` 匹配的词条
   - 项目层：当前论文工作区 `terminology.md`（如果存在且 `状态=已确认`）
3. **优先级与冲突处理**（可执行顺序）：
   - 第一步：状态/作用域过滤（只加载 `已确认` 且作用域匹配的规则）
   - 第二步：用户硬禁用优先（已明确禁用的词不被普通规则覆盖）；**注意**：`vocab-full.md` 表头无"硬禁用"字段，审计器一律将所有 `vocab-full.md` 词条视为硬禁用处理；优先级无法通过表中字段区分，来源字段（加载顺序+状态字段）为唯一依据；如需区分"硬禁用"与"建议替换"，需在 `vocab-full.md` 表头新增该字段（本轮范围外）
   - 第三步：显式确认的例外（`例外覆盖用户禁用=是` 的术语可覆盖禁用）
   - 第四步：具体性排序（同一词条多层都有规则时：项目专属 > 领域术语 > 通用文风）
   - 第五步：同层冲突（同层内不同替换、正则重叠或语义冲突 → "冲突待审"，不自动改写）；冲突待审时保留旧已确认规则，新规则写入候选台账标为"冲突待审"，不自动覆盖
4. 合并三层的匹配模式，生成统一检查规则
5. 扫描目标文本，跳过：
   - fenced code block 和行内代码
   - URL、文件路径
   - LaTeX 命令、label、ref、cite key
   - 引用原文和参考文献列表
   - 人名、机构名、论文题名
   - `vocab/`、`Humanizer-zh`、规则说明文件
6. 命中不等于违规。逐条对照 `例外语境` 判断。
7. 只改确认违规的句子；不要做全局盲替换。
8. 每轮改写后复扫，最多 3 轮。
9. 剩余命中输出短报告：`词条 | 位置 | 来源层级（通用/领域/项目）| 保留原因`。
10. 论文稿交付前复扫：调用 `audit_writing_memory.py`，传入稿件与 `vocab-full.md`、`scientific-terminology-bank.md`（当前脚本不支持项目层多数据源输入；脚本扩展前，项目层规则改为人工静态核验）

论文稿的交付前复扫必须调用 `ieee-manuscript-edit/scripts/audit_writing_memory.py`，并同时传入稿件、词表、专业术语库和结构化例外表。模型自述“已检查”不能代替脚本结果。报告必须记录输入与规则文件 SHA-256、审计器版本和上下文；`violations`、`unresolved` 或 `schema_errors` 非空时只能报告“复扫未通过”，不能声称精修完成。

## 写作技能协作

- `writing-router` 负责判断是不是交付文稿任务。
- `project-writing` 起草或精修申报书时，可读取 `vocab-full.md` 中 `申报书` 场景词条。
- `ieee-manuscript-edit` 起草或精修论文时，可读取 `vocab-full.md` 中 `论文` 场景词条。
- `Humanizer-zh` 管句式、结构和整体 AI 写作痕迹；本技能管用户自维护的词级偏好。
- 用户明确的硬禁用优先于普通术语建议；只有已确认、作用域匹配、用户审阅为 `是` 且显式标记 `例外覆盖用户禁用=是` 的专业术语或结构化例外才能覆盖指定禁用。冲突必须列为待确认。
- **完成交付文稿润色、精修任务后，主动询问用户："这轮修改中是否有用词规则值得收录到词表？"不等用户提醒才检查。**

## 输出

收录完成：

```markdown

位置：`D:\BaiduSyncdisk\.agents\vocab\vocab-full.md`
核心表：已同步 / 未同步
```

检查完成：

```markdown
已检查：<文件>
已改：<数量> 处
保留例外：<数量> 处
仍需确认：<数量> 处
```

## 验收

- `vocab-full.md` 无重复词条。
- 核心表不超过 30 个替换对，文件不超过 80 行。
- 新增英文匹配模式能覆盖常见词形变化。
- 检查模式不改引用原文、参考文献、代码、LaTeX 命令和 citation key。
- 不把专业术语误收进文风词表。
- 学习启动前有用户确认；未确认候选不影响生成。
- 已拒绝候选保留理由，不能由同义变体绕过确认门。
- 交付稿存在可核验的独立复扫报告；报告未通过时不标记完成。
