# lark-doc 画板处理指南

## 职责边界

| Skill | 负责 | 不负责 |
|---|---|---|
| `lark-doc` | 判断文档中哪里需要图；建立空白画板；取得文档 token、画板 token 和 block ID；插图后回读文档 | 生成、选择或校验拓扑图格式；直接设计画板内容 |
| `lark-whiteboard` | 图型判断、图内容清单、原生对象创建、追加、局部编辑、服务端回读、预览查看与完成判定 | 文档正文、文档排版、电子表格与 Base |

系统架构、硬件信号链、接线图、模块拓扑固定使用可编辑原生对象，由 `lark-whiteboard` 创建。文档入口不得生成 SVG。原生画板新建和追加使用 CLI RAW；已有画板的局部结构编辑使用画板技能的后台编辑器。二者都不通过 `lark-doc` 生成 SVG。

## 插入流程

1. 先通过 `docs +fetch` 确认目标文档、章节或 block 位置。
2. 在目标位置插入空白画板：

```xml
<whiteboard type="blank"></whiteboard>
```

3. 从 `docs +create` / `docs +update` 的返回结果同时取得：

- 文档 token 或文档 URL
- `block_id`
- `block_token`，即画板 token

三者不能互相替代。已有画板更新必须复用文档里现有画板的 token，不得新建空白画板来规避更新。

4. 主 Agent 读取 [`lark-whiteboard/SKILL.md`](../../lark-whiteboard/SKILL.md)，把本图目标、准确插入位置和上述三个标识交给画板技能。每张语义完整的系统图默认独立一个画板。
5. 画板技能完成原生写入、RAW 回读和预览查看后，`lark-doc` 只回读目标 block，确认画板仍在原位置且文档未被无关改动。
6. 原生写入未完成时，保留准确的文档、画板 token 与 block ID 并报告未完成；可以继续补写同一画板。不得留下空白占位画板冒充完成。

## 图型分流

系统框图、信号链、接线和模块拓扑无需讨论格式，直接进入 `lark-whiteboard` 原生路线。

思维导图、时序图、类图、饼图或甘特图等非拓扑图，先由主 Agent 判断是否原生对象更合适；确实需要 Mermaid、PlantUML 或 SVG 时，向用户说明原因和取舍并征求意见。用户不负责记住格式名称。用户明确指定某一格式时，进入 `lark-whiteboard` 的显式非原生导入路径，并明确其可编辑性和绑定限制。

系统拓扑不得自动选择 Mermaid、PlantUML 或 SVG。原生编辑失败不构成改用其他格式的理由。海报式视觉确实需要静态图片时，先取得用户同意，再作为普通图片插入；静态图不替代系统框图，不占用原生图位置的完成状态。

## 完成检查

- `lark-doc`：画板 block 位置、文档 token、画板 token、block ID 与最新文档回读一致。
- `lark-whiteboard`：图内容清单、RAW 回读、连线两端绑定和实际预览均通过。
- 不把“文档里有画板块”“工具返回成功”“RAW 有 N 个节点”单独当作完成。
