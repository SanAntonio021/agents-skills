# 流接口与包处理

先核对实际接口。AXI-Stream、厂商流接口及无背压采样接口不能混用假设；从端口、IP 配置和使用方确定哪些旁带存在，以及字节顺序、有效字节和帧边界约定。

## 握手与缓存

对采用 ready/valid 的 AXI-Stream，时钟有效沿上 VALID 与 READY 同时为真才发生传输。源端不能等待 READY 才断言 VALID；VALID 一旦断言，除协议规定的复位外，必须保持到传输完成。等待期间 payload 及其有效旁带保持不变。状态机、地址、计数器按相应接口实际握手推进，不按 VALID 单独推进。

插入寄存器或缓存时检查容量、满空判断、同时入出、连续吞吐和背压传播。需要切断 READY 路径时选用已有 register slice、skid buffer 或 FIFO，并核对其行为；不把简单打一拍视为完整弹性缓存。不能背压的源必须明确峰值、缓存容量及溢出策略，不凭平均速率保证无丢失。

## 包与多入口

数据、TLAST、TKEEP 和适用 TUSER 在缓存、位宽转换及流水线中保持对应关系；特别验证非整字尾包、最后一拍被阻塞和相邻包。不得把每个总线周期都当成满有效负载。

两个入口共享写入资源时，先确定互斥访问、包级仲裁或请求级所有权，返回信息如何关联来源，以及复位或断流如何恢复。包级仲裁应在合法边界切换，不能只看一个时钟周期有无 VALID 就释放未结束的包。公平性、超时、中止和重试需依项目协议定义，不能擅自补出丢包规则。

多光口接入还涉及 MAC/PCS、GT、参考时钟、复位、地址与协议状态；复用一个 RTL 接口不能证明第二个物理口可用。先查已有工程与 IP 支持，器件引脚和速率不得猜测。
