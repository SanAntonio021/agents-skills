# 项目骨架

新建项目，以及整理、归位已有项目时使用。只创建有内容的目录；按实验规范用脚手架建立的项目，沿用脚手架生成的目录和文件。已有项目不为统一而批量改名；已提交的申报包、比赛包和冻结的提交版本保持原样。用户指定的结构和项目已有约定优先。

## 根目录

根目录默认平铺，用类型前缀分组，不为分类增加层级。

```text
<项目>/
├── README.md  AGENTS.md  项目规范.md
├── lab.md                                          实验项目的人工记录，按实验规范建立
├── code/  config/                                  代码与配置
├── simulation/  measurement/  analysis/  checks/   运行批次：<类别>/YYYYMMDD_HHMMSS_<名称>/
├── paper_<简称>/                                   一篇论文一个目录
├── 专利_<简称>/
├── 申报_<事项>/                                    申报书、实施方案、任务书
├── 验收_<事项>/                                    中期、结题、测试大纲与报告
├── 方案_<主题>/                                    技术方案、选型、调研
├── 汇报_<主题>_v01.pptx                            汇报和演示材料，文件可直接平铺
├── 归档/
└── 过程文件/
```

只有一两个文件的类型可以不建目录，文件带同一套前缀直接平铺在根目录；周期性汇报用日期区分，如 `汇报_组会_20261105.pptx`。前缀清单固定；出现放不进去的类型时，先与用户确定新前缀，不临时发明。根目录不加排序编号，编号只用在顺序本身有含义的地方，例如提交版本。

运行批次沿用实验规范的命名；归入已有结果而时刻未知时只写日期，不补造时刻。整合迁移产生的 `恢复资料/` 沿用本技能既有约定，不属于类型前缀。

新建项目在 AGENTS.md 写明“过程文件可整体清理”，`chat-notes` 据此按目录整体清理；已有项目等 `过程文件` 里的正式内容都归位后再写。

## 中文还是英文

只问一件事：程序会不会把这个目录当作工作目录，或按路径读写其中的文件。

- 会：目录名及其子目录用英文字母、数字和下划线，不带空格和中文。
- 不会，里面只有人直接打开的文档：用中文前缀。

按类型判断，不按个例；清单外的新类型先按上述标准归类，再加入清单。

| 目录 | 语言 | 依据 |
|---|---|---|
| `code`、`config` | 英文 | 程序本身 |
| `simulation`、`measurement`、`analysis`、`checks` | 英文 | 程序写入结果 |
| `paper_<简称>` 及其子目录 | 英文 | 编译、绘图脚本输出、代码按相对路径引用 |
| 子工程目录 | 英文 | 自带代码或是独立仓库 |
| `专利_`、`申报_`、`验收_`、`方案_`、`汇报_`、`归档` | 中文 | 只有人打开的文档 |

英文目录中，程序读写的文件用英文名，给人看的文档可以用中文名。中文目录不放长期使用的程序；需要长期保留的脚本进 `code/`。`过程文件` 沿用原名，是这条标准的例外。

## 层级

人直接打开的文件（稿件、PPT、表格、说明文档）距项目根不超过 2 层目录，即最深为 `项目根/目录/目录/文件`。代码树、运行批次、LaTeX 工程、完整申报包和外来仓库保留内部结构，但入口文件满足上述要求。需要第 3 层时，改用命名把内容并入上一层。

实际出过问题的是路径过长，不是中文字符。归位前检查最长路径；代码包和数据包不搬动，也不加长其上级目录名。

## 论文

论文随项目保存，一篇论文一个目录，直接放在项目根下。独立的论文工程视为只产出一篇论文的项目。简称取论文主题，不取期刊名，改投后仍然适用。

```text
paper_<简称>/
├── <当前稿件>                Word 或 Markdown 稿直接平铺；LaTeX 稿用一个工程目录，默认 latex/
├── figures/                  各提交版本共用的图源和成品图
├── submission-state.json     投稿状态记录，开始投稿时建立
├── 1_<期刊>_<提交日期>/       一次提交一个目录，存放冻结的提交件
└── 2_<期刊>_<提交日期>/
```

- 当前稿件和图源始终在论文目录第一层。提交件在论文目录第一层准备，提交当天建立版本目录并移入，此后不修改其中已提交的文件；工作目录可以随时重新编译，不会覆盖提交件。版本目录的序号按提交先后从 1 起，期刊用常用简称，日期写 YYYYMMDD。
- 该次提交收到的决定信、审稿意见原件和回执放入对应的版本目录；为该次提交准备但最终未上传的材料也放这里。
- 回复稿是下一次提交的工作稿，放论文目录根，提交后随新版本冻结。
- 为论文做的分析，脚本进 `code/`，结果进 `analysis/` 批次，论文目录用相对路径引用。

## 子项目

- 有独立目标、经费或交付，能脱离父项目继续的，作为独立项目与父项目并列，用共同的名称开头归组。
- 只为父项目服务的子工程（一个工具、一块板的工程、外来仓库）放在父项目根下一层，占一个目录，不再套第三级。
- 子工程不另设 `过程文件`。只有单独分发的子工程保留自己的 README 和 AGENTS，其余说明并入项目根 README。
