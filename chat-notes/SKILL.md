# 对话经验整理

从本轮对话和实际改动中找出下次仍有用的新信息，核实事实并检查相关现有说明。能说清这条经验会改变下次哪个判断或行动，才值得记录；一次失败本身不等于规则缺失。

优先更新已有文件：项目事实留在项目说明，跨项目方法归负责该行为的已有 Skill。按内容选择正文、参考、模板、脚本或测试；只有现有文件无法承载时才考虑新建。

已有规则清晰覆盖时，不追加同义句；存在冲突或结构妨碍执行时，通过删改、合并解决。没有新信息就不新增文件。按实际变化检查受影响的用法、配置、接口、名称路径、架构图和上下游说明，更新相关现有材料，不为凑分类创建文档。

本地依据不足，或外部方案会影响技能改进选择时，通过 `web-access` 查上游并比较可复用部分；沿用来源和许可要求，不自动安装或替换。不要求每次搜索技能市场、统计热度或填写固定比较表。

只有建议、没有具体修改授权时，简短说明值得改哪里、为什么以及准备怎么改。已有准确授权就完成该范围的修改；修改 Skill 后使用 `skill-creator` 做相称检查，并按[发布说明](references/skill-edit-followup.md)自动提交、推送和双端同步，除非用户明确限定只改本地。

整理和记录完成后，按已有清理授权处理本轮可确认的临时文件和失效中间产物，优先采用可恢复方式。保留正式成果、可编辑原件、来源证据和必要验证材料；归属、用途不明或范围外的文件不动。清场后检查保留成果和引用仍有效；没有新经验不妨碍完成已授权的清场，单独调用本技能不等于任意删除授权。

用户要求整理目录或命名时，遵循项目现有习惯和依赖关系，调整后修复引用；涉及多目录合并或迁移时使用 `project-organizer`。不默认搬平目录或强加统一前缀。

未完成事项或异常需要留待恢复时，在本次获准维护的现有记录中简要留下状态、影响和恢复依据，解决后更新原记录；确无合适落点且需要后续追踪时才新建。只审阅时在回复中说明，不额外落盘，也不强制生成中央报告。
