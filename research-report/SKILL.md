# 调研报告

## 目标

把已经完成调研的问题写成读者能够顺着结论、事实和引用读下去的报告。报告不承担展示研究过程、待办事项或取证进度的职责。

本技能不规定页数、章节数、图数或咨询公司式目录。先根据读者需要获得的结论选择结构，再决定是否需要市场规模、竞品、政策或技术比较等模块。

## 两类工件

正式报告与内部调研台账必须分开保存，不能用同一份文稿同时承担两种用途。

| 工件 | 面向对象 | 可包含 | 不得包含 |
|---|---|---|---|
| 正式报告 | 报告读者 | 已闭合研究问题的范围、可核验事实、分析结论、真实引用 | 待补充、待核实、待确认、来源补全任务、内部编号、行动安排 |
| 内部调研台账 | 研究者和项目组 | 问题状态、检索记录、来源冲突、缺失字段、内部编号、后续取证任务 | 面向外部或决策读者的正式结论 |

先读取 [内部调研台账](references/research-ledger.md)，建立并维护台账；只有报告范围内的问题全部闭合，才开始写正式报告。用户只要求发现证据问题或重构原稿时，可以交付台账、映射表或审查意见，但不要把它们伪装成完成的正式报告。

## 正式报告的内容职责

正式正文只保留三类内容：

1. 定义与研究范围：说明讨论对象、地区、时间、资料截止日和必要术语。
2. 来源事实：写真实资料直接支持的事实、数据、参数或原意，并就近引用。
3. 综合判断：在已写明的事实基础上作出的比较、归纳或结论。

一个段落只承担一种主要任务。定义不与市场结论混写；事实不以行动要求收尾；判断不加入新的无来源数字。术语只在“范围与术语”或专门背景节定义一次；主体发现段直接写对象、事实和判断，不先重复“X 是……”再转入调研内容。研究范围可以限定对象、地区和时间，但不能把未完成取证改写成“资料范围”“证据条件”或“暂不判断”段落。

原稿中的建议、行动安排和下一步要求只留在内部重构映射表中，处理为删除或转入台账。不要把“应冻结参数”改写成“参数核定还需要某些资料”并放进正式稿；前者是行动语句，后者仍在向读者展示未完成调研。

写作或重构前必须读取 [报告内容契约](references/report-contract.md)。按任务再读取：

| 当前任务 | 读取文件 |
|---|---|
| 选择新写、证据转报告、重构或只审查模式 | [工作模式](references/modes.md) |
| 处理已有 Markdown、DOCX 或长稿 | [旧稿重构](references/restructure-existing.md) |
| 维护未闭合问题和来源状态 | [内部调研台账](references/research-ledger.md) |
| 需要核对外部设计来源 | references/upstream-sources.md，仅在来源登记完成后出现 |

## 流程

### 1. 确定读者问题和完成标准

从现有材料提取并写入内部台账：

- 主要读者和使用场景；
- 调研对象、地区、时间范围和资料截止日；
- 必须回答的问题；
- 每个问题的可接受证据标准；
- 输出格式和用户明确要求保留的内容。

只有缺失信息会改变报告对象、统计定义、证据标准或交付形式时，才问一个最关键的问题。其他事实通过调研自行补齐。

### 2. 先过研究闭合门

对每个必须回答的问题逐项判断：

- 是否已有能直接支撑结论的真实来源；
- 事实、数据、版本、地区和时间是否一致；
- 引用信息是否足以按选定规范形成可回查的正式条目；
- 来源冲突是否已经处理，或该问题是否已按用户确认的范围排除。

只有全部满足时，问题才可进入正式报告。任何一项未满足，都留在内部台账并继续取证；持续取样和证据链补齐转交 baseline-research。

不要静默删掉用户要求回答的问题来让报告看似完成。若用户要求的问题尚未闭合，明确交付内部台账或调研进度说明，并等待补充调研或用户调整研究范围。

### 3. 选择工作模式

按 [工作模式](references/modes.md) 选择一种主模式：

- new-report：先形成研究约定和内部台账，闭合后再写报告；
- evidence-to-report：从已闭合的证据集生成报告；
- restructure-existing：重排已有长稿，把未闭合内容转入内部台账；
- audit-only：只指出问题，不改正文。

不要因为材料很多就自动采用“市场概览—竞争格局—趋势—建议”的固定结构。

### 4. 建立问题、证据和章节关系

先在内部台账中为每个读者问题记录已闭合来源、可作出的结论和正式稿位置。对每个关键来源事实和综合判断补一条“来源—断言”记录，写清实际支持范围、冲突处理和将采用的正式引用；内部来源键只用于核验，不能进入正式稿。读者问题只用于组织工作，不直接复制成正式标题。

正式标题用对象明确的名词短语或结论句。例如：

- “研究目的与决策问题”；
- “公开试验进展”；
- “终端样机参数”；
- “业务状态判断”。

不用“这份报告要帮助项目团队判断什么”“当前应如何推进”“核心洞察”“关键抓手”“战略启示”等标题。研究目的直接写评估对象、比较对象或结论用途，不写“帮助团队判断”“供读者弄清”等口语元话语。

标题只在读者问题、证据类型或分析对象发生切换时设置。一个标题下只有一段短说明、少量零散参数或一张表，而相邻内容仍围绕同一对象和同类证据时，优先并入相邻章节；不要为了目录整齐另设薄标题。

### 5. 先写事实，再写判断

每个主体小节通常先给出最重要的发现，再写支持它的事实、数据和正式引用；需要综合时，另起段落写判断及其所依据的事实。

术语只解释到读者能够理解后文为止。术语较多时放入“范围与术语”或附录；摘要不承担术语表的工作。

正式稿不设置“证据范围与待核实事项”“资料缺口”“引用信息待补”或同类章节。发现未闭合事项时，停止该问题的正式起草，回到内部台账和调研流程。

### 6. 最后写摘要

摘要最后写。它只概括研究对象、最重要的已核验发现和报告结论，不交代研究尚未完成的事项、缺失字段、检索过程或引用整理过程。

摘要优先写成一个或少数几个连贯自然段。通常从最重要的结论或发现切入，用事实和推理关系连接后文。允许在开头用一句自然的话交代研究对象或分析范围，但不要把“研究对象、主要发现、证据限制、当前含义”写成逐句短标签、四段清单或重复的元话语开头。结构化概述只能作为过渡，摘要主体必须综合归纳发现及其关系，不能把各章节首句拼接成摘要。

不要在摘要解释常识性名词，不加入正文没有来源的数字，也不加入行动指令、劝告、未完成状态或防御性限制语句。若术语确实影响结论，先在范围与术语节完成一次定义，摘要直接使用术语及其已核验发现。

### 7. 做内容审计

对 Markdown 或纯文本可运行启发式审计：

    python scripts/audit_report.py path\to\report.md --mode formal --json

内部调研台账可用：

    python scripts/audit_report.py path\to\research-ledger.md --mode internal-ledger --json

脚本检查摘要的机械结构、内部分类和来源编号、未完成调研状态、行动性表达、同段混写、无来源事实、口语问题式标题、标题过密或薄章节、咨询式用语、重复句和过度加粗。它只提供排查线索，不能代替人工判断。

最终逐项检查：

- 信息顺序是否符合读者理解结论的过程；
- 定义是否与事实和判断分开；
- 每个正式结论是否由就近的真实来源支撑；
- 每条正式引用是否能回到真实且可回查的来源条目；
- 正式正文、摘要、标题、脚注和参考资料中是否都没有内部编号、未完成调研状态或行动性表达；
- 标题是否只在对象、证据类型或分析问题切换时出现；孤立短段和单表是否已并入相邻章节；
- 中文是否自然、具体，没有模板填充、连续否定、弱化断言的套语或同义反复。

## 证据与引用规则

- 起草前建立来源清单，记录原材料实际提供的题名、发布主体或作者、日期、文号、DOI、URL、访问日期或本地文件位置。原材料没有的字段不能推测或补造。
- S-01、S01 等编号只用于内部台账或重构映射表，绝不是正式引用格式。正式稿采用用户指定的脚注、尾注或编号参考文献；未指定时，可采用顺序编码，并确保每个编号对应真实来源条目。
- 未闭合来源元数据和无法回查的材料留在内部台账。不要把“引用信息待补”写入摘要、正文、脚注、参考资料说明或交付说明后仍把文稿称为正式报告。
- 关键事实和数字就近放置正式引用；引用必须实际支持该句，来源清单之外的条目不得进入正文。
- 计算结果引用输入和计算方法，不冒充来源直接发布的数字。多篇转载同一原始资料只算一条证据链。
- 发现来源冲突时，在内部台账解决或按用户确认的范围排除相关问题；不得用模糊限制句掩盖冲突。

## 语言与版式

- 用具体主语、动作、条件和结果写句子；需要强调时补证据，不靠形容词。
- 删除只评价材料、产品或来源作用而没有新增事实的元话语，例如“这些材料共同构成……基础”“为……提供依据”“作为外部参照”“形成……信息基础”。把其中的对象、时间、数据和适用条件直接写出来；没有事实增量时删句。
- 标题使用对象明确的名词短语或结论句；内部读者问题只用于搭结构，不原样进入标题。
- 目的和作用使用“评估、核定、识别、比较、验证、形成决策依据”等专业动词。
- D/F/J/R/U、[事实]、[判断]、[建议] 等标签只用于内部工件，不得替换为四字句首标签进入正式稿。
- 不使用“待补充、待核实、待确认、仍待补证、引用信息待补、尚未公布、尚不能说明、不宜、建议、下一步、推进”等未完成、免责或行动性表达。若“公开信息的边界”本身是必须回答的事实，不用状态模板句，改写为带日期、对象和来源的具体描述；若该事实还不能闭合，则转入内部台账。
- 避免“不是没有、并非不存在、不能不、未必不、无不”等连续否定，改为直接肯定或否定；避免“在一定程度上、相对而言、某种意义上、不排除”等没有证据作用的弱化限定语。确有统计不确定性时，写明区间、条件、样本或来源，而不是用模糊缓冲词。
- 少用“赋能、抓手、闭环、落地、核心洞察、深度解析、战略纵深”等套话；专业语境中的同形术语除外。
- 不反复使用“从……来看”“不只是……更是……”“综上所述”等连接方式。
- 表格用于参数、来源和明确可比较项；解释和推理写成段落。
- 只对标题、真正需要扫描的关键词和表头加粗，不整段加粗。

## Word 交付

内容在 Markdown 中通过研究闭合门和人工复核后，再按 docx 规则生成新的 DOCX。不要覆盖原文件，也不要把原文件的生硬模板自动带入新稿。

## 边界

- 持续性 sample-first 调研、证据表和任务池维护由 baseline-research 负责；研究闭合后再使用本技能。
- 单篇论文总结由 paper-summary 负责，多篇学术证据检索由 research-lookup 负责。
- 论文、申报书和投稿材料仍由 writing-router 的对应下游技能负责。
- 只做 Word 样式、分页或格式转换时不接管 docx。
- 不把投资、法律或合规意见伪装成调研事实。

## 完成条件

报告只有在以下条件同时满足时才算完成：

1. 读者能在前几屏知道报告回答什么问题和得出什么结论；
2. 所有用户要求回答的问题都已研究闭合，或已由用户明确从本次范围排除；
3. 定义只在必要位置出现一次，没有挤占摘要和发现段；
4. 关键事实和数字能够回查到真实来源；
5. 正式稿引用只对应真实来源，不含内部来源编号或补造的元数据；
6. 正式稿不呈现待补充、待核实、待确认、资料缺口、引用待补或同类内部状态；
7. 摘要和标题使用专业、自然的中文，没有否定清单、口语问句、四字标签链或模板填充；
8. 正式稿没有行动建议、行动指令或防御性限制句式。
