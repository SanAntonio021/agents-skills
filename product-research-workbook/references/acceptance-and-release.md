# 验收与发布

## 交付前验收

以下针对产品库流程。普通产品或采购渠道对比、一般表格审计及仅改格式的任务采用 `xlsx` 的相应检查，不要求为验收补建过程账本或正式编号。

1. 用 `validate_product_workbooks.py` 校验过程表和正式表；保存新的 JSON 报告，不能覆盖旧报告。
2. 用 `xlsx/scripts/verify_xlsx.py` 做 ZIP/OOXML、公式和对象检查。正式工作簿不含公式时，验收结论应为公式数 `0`，不为制造缓存而重算。
3. 对每张正式工作表进行视觉验收：整体检查，再抽查长表首、中、末区。检查字段和单位、冻结窗格、换行、列宽、裁切、重叠、空白页、链接显示和采购筛选。
4. 如需 PDF，只按 `libreoffice-runner` 的调用契约生成新的隔离输出，不直接运行 `soffice` 或控制 Microsoft Office。若当前任务明确要求 Excel 原生检查，单独交给 `xlsx` 的原生 gate，遵循其技能内的进程归属、隔离副本和自有空实例清理要求；PDF 转换本身不触发该检查。
5. 记录过程/正式文件 SHA-256、产品和渠道数量、校验报告路径、OOXML 超链接关系结论和视觉结论。

## 历史表只读审计

先记录源文件 SHA-256，使用只读加载或 ZIP/XML 检查得到差异。审计完成后再次计算 SHA-256；不一致时停止，不把源文件重保存为任何版本。

历史编号默认保留，行标识与厂家型号分开，不因审计或使用本技能而自动删除、重排或净化。已发布产品库编号继续按契约稳定维护；普通历史表不自动转换为产品库格式。

只有当前项目明确要求删除历史人工编号时，才采用净化流程：用源工作表和行/单元格定位，不在新输出、样本、说明或映射中复制明确要求移除的旧值；初版产品库正式编号仍为数值型 `1..N`。在独立暂存目录运行 `scripts/scan_legacy_identifiers.py <source.xlsx> <staging-directory> --identifier-header <source-id-column> --json-out <new-scan-report.json>`；扫描报告只记计数和问题文件，退出码 `0` 后才交付该净化版本。未提出净化要求的任务不运行这项发布检查。

## 技能源码发布

技能源码只在 `D:\BaiduSyncdisk\.agents\skills` 修改。测试和评审通过后，精确暂存本任务路径，保留其他用户改动，提交并推送。取得远端 40 位 SHA 后，调用 `Invoke-CcSwitchSkillSync.ps1` 仅同步这次实际改变的技能。

只有远端源码、`.cc-switch\skills`、`.claude\skills`、`.codex\skills` 的目标文件集合和 SHA-256 全部一致，才能称为运行时生效。新增 Skill 首次安装或四层验收不一致时，停止并报告“源码已推送，但运行时未生效”；不手工复制、不改数据库、不点击全部更新。
