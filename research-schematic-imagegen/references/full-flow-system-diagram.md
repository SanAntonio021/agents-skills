# 全流程系统图合同与验收

适用于一张图需要同时呈现端到端业务路径、地面/空间/网络等分区，以及控制、运维、反馈或可选机制的科研和工程系统图。它补充通用技术合同，不取代项目中的技术依据。

## 1. 建图合同

先确定读者和用途。面向领导汇报、跨专业讨论或首次接触该系统的读者时，缩写首次出现应给出确认过的中文全称或括号短解释；面向领域专家时，可只保留通用缩写。

按下表在提示词前写清每一种关系。没有台账的关系不画，台账中标为可选的关系不画成主路径。

| 关系类型 | 源节点 | 目标节点 | 业务含义 | 视觉语义 | 布局约束 |
| --- | --- | --- | --- | --- | --- |
| 主业务 | [节点] | [节点] | [数据、能量或任务主线] | [实线、颜色、箭头方向] | [沿首要阅读线，逐段直连] |
| 控制/运维 | [节点] | [受管节点] | [逻辑控制、监测或调度] | [虚线、颜色、箭头方向] | [靠近受管对象，不跨图绕线] |
| 可选/备选 | [节点] | [节点] | [仅在特定条件下启用] | [虚线或强调色] | [只连接已确认对象，不抢主线] |

合同还应列出：

- 分区及其角色：例如应用端、接入端、传输/平台、核心网络、运行保障。分区名称按实际系统调整，不把逻辑层强行画成实体设施。
- 每个节点的准确标签、允许的括号解释和禁用词。文字只能来自这份清单。
- 图例：主业务、控制/运维、可选机制各自的线型、颜色和箭头方向。颜色必须在白底投屏时仍能区分，不能用低对比度浅色承担主线。
- 省略项及其理由：例如为避免误导而不展开的内部协同、实际物理链路或设备内部实现。

## 2. 空间布局

先为主业务路径留出连续、短而清晰的阅读线，再安放辅助关系。不要让装饰、说明框或跨图长线盖住主线。

- 控制与运维节点可作为独立保障区，也可放在受管对象近旁；选择以读者能否看清“谁管理谁”为准。
- 若一条线只表示逻辑管理关系，标签或图例应避免暗示它就是物理无线/有线链路。实际物理链路只有在技术依据要求时才画。
- 用线条穿越多个无关分区通常说明节点位置不对。优先重排控制框和局部连线，而不是让线在外围绕行。
- 模型不能替代拓扑设计：每一条箭头都要能回填到关系台账，且不与禁画关系冲突。

## 3. 提示词补充

在通用提示词后增加以下信息，并把尖括号替换为合同中的具体内容：

```text
System-flow requirements:
- Make <main path> the first readable path, with direct directed arrows for every adjacent pair.
- Use <business visual semantics> only for the main business path.
- Use <control visual semantics> only for these logical control or operations relationships: <source -> target list>.
- Use <optional visual semantics> only for these optional relationships: <source -> target list>.
- Place <control nodes> adjacent to their managed objects; no long perimeter routing and no floating arrowheads.
- Include a compact legend that matches every visible line type.
- Render only the approved labels exactly as written: <label list>.
```

## 4. 验收门槛

在进入 `final/` 前，保留整图视图和每个具有独立节点或连线语义的分区放大图。常见分区包括主路径、控制/保障区、网络/平台区和应用/终端区；具体数量由图的结构决定，不为凑数量重复裁剪。

对整图和每个局部逐项确认：

- 每个标签逐字符合合同，中文、括号、缩写、全称和解释均无错字、重叠或裁切。
- 主业务箭头逐段连接相邻节点，方向与合同一致，没有悬空箭头或遮挡端点。
- 控制/运维线只连接台账中的控制关系；可选线只连接台账中的可选关系，且不会被误读为主业务必经路径。
- 图例与实际颜色、线型和箭头方向一致；投屏尺寸下主线仍比辅助线清楚。
- 分区、节点和说明框不互相遮挡；边缘留白足够，视觉上没有无意义的绕线或重复元素。

发现问题时，先界定受影响区域，再做局部编辑或确定性覆盖。保存前比较修正前后的无关区域，确保已通过的主路径、节点和文字没有被重画。仅当局部修正无法恢复正确拓扑或可读性时，才重做整图。

在 `record.md` 记录本轮关系台账、检查区域、发现的问题、修正范围和最终 `PASS`/`FAIL` 结论。文件名含 `final` 不能替代这一步验收。
