# 实验准备与记录

把讨论形成的方案写成现场可执行的步骤，实验时在对应位置记录结果，让换电脑或换人的接续仍有依据。普通仿真日志和已有结果整理直接走记录流程，不要求补做实验规划。

## 开始与范围

1. 先读用户指定的主记录；未指定时沿用项目已有记录和产物目录，主稿可以在本地或飞书。确实没有且用户未指定在线位置时，用 [简短模板](assets/labbook-template.md) 建立 `labbook.md`；已指定飞书时按该处格式建记录，不另建本地同步正文。多处记录无法确定主稿且影响写入时，只确认主稿位置。
2. 续写前读取当前内容，保留用户手改和历史条目。默认用中文，沿用已有格式和目录，不自动重排旧记录。写前再次核对相关片段；出现并发修改时基于新内容合并，冲突未明不覆盖。
3. 开头简要写明当前目标和关键条件，已有内容不重复介绍。同一任务续做时继续原记录；切到无关任务时不延续旧日志，用户要求停止时立即停止。
4. 按关键实验、重要修改或判断变化更新记录。讨论中的假设和建议不写成已批准方案；确认后的选择及时写入，结果产生后及时补充。普通操作不要求前后各写一遍，也不等全部工作结束才追记。

## 逐步准备实验

- 先读已有方案、结果及当前问题涉及的设备资料；涉及实物能力时配合 `lab-resources` 查来源。一次讨论一个影响做法的问题，能从资料查明的不重复问用户。
- 先拟好一个小实验的完整步骤，包括接线、设置、测量、记录及进入下一步的条件。按 `technical-writing` 的实验操作单写法展示，经用户确认这部分正文后写入主文档，再展开下一部分；认可整体结构不等于确认全部正文。
- 写明参数、单位、测量点及顺序、每点采集次数和判断标准。已确定的数值直接写入，不用“较低／较高”“多测几次”代替；未知参数先查明或提出具体建议供用户判断，不自行补造。
- 人工填写项采用“填写项｜内容”两列表格，每行指明一个具体信息，内容格留空；在标题标“（人写）”，照片单独留位置。用户也可在对话中提供信息，由AI代填，不要求重复手写。
- 在对应步骤后留出“（AI写）”结果、图片和数据位置。人写、AI写的参数均用表格，每个结果格只放一个参数；I/Q、译码前后、均值与标准差分别列项，参数名与单位放在行名或表头。没有结果时留空，不加下划线、占位空格或“待回填”。计划设定与实测结果分开，图片和分析结论单独放，不强制表格化。
- 表格过宽时拆成设置表与结果表，用相同测量点或运行编号对应，不靠一个格子合塞多个参数缩短表格。公用设置按主题分小标题；已经写明的固定接线不要求人工重复填写，只记录实际通道和变化。
- 保留公式、必要条件和操作动作，删除重复解释、无动作的提醒及讨论中的反复纠偏。记录和判断跟随步骤，不集中堆在文末；选做扫描和异常排查放在主流程之后。

## 现场推进与回填

- 先核对当前步骤及已批准条件；只有用户已授权上机且现有安全检查通过，才由 `link-test` 或项目程序执行仪器操作。写好方案本身不授权连接或开启仪器。
- 方案明确允许的调节和复测按约定执行并记录，不逐点重复询问。需要改变参数范围、次数、接线、处理方法或测试顺序时，先说明原因、拟改内容及影响；经用户确认后更新方案，再执行。不把建议提前写成当前操作指令。
- 异常可以先暂停，必要安全处置沿用仪器操作规则；暂停排查不等于获准更改方案继续测试。保留异常数据和已完成进度。
- 读取本次真实数据、配置和日志后，在对应步骤回填数值、判断、代表图片及可定位的数据引用，不用计划值、历史结果或推测代替实测。保留失败及获准调整的过程，不为使结果看起来完整而删掉不利记录。
- 每轮按本步骤判据判断继续还是排查；只有实际完成的步骤才记为完成。文档写入后读回核对，回填受阻时保留已保存的结果和待更新位置，不重跑测量来解决文档问题。
- 整理已填写表格时逐项搬移原值，保留精度、单位、统计口径、数据来源和图片，写后逐项核对。含义不明确的数据不猜拆，不将空白补为零；文字分析中的多个数值不因此机械拆表。
- 换线、换配置后的测量分别列批次，关联各自设置、结果和来源。明确当前与历史结果，保留失败及被后续修正的判断，不把旧批次结论套用到新批次；涉及改变工作点建议或科学判断时先核对依据，再请用户确认。

## 换电脑或对话接续

- 先读同一主文档、已有结果、上次停下的位置及必要的代码版本和依赖，继续尚未完成的步骤，不重新规划整套实验或另建重复记录。沿用现有表格、单位和批次对应关系回填；需要调整表格结构时先说明，不自行改成大段流水记录。
- 只核对缺失或变化的信息：当前接线、设备占用、代码与依赖、实际控制能力及本轮操作授权。历史接线和上机授权不自动当作当前事实；能从现场已有配置和材料查明的不要求用户重新口述。
- 跨机材料用接续电脑可获取的仓库版本、附件或共享数据位置定位；旧电脑的绝对路径不能单独作为可用交接依据。缺少材料时说明具体缺项及影响，不凭旧环境验证结果声称现场已就绪。

## 随实验维护设备关联

- 涉及设备或模块的实验，新建、续写主记录时配合 `lab-resources` 查找并维护现有“测试与维护”索引：主记录链接或路径、所属项目、已实际参与的具体实物。同一云文档按稳定 token、本地按准确绝对路径查重，续写复用原索引。成员自行创建的文档在提供链接后补关联，不要求再上传实验资料。
- 接线、设置、截图、数据、代码和结果继续在主记录中填写；索引只负责定位和关联，不自动复制正文，不删改既有测试、维修内容。按设备反查实验时沿同一关联读取原文档。
- 拟用设备不写成实际参与设备。同型号实物不明确时标为待核实；更换模块时在主记录记下变化，索引保留之前和本次实际参与的实物。
- 关联不扩大文档及附件权限。飞书不可达或索引受阻时，本地记录照常续写，并报告待补关联项；恢复后先查重再补，不另建同步正文或定时任务。纯仿真等无实际设备参与的记录不强行关联设备。

## 飞书主记录

- 在线文档用 `lark-doc`，原生 Markdown 文件用 `lark-markdown`；读当前正文及版本后再更新，保留人工新增内容和附件引用。联网按 `web-access` 处理。
- Docx 优先指定刚读取的基准 revision 和 block 局部追加或修改；版本冲突时重读核对，不能将旧草稿改用最新版本号强行覆盖。每轮写后读回，后续使用新的 block ID。
- 原生 Markdown 的 `+patch` 是完整下载后替换、再整文件覆盖，不是原子更新。发现远端变更先合并；无法安全排除并发覆盖时，保留待追加片段并说明冲突，不覆盖主记录。请求结果不明确时先读回，避免重复追加。
- 本地代码、数据和飞书记录互相引用即可，不自动同步两份正文。设备资料查询和阶段共享交给 `lab-resources`；共享时检查必要文件能否由获授权者从云端取得。

## 每条记录

已有操作单时就地回填；没有对应步骤的日志条目，用时间和本次关键变化作标题，按实际需要分点写：

- **操作与条件**：实际改了什么、测了什么，以及影响结果或复现的参数、单位、配置或代码版本。
- **结果与产物**：关键数值、统计口径、样本范围或失败现象，并链接实际数据、配置、日志或图件。
- **判断与后续**：结果支持什么判断、还有什么未确定；确有后续动作时再写。

这些是日志内容提示，不是必填栏目；普通日志空项省略，能合并说清就合并。操作单中已约定的空白填写区保留。观察结果与推测分开，仿真、离线回放和硬件实测分别注明。

## 控制篇幅

- 只记新增信息，不反复写背景、总目标、完整路径清单或已有结论。没有新结果或重要变化时不追加流水账。
- 连续的小改动或重复尝试可合并，保留关键条件、结果差异和最终处理；不同结论、异常或不利结果不能合并掉。
- 完整命令、参数配置和原始日志已有文件时，引用可定位的文件或运行编号，不整段粘贴。没有相应记录时补上必要的命令和条件，避免复现信息缺失。
- 图件默认给文件链接和简短说明；需要直观看到差异时才嵌入关键图片。同一产物的路径、图片和说明不在多个栏目重复。
- 普通调参简短记录；异常、方案转向和重要结论按需展开。不设机械字数上限，不为缩短文字删除关键条件。

## 边界

- 仪器操作、读回验证和异常收尾由 `link-test` 或项目程序负责，本技能负责方案讨论、推进协调与主记录。仅准备方案或整理已有实验、仿真或分析记录时，不触发实际仪器操作，也不连接仪器。
- 只记录实际动作和已有材料支持的结果，保留失败、未完成和暂时判断。
- 本地或飞书主记录用于阅读和接力，复用既有运行日志与配置，不代替或删改原始数据、机器记录。
- 周报、跨项目复盘和汇报按用户另行提出的请求处理。需要 Word 时交给 [docx](../docx/SKILL.md)。
- 维护本技能时优先精简现有说明和模板，不另建记录状态机或默认增加自动化。
