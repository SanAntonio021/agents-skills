# FPGA RTL 设计与功能验证

本技能负责逻辑行为与接口契约，优先复用现有工程模块及测试。工具运行、器件资源映射与物理时序验收分别交给相关技能，避免把仿真通过当作硬件或时序通过。

## 工作方式

1. 读取项目 README、AGENTS、相关 RTL、接口定义和现有测试。确定端口、时钟复位、数据单位、位宽符号、吞吐率、延迟及合法输入；不根据文件名猜测当前实际连线。
2. 按用户要求区分设计讨论、只读审查、代码修改和执行验证。不能把“任意一个入口可用”自行解释为并行写入、自动切换或带宽叠加。关键行为无法查明时先列差异并询问，独立部分继续。
3. 画清或描述模块边界和数据、控制流，按下表加载本次需要的参考。保留已有接口、时序与复位语义；必要的接口变化先说明影响并遵守任务授权。
4. 在获准范围内实施最小修改。时序逻辑使用非阻塞赋值，组合逻辑完整赋值，检查隐式锁存、多驱动、截断、符号扩展和非法参数；不能为性能推测无依据地增加流水级或改变包语义。
5. 基于接口契约设计独立期望模型与自检，按需运行仿真。缺少执行环境时交付可复现测试及未验证项，不伪造通过；现有测试足以覆盖时直接复用。

## 必须保持的行为边界

有效数据在背压期间保持，数据和旁带作为同一传输单元；不能用宽泛时序例外代替正确的 CDC 电路，也不能把相关总线逐位打拍当作一致性保证。仿真验收必须检查实际测试结果，单独的工具退出码不构成通过证据。

只生成代码或审查不自动运行综合实现；不得因加载本技能连接硬件或烧写。遵守已有项目范围，不在公共技能中写入本机路径、地址、固定器件参数或实验数据。本技能不自动派发其他代理。
