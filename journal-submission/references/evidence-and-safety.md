# 证据与安全规则

## 证据记录

每个易变规则保存：

```text
url
accessed_on: YYYY-MM-DD
key_requirement: 完成当前操作所需的短摘要
applies_to: 期刊 / 文章类型 / 生命周期阶段 / 页面 / 租户
```

页面需要登录时，只记录稳定 URL 或页面名称，不保存 session 参数、cookie、token 或临时签名链接。

## 冲突处理

1. 当前页面与目标期刊指南不一致：暂停当前字段，记录两处原文和影响。
2. 出版商通用规则与目标期刊指南不一致：目标期刊指南优先，但先核对版本和文章类型。
3. 项目旧记录与当前官方页面不一致：保留历史；当前操作使用当前官方页面。
4. 社区经验与官方来源不一致：忽略社区规则。
5. Wiley Research Exchange 文档与 IEEE Atypon 租户页面不一致：视为不同租户，不跨租户推断。

## 最终提交审查门

可以在 `pre_submission_review` 前准备文件和填写普通字段。最终 Submit 或返修 Submit 前必须满足：

- 审查门状态为 `pass`；
- `checked_at` 存在；
- `evidence` 非空并能定位审查报告或具体检查结果；
- 审查后发生的正文、参考文献或正式图件变化已重新评估。

任何一项不满足，停止在最终提交动作前。

## 必须由用户确认和操作

- 最终 Submit、Complete、Approve、Confirm 或同义最终动作；
- 作者增删、顺序、通信作者、投稿联系人和贡献角色；
- 推荐或回避审稿人；
- 伦理、利益冲突、数据、代码和重复投稿声明；
- OA、APC、版面费、超页费、彩色印刷费和付款责任；
- 版权许可、出版协议和第三方材料许可；
- 撤稿、转投或稿件转移。

确认后仍需回读页面值。回读失败时不记为完成。

## 凭据与身份

- 允许：浏览器现有登录会话、密码管理器自动填充。
- 禁止：读取密码框、导出 cookie、保存 token、让用户在聊天发送密码。
- CAPTCHA 和 2FA 由用户完成。
- 测试只用合成作者、机构、邮箱和稿号。

## 文件安全与新鲜度

- 上传前记录路径、用途、大小和 SHA-256。
- 编译、压缩和逐页目检只对当时的输入快照有效。
- 任一输入在上传文件生成后变化，相关 PDF、source 包和页面 preview/proof 结论失效。
- 无输入快照时，`freshness_status` 只能为 `unknown`。
- 页面不要求 source 包时不生成；页面不要求 proof/preview 时不伪造检查。
- 提交确认后，已上传文件成为不可变基线。本地新版本另记漂移，不静默替换。
