# 会议纪要处理流程

## 1. 合并材料

把同一场会议的 `.txt`、`.md`、`.vtt`、`.srt` 或文档转写按时间合并。记录分片来源，避免把两场会议混在一起。

## 2. 建立内部记录

逐项记录：

| 项目 | 最低证据 |
|---|---|
| 事实 | 转写中的明确陈述；必要时注明发言人 |
| 观点 | 谁提出、针对什么 |
| 异议 | 谁不同意，分歧在哪里 |
| 决定 | 有明确形成决定的表述 |
| 未决问题 | 仍缺什么数据、比较或定义 |
| 任务 | 执行动作 + 执行方 |

时间、条件和负责人只按原文填写。听不清或转写冲突时标为待核对，不猜。

## 3. 整理与复核

按[技能入口](../SKILL.md)的事实边界、结构、整理方法和完成条件处理；跨会议核对只使用本次指定材料。去重时保留新增条件、依据、反例或结论，不用“再次强调”“反复指出”保留无信息重复。

标题写实际议题，例如“射频链路的带宽限制”“两种时钟方案的分歧”。用户指定模板时保留模板；必须保留的空栏目使用模板允许的空值，不补造句子。检查每段是否推进议题，避免按转写顺序复述整场会议。

## 4. 交付

沿用入口选择对话、本地文件、飞书主稿或 Word。没有保存要求或指定主稿时，不因使用 Markdown 就生成本地文件；已授权写入时读取当前主稿、保留用户修改并核对实际结果。

用户的补充笔记按已明确的归属并入并注明来源；与原转写存在实质冲突时，保留来源并询问相关决定或任务，不把所有补充一律送去确认。用户要求 Word 且没有先审阅或分步确认的限制时，使用本轮整理和审校后的正文交给 `docx`，不另设正文确认步骤，也不在转换时重新概括。必要内容仍待澄清时继续其他已明确部分，导出受影响部分的限制如实说明。
