# 论文用词与术语契约

## 数据位置

- 中文文风：`D:\BaiduSyncdisk\.agents\vocab\中文\通用.md` 与对应任务表
- 英文文风：`D:\BaiduSyncdisk\.agents\vocab\英文\通用.md` 与对应任务表
- 全局术语：`D:\BaiduSyncdisk\.agents\vocab\术语.md`
- 候选、弃用项、检查补充和变更记录：`D:\BaiduSyncdisk\.agents\vocab\维护.md`
- 项目术语：当前项目内的 `术语.md`（如有）

## 固定结构

文风表只允许三列：

```markdown
| 不建议 | 建议 | 例外 |
|---|---|---|
```

术语表只允许两列：

```markdown
| 中文 | 英文 |
|---|---|
```

维护表固定包含“待确认、不采用、检查补充、变更记录”四节。普通写作不读取维护表。

## 论文加载

- 中文论文：`中文/通用.md` + `中文/论文.md`。
- 英文论文：`英文/通用.md` + `英文/论文.md`。
- 审稿回复改用对应语言的“审稿回复”表。
- 同一“不建议”发生重叠时，任务表覆盖通用表。
- 需要统一术语时再读全局 `术语.md`；项目 `术语.md` 覆盖同名全局术语。

## 收录与冲突

用户明确确认的文风规则直接写入对应正式表。普通字面匹配不另存；词形变化和非字面结构写入 `维护.md` 的“检查补充”，且“条目”必须与正式表的“不建议”完全一致。

术语只保存中文和英文。新增候选、互相冲突的译法和不采用项进入 `维护.md`；确认后再写入全局或项目术语表。外部来源、判断过程和历史变体需要保留时写入“变更记录”，不增加日常术语表的列。

## 独立复扫

每次写入或交付论文稿后运行 `scripts/audit_writing_memory.py`。报告包含输入文件、实际加载规则文件和 SHA-256：

- `clean` / 0：没有命中。
- `review_required` / 1：有命中，结合上下文和例外人工判断。
- `error` / 2：输入或规则无效。

检查程序不修改正文，也不检查专业术语。术语一致性由全局和项目 `术语.md` 单独核对。
