# 本地文稿版本保护

修改 `.md`、`.tex` 及必要源文件前，读取当前内容与已有改动。保护用户手工修改，不把历史快照视为最新主稿。

多人或并行对话修改同一文稿时，生成改稿前重新读取目标文件并计算 SHA-256，实际写入前再次核对文件哈希与本轮读取时一致。README、历史哈希和旧候选稿只作为定位线索；发生变化时先读取并比较当前文件，在当前稿上合入仍适用的局部修改，不用旧候选覆盖。结构方案曾反转时，先核实当前唯一基线及其自包含要求，不能让历史方案回写当前稿。

- 有合适的项目 Git 时，按项目规则只处理本轮准确文件。保留无关暂存、未提交和未跟踪内容，不执行整仓重置或自动收口其他分支。
- Git 缺失、项目根过大、误初始化了公共父目录或仓库环境不适用时，只停止该 Git 操作。采用本轮新副本或已有备份继续写作，不为普通文稿默认初始化仓库，也不要求用户先修仓库才能拿到结果。
- 目标已有改动时先保留可恢复副本；不把原有改动伪装成本轮贡献。只有当前请求或项目约定要求版本记录时才提交；无法分离改动时交付文件并说明提交范围限制。
- 验证当前 diff、事实、公式、引用及必要编译。验证失败继续修复；确需停下时保留文件与已有证据，不另设 WIP 批准关口。
- 缓存、大型派生产物和无关文件不自动入库。不默认增加忽略规则、远程仓库、上传、里程碑 tag 或维护记录。
- 用户要求恢复旧版本时先确定目标版本和文件，保留当前内容，再只恢复该范围；已有准确授权无需重复询问。使用可撤销的恢复提交，不强制改写历史。

`.git` 不进入双向同步。发现该风险时暂停 Git 写入，继续可安全完成的文件工作。
