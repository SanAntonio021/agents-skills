# 原文保留编辑

只用于用户要求原文逐字不动、本轮仅在开头加标题或末尾追加给定文字的任务。标题由用户给定，或先在用户允许的范围内拟定；追加原句不改写。替换既有标题、段内插入、分段、摘要和润色不属于此工具的操作。

## 处理

1. 读取当前原文，明确要新增的标题或原句。原文未涉及的文字不重新生成，也不按词表改字。
2. 本地 UTF-8 Markdown 或纯文本使用 [exact_edit.py](../scripts/exact_edit.py)，以源文件实际字节的 SHA-256 固定本次读取版本，输出到不存在的新路径。已有文稿版本保护仍适用；这不是覆盖主稿的许可。
3. 工具从原文字节构造结果，只补连接处缺少的换行。保留原文 BOM、空格、公式、行序和已有换行；标题需包含 Markdown 标记，如 `## 标题`。默认只接一个换行，不擅加空段或末尾换行。
4. 交付工具生成并回读的结果，不在展示或写回时再润色。用户只要正文时，不附校验结果或“已保持原样”的说明。

## 调用

在已确认的源文件路径上计算 SHA-256，再调用：

```text
python exact_edit.py apply --source SOURCE --source-sha256 SHA256 --title "## 标题" --output NEW_OUTPUT
python exact_edit.py apply --source SOURCE --source-sha256 SHA256 --append "用户给定原句" --output NEW_OUTPUT
python exact_edit.py verify --source SOURCE --source-sha256 SHA256 --title "## 标题" --candidate CANDIDATE
```

`verify` 的操作参数须与生成时相同；可同时指定 `--title` 和 `--append`。它比较整个候选与确定的拼接结果，不能靠“包含原文”放过额外说明。校验失败时不交付候选，回到原文重新拼接；源文件已变化时重新读取，不沿用旧版本。

只有聊天文字时，可在内存中调用 `edit_bytes` / `validate_bytes`，无需为校验新建文件。对话展示可保留常规标题间距，但不能因此忽略正文内部的空格或换行变化；文件交付以工具生成的字节为准。

## 限制

- 只处理 UTF-8 文本，不直接处理 DOCX、PDF 或其他编码；不得为使用此工具擅自转换原稿。
- 输入和输出的路径组件不能是符号链接或 Windows 重解析点，输出目录须已存在。已有目标不覆盖；源内容与摘要不符时停止该次写入。
- 文件检查防止常见误写，不是对抗其他进程并发换文件的安全隔离。写入中断可能留下不完整的新文件，不能当成已交付成果。
- 此校验只证明指定拼接没有改动原文，不证明原文事实正确或文风合格，也不扩大本轮修改范围。
