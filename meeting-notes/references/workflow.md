# 会议纪要处理流程

## 1. 合并材料

把同一场会议的 `.txt`、`.md`、`.vtt`、`.srt` 或文档转写按时间合并。记录分片来源，避免把两场会议混在一起。

## 2. 建立内部记录

逐项记录：

| 项目 | 最低证据 |
|---|---|
| 事实 | 转写中的明确陈述；必要时注明发言人 |
| 观点 | 谁提出、针对什么 |
| 异议 | 谁不同意，分歧在哪里 |
| 决定 | 有明确形成决定的表述 |
| 未决问题 | 仍缺什么数据、比较或定义 |
| 任务 | 执行动作 + 执行方 |

时间、条件和负责人只按原文填写。听不清或转写冲突时标为待核对，不猜。

## 3. 合并重复

同一人或多人重复同一观点时，检查是否增加了条件、证据、反例或结论。没有增量就合并；有实质差别就保留差别。不要用“再次强调”“反复指出”保存无信息重复。

## 4. 选择模式和标题

- `discussion`：围绕议题、观点、依据、分歧和未决问题组织。
- `action`：围绕决定、任务、执行方和原文明确的时间组织。
- `mixed`：先写影响决定的讨论，再写已明确任务。

标题写实际议题，例如“射频链路的带宽限制”“两种时钟方案的分歧”。内容不存在就不设栏目。用户指定模板时保留模板，但空栏目不补造句子；若模板必须保留空栏，使用模板允许的空值，不写假结论。

## 5. 输出前复核

- 个人观点没有变成会议共识；
- 建议和资料缺口没有变成已分配任务；
- 任务同时有动作和执行方；
- 决定、条件、时间和状态没有升级；
- 每个段落都推进议题，没有转写顺序式复述；
- 删除内容只包括寒暄、噪声和无信息重复。

## 6. 交付

默认保存 Markdown。用户的补充笔记可以直接并入并注明来源；只有补充会改变决定或任务时才单独列出待确认项。Word 导出在正文确认后交给 `docx`，不在转换时重新概括。
