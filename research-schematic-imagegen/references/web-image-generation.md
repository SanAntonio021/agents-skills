# 网页生图与同一会话编辑

网页路径用于用户已经对准确站点作出单独授权、但本地注册渠道或兼容接口不适用的情况。它不是 API 失败后的自动换路，也不改变 pinned 渠道的失败关闭规则。

## 授权边界

- 用户在原请求中直接点名站点，视为已授权该准确站点。
- 用户只说“换个能生图的网站”时，先说明准备使用的站点；得到确认后才提交提示词。
- 登录、账号选择、验证码、订阅或付款仍按 `web-access` 的接管和确认规则处理。
- 换到第二个网站、重新生成或追加一张候选，都是新的生成动作，需要新的明确授权。

## 单次提交合同

1. 提交前保存最终提示词、目标尺寸、图像数量和禁止项。
2. 每项已授权的生成或编辑只触发一次提交；点击成功、页面出现进度或会话中出现生成任务后，都视为已经提交。
3. 等待页面给出完成、明确失败或可核实的终态。不要用固定等待时长把“仍在处理”写成失败。
4. 页面停在 99%、连接中断或工具返回不确定结果时，重新打开或刷新同一会话，先检查任务卡片、成品图和错误提示。
5. 只有同一会话已经明确显示失败且用户重新授权时，才允许再次提交。刷新、恢复会话和读取现有结果不算新的生成动作。

## 保留后续编辑上下文

用户要求先确认底图、再在同一张图上编辑时：

- 在首次生成后停止追加操作，只展示当前候选。
- 保留原会话和包含该图的页面；结束浏览器 task 时使用 `keep:true`，不要关闭或另开会话重建背景。
- 在项目记录中写明站点、会话是否保留、当前停止点和仍未授权的编辑内容，不记录账号、会话令牌或私密 URL 参数。
- 用户确认后，从原会话中的原图发起一次高保真编辑；若原会话已经不可恢复，先说明这一变化，不能假装仍是同图编辑。

## 结果提取与来源标注

结果提取按以下优先级执行：

1. 能直接取得服务器返回的图片文件时，保存文件字节，并记录实际尺寸、格式和哈希。
2. 外部直链因登录态被拒，但页面已经加载完整图片时，使用 `web-access` 的自然尺寸媒体提取流程。
3. 只有视觉状态本身重要、或用户不需要源分辨率时才使用页面截图；截图不能冒充生成图原件。

浏览器画布导出会重新编码像素。此类文件在 `working/raw/` 中可作为“未经裁切的浏览器像素导出图”保留，但记录必须同时说明：

- 它保留的是页面已解码像素，不是服务器原始文件字节。
- 导出前后的自然宽高、输出格式、文件大小和 SHA-256。
- 为满足目标画幅所做的裁切、缩放或格式转换，以及对应候选文件。

## 最小记录字段

`record.md` 至少记录：准确站点、授权时间点、提交次数、同一会话核验结果、会话保留状态、提取方式、服务器字节或浏览器像素的来源分类、原始尺寸、候选处理和当前停止点。
