# 实验数据接收

跨机分析时，用项目已有的接收器取本轮材料。接收器独立在后台运行。本页供助手操作，实验正文只记影响结果的事项。

## 定位与检查

1. 从项目 README 和批次路径找到项目根目录。查看 `config/data_receive.json` 中的 `receiver`，用 `local_config_env` 指定的环境变量或 `local_config` 路径找到本机配置。核对获准的数据来源和映射。找不到其中任一配置时，直接使用已有数据、附件或共享位置。配置损坏、程序缺失时报告具体问题。
2. 用本机已有的 Python 在项目根目录查询批次。例如，`python scripts/data_receive/receiver.py --config config/data_receive.json status --batch analysis/ID`。把示例批次换成实际的 `analysis/ID` 或 `measurement/ID`，将各参数分开传递。表中的 `once`、`redownload` 替换同一条命令里的 `status`。
3. 看返回的状态和缺项，实际打开本机文件。核对校验结果、冲突，以及 `run_info.json` 中的运行结束状态、文件清单和外部参考。接收器未检查的依赖按项目配置查找。实验室电脑上的绝对路径须在接续电脑上另行定位。

## 按状态处理

| 批次状态 | 怎么做 |
|---|---|
| 所需文件已核验、无冲突，参考可用 | 用该版本分析，保留批次引用。 |
| 缺少尚未接收的文件，或需检查云端批次 | 已获接收授权时，对该批次运行 `once`，再查 `status` 并核对文件。 |
| 先前已接收，后来在本机删除 | 保留删除记录，说明缺哪个文件。用户明确要求重新下载后，用 `redownload` 恢复。 |
| 本地修改与云端新版冲突 | 保留两份，说明哪些分析会受版本影响。需要选择时请用户指定。 |
| 文件仍在变化、待校验，或缺外部参考 | 写清具体缺项，先做材料齐全的部分。 |
| 接收暂停、鉴权失效、空间不足或状态库异常 | 停止重试，报告当前状态和项目已有的处理入口。不得自行解除暂停、清理文件或重建状态库。 |

失败或取消的实验也保留记录，按同样的规则接收材料。没有完整运行清单时，只能确认云端当前可见的文件已接收。实验是否成功，根据实验结果判断。

## 写回与边界

把分析结果填回对应步骤，引用实际文件和版本。会影响解释或后续操作的冲突与缺项写入主稿，正常接收过程留在程序日志。单纯整理仿真记录时，一句结果加数据引用即可。

只从批准的来源接收目标批次。不得扫描其他备份、改动云端来源、上传或删除云端文件。补记录不包括安装接收器、创建定时任务或连接仪器。共享说明用项目相对路径，机器路径和凭据留在本机。
