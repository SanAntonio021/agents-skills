# 操作细节与边界

## 文字起图

场景直接沿用上游 `version/page/nodes/edges/assets`，坐标默认英寸、左上角原点。`metadata` 可记录 `authoring_source: "confirmed_discussion"`、`caption`、`pending_questions` 和简短的确认依据；这些字段不改变渲染。技术依据留在场景所处项目，不把私有文件路径带入公开模板。

节点与连线的 ID 是连续修订的定位依据。每个端口用边界锚点和独立文字节点表达，例如 `mixer:left@0.50` 配合标签 `LO`，不创建无效的自定义端口字段。需要保留双向关系时使用两条明确方向的路径或已确认的双端箭头，不用交叉点猜测连接。

同版本正式源由场景、Visio 和 PNG 组成。用户在 Visio 手改后，先把变化回写场景；下一轮生成的是新文档，不能自动保留旧 Visio 对象 ID、手工布局、主题、宏或批注。上游连线以可编辑线段/路径绘制，不保证移动模块时自动粘连重排。

## 预检与渲染

`check` 运行上游结构校验、文本及栅格审计并检查可见文字字体。本地模板用英文内部 ID，显示文字用中文。字号使用节点 `style.font_size_pt`；明确不缩字时设置 `text_fit: "none"`。连线旁的中文标签优先用独立 `text_block`，这样字体、字号、位置和局部修改均可直接检查。

`render` 使用独立 Visio 实例和本机已安装字体，将相对素材路径按场景所在目录解析。导出缺失、空文件、PNG 损坏、字体替代、文本高度超框均报错；失败留下实际已产生文件和可选检查报告，修复后使用新版本名重试。报告会包含本机路径，仅存过程目录。缺 Microsoft Visio、pywin32 或正确授权时如实停止导出，不用整图贴入伪造原生图。

`compare` 要求同时提供前后场景与 PNG，以稳定 ID 检查改动范围，再调用上游 `round_noop_gate.py`。改动集合须覆盖实际联动对象；metadata 改动会记录，但不能单独证明图变了。页面调整用 `--allow-page` 显式声明。新增或删除对象也需其 ID 列入本轮集合。

上游 no-op 分类器未识别节点样式中的嵌套 `style.font_size_pt`。本地仅在场景差异全部为既有节点字号、页面像素尺寸不变且 PNG 像素差异非空时作窄范围放行；其他未知字段仍按上游门禁失败处理。

## 看图和正文衔接

程序检查后，查看真实导出 PNG 的整页和拥挤局部，按确认清单检查模块、物理端口、方向、虚实线和文字。需要核对字体时可用 ZIP/XML 读取 `.vsdx` 的字符行，或通过独立 Visio 实例只读打开。不要隐藏真实的未确认内容。

专利项目确认图件后，由 `docx` 等现有文档工具更新嵌入图与图源链接；本技能不直接改 Word 正文。更新后检查 Markdown 链接、Word 嵌入图片和正式图件哈希对应。图号和图名保留在文档图注。

## 图片复刻

原有图片复刻能力仍可使用。按 [上游工作流](../vendor/upstream/SKILL.md) 和 [审查契约](../vendor/upstream/references/review-contract.md) 获取本地原图、记录可见结构并执行对应严格校验。上游文档中的作者本机解释器路径不适用于本机；使用当前 Python，本地渲染统一走本技能后台入口。没有图片的文字起图不套用“像素复刻”审查，也不虚构 source_image 或原图相似度。
