# 设备与实验资料

让实验方案有实际设备和原始资料可查，让后续成员能沿记录找到复现材料。资料保存在用户的库与项目中，技能只保存方法，不收录真实设备、飞书坐标、用户身份或本机私有路径。

## 先定位，再操作

1. 读取当前对话、项目说明和用户指定的设备或实验链接，明确是查询、整理提交、续写记录还是共享资料。沿用已有库和主记录，不另建一套台账。
2. 从启动环境已展开的用户主目录读取 `.agent-rules/local.md`，按其中“规则维护目录”定位 `docs/lab-resources/library.json`；实际访问前验证路径。定位约定见 [资料定位与更新](references/library-workflow.md)。用户明确指定的库优先于默认定位。
3. 本机配置或定位文件缺失时，说明需要用户指定资料库链接；不要猜用户目录、搜索全部个人文件或自动创建替代库。独立的本地记录工作仍可继续。
4. 按当前任务只读取必要的表、字段与记录。调用前核对当前库结构与私有字段映射；使用稳定记录 ID 和字段 ID，不把设备简称、型号名或字段显示名当唯一主键。联网不可用时说明资料未刷新，不把旧缓存当作当前状态。
5. 按资源使用已有技能：多维表格用 `lark-base`，在线文档用 `lark-doc`，飞书原生 Markdown 用 `lark-markdown`，文件及权限用 `lark-drive`，手册按文件类型使用 `pdf` 等阅读技能。联网遵循 `web-access`；只有认证问题才进入相应身份处理流程，不自行切换操作者。

## 资料归属与证据

| 对象 | 保存内容 | 不能混入的内容 |
|---|---|---|
| 物料与型号 | 可共用的手册、规格、接口、通用说明 | 某台设备独有选件、某次实验实测结果 |
| 设备与器件 | 具体实物、已装选件、接口配置、位置状态、已知问题 | 把选配能力写成所有同型号设备都具备 |
| 测试与维护 | 实验主记录链接或路径、所属项目、实际参与的具体实物等索引 | 自动复制接线、设置、结果等实验正文；把历史接线当作当前现场接线 |
| 资料提交 | 设备手册、规格书、厂家说明的原始附件或链接、对应设备、可选项目、补充说明、处理情况 | 要求成员重复提交实验文档内的数据、截图、代码；用 AI 摘要替换原始提交 |

- 新设备沿用现有登记入口；“补充设备资料”仅收手册、规格书、厂家说明等，所属项目仅用于项目专用设备资料。实验直接新建或续写主记录，不另走资料上传入口。历史提交、字段、选项及附件保留。
- 补交资料和实验索引只关联已有设备。多个同型号实物分别保留配置，型号或具体实物不明时列为待核实，不猜配对。
- 提交入口使用编号或链接代替关联选择时，保留提交者原始填写，再解析到已有设备或项目的唯一记录 ID；重名、缺号或链接无权限时列为待核实，不直接新建或猜选。
- 每条技术结论带可访问的来源链接或附件标识、版本，以及页码、章节或文档块位置；单位、适用选件和条件一起保留。来源没有版本时注明未提供，不自造版本。
- 区分厂家额定指标、实物配置、实测结果和推断。相互矛盾的来源并列保留出处，说明适用条件或待核实点；不以新文件自动覆盖旧文件，也不替用户判定未经证实的规格。
- 只按原文确认接口方向、连接器、频率、功率、阻抗、供电、触发与时钟等与当前方案相关的限制。不能从外观或型号系列推定具体实物接口。

## 整理新增资料

用户按需发起后执行，不设置定时任务或常驻服务。

1. 读取新增、失败及源内容发生变化的提交；先核对项目归属和可见范围。附件、链接、备注或关联实物有变化，均视为可能需要重新整理。
2. 读取原件，按型号、实物拆分待补充内容；历史实验提交保留并按其主记录建立关联，不要求重新提交。在源记录保存处理版本、目标关联和结果，方法见 [更新流程](references/library-workflow.md)。不要为了处理状态另建数据库。
3. 对照已处理来源与目标内容，跳过同源同版本且读回确认过的内容；失败项仅续做未完成目标。重复执行不得重复创建型号、实物、实验或重复追加摘要。
4. 写前重读目标记录或文档，把变更合并到当前内容，只改本次负责的字段或片段。相关内容被他人改动时保留双方内容并列出差异，不覆盖；能独立完成的其他条目继续。
5. 按资源实际能力执行局部更新，完成一轮变更后统一读回核对，再记录处理完成。请求超时或返回不明确时先查询目标是否已生效，不能直接重试追加或建档。原始附件和人工内容保持可追溯。
6. 简短报告新增、更新、跳过、待核实和失败项，给出对应记录链接。写入已返回但尚未读回确认的结果，标为待验证。

## 查询设备与讨论实验

- 先查具体实物、选件、可用状态、手册和相关实验，再讨论组合、连接和关键设置。台账显示在库不代表已预约可用；状态记录有日期时说明其时效。
- 从实验索引查实际参与的模块；按具体设备记录 ID 反查“测试与维护”的设备关联，再读取有权限的实验原文档。不要另建反向实验台账，也不要把关联关系当成文档访问授权。
- 已验证接线注明对应实验、日期及配置。新的设备组合写明待验证条件；历史“成功”不能证明换选件、换线缆或换参数后同样成立。
- 输出以当前任务需要为限：可用组合、连接依据、关键限制及缺口。遇到缺失资料先指出具体缺项，避免要求用户重新口述全部设备。
- 资料查询和方案讨论不连接仪器、不启动输出、不运行测量程序。实际操作按用户授权进入 `link-test` 或项目程序。

## 实验主记录与共享

- 继续实验时交给 `lab-notebook`：主记录可在本地或飞书，沿用用户指定或已有主稿；不自动创建本地同步正文。多处资料只关联，主稿不明确且会影响写入时再询问。
- 新建或续写实验主记录时，默认查找并维护“测试与维护”的实验索引，保存主记录链接或路径、项目和实际参与的具体实物。成员自行创建的文档在提供链接后补关联，不要求重新上传正文或其中的文件，也不后台扫描所有文档。
- 用主文档稳定 token 或本地主记录准确绝对路径查重，同一主文档默认复用同一索引；写前重读，保留人工内容和现有测试、维修字段。接线、设置、截图、数据、代码和结果留在主记录，索引不自动复制正文。具体步骤见 [实验索引](references/library-workflow.md#实验索引与设备反查)。
- 只关联明确已实际参与的实物，拟用设备留在方案中。同型号实物无法区分时列为待核实；中途更换模块时在主记录记录变化，索引保留所有实际参与过的实物，不能用新模块覆盖历史参与列表。
- 飞书不可达或索引写入受阻时，继续可独立完成的本地主记录，说明待补关联的主记录与设备；恢复后先查重再补，不把待补项宣称为已完成。
- 飞书文档优先以最新读取的 block 和基准 revision 局部追加或修改；版本冲突后重读再判断。原生 Markdown 的 `+patch` 是下载、替换、整文件覆盖，不是原子 patch。发现并发修改或不能安全保留协作内容时停止该次覆盖，保留待追加内容供合并。
- 在用户指定节点和资料范围内整理共享：目的、参与设备及配置、接线、关键设置、步骤、必要代码及依赖、代表性数据、结果和限制。补齐原记录中缺少的复现条件，已有部分直接关联。
- 飞书主记录沿用原文档；本地项目按选定材料上传并关联。必要代码应有具体版本，必要数据和配置应能下载；仅有本地绝对路径或某人电脑上的文件不满足跨机复现。大批原始数据按需另行归档，不自动全量上传。
- 缺少必要材料时列出缺口，称为共享草稿或部分资料，不称为可复现。实质改写共享说明按 `writing-router` 的当前协作流程确认正文；原样导入和已授权的小幅补充沿用原流程。

## 可见范围与验收

- 新提交默认受限。公开厂家手册、公开规格及通用说明可按既定规则向团队共享；研究资料只对所属项目已获授权的人员开放，范围不明时保持受限。
- 新建云文档时先核对默认链接分享和直接协作者；不要假定新文档天然私有。研究正文写入前落实已授权范围，链接权限和附件访问分别读回验证。
- **关联项目不等于设置权限。** 分别核验记录与字段、AI 摘要、关联文档、附件及可下载文件的实际权限；视图筛选、隐藏字段或只有一个链接都不能当访问控制。受限研究结论不能被提取到团队可见的型号摘要中。
- 不改财务规则，不邀请新成员、不切换账号；扩大受众须有用户对资料集合和受众的授权。权限能力或配额不支持隔离时停止该部分共享，保留受限资料，不退回到全员公开。
- 从飞书链接实际取得至少一台设备和一项实验的必要材料，验证不依赖本机缓存的查询路径。记录实际操作者与访问证据；管理员可读不能证明普通成员可读，更不能证明未授权者不可读。
- 没有真实普通成员验证时，明确交付为管理员试用。技能结构检查、样例流程、实际飞书读写、运行副本生效和团队访问验收分别报告，不相互替代。
