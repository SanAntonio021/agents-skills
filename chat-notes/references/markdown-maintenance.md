# Markdown 文档维护规范

## 目的与适用范围

本规范用于整理、重构、合并或持续维护 Markdown 文档。它规定文档之间如何分工、归位、引用和验收，不替代 README、AGENTS、SKILL、实验记录、技术文档或版本记录各自的专业内容要求。

处理前先识别文档的职责、目标读者、主要维护位置和本轮范围。文档可以是项目入口、执行规则、专题说明、实验记录、验收记录、版本记录或其他明确载体；不因扩展名相同就套用同一模板、标题层级或列表格式。

## 组织原则

- 当前配置、用法、状态、限制、待办、证据和恢复信息分别放在最适合其职责的主要位置；入口只概括后续使用需要的内容，并链接详细记录。
- 同一事实只保留一个主要维护位置。其他文档需要时引用该位置并说明其用途，不复制一份可独立失效的正文。
- 引用使用读者可访问、可验证的路径或链接；写回后检查目标存在、相对位置正确、引用对象与文字所指一致。路径存在本身不等于证据已核验。
- 当前状态、历史事实、计划、实测、推测和待办分开表达。历史记录保留当时条件和结论，不改写成当前状态；当前入口不因追求完整而复制整段历史。
- 结构由信息关系决定。配置、待办、参数和并列事实可用列表或表格，背景、判断、限制和方法可用段落；不为形式整齐强行分类。

## 重复与历史

按“事实 + 章节功能 + 证据”判断重复：同一事实承担同一功能且没有新证据时合并或删除；摘要、结论、不同模板栏目或不同读者确有独立功能时压缩保留。不要只为避免重复而轮换术语或改变事实强度。

日期用于表示实验批次、版本、验收时间或历史索引，不作为每次修改的流水账。历史内容必须逐条判断，不能按日期、版本号、段落长度或“看起来旧”整体删除：

- 仍影响当前使用、兼容、排错、恢复、验收或责任判断的内容保留在原处，或归入能承接它的当前章节、专题记录或恢复材料，并更新引用；
- 已解决且没有上述后续用途的普通试错、重复说明和调试流水可以合并或删除；
- 准备删除的内容如果没有明确承接位置、唯一证据或恢复依据，先保留并标为待核实，不以新建一份冗余历史副本代替归位。

## 按文档职责验收

整理后先回读完整文档及受影响引用，再按该文档职责检查：

1. 目标读者能找到当前入口、使用方法、状态、限制和后续动作；
2. 该类文档应保留的参数、条件、批次、结果、版本差异、证据、恢复位置和未验证边界仍可定位；
3. 项目规则、安全文件、配置、回滚、恢复和证据等关键入口（适用时）没有因精简丢失；
4. 同一事实没有在多个位置继续独立维护，迁出内容有明确归属，引用目标存在且指向正确对象；
5. 删除没有改变数字、版本、因果、范围、状态或结论强度，也没有把历史事实改写成当前事实；
6. 继续修改只能产生同义替换或个人偏好变化时停止，不按字数、日期数量或固定压缩比例判断完成。

缺少原始材料、外部证据或目标文件不可达时，保留来源和未核验状态；不能把路径存在、模型返回或文件写入成功说成内容已经验证。
