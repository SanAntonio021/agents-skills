# 写作规则加载与执行复测

2026-09-07。本轮已完成对照、原文保留工具和实际输出检查。候选技能仍未通过写作效果验收；未提交、推送、分发或更换模型、上游。个人词表、私有样稿和真实文稿未修改。

## 结论

不能把效果不佳简单归为“没吸收上游”或“没加载技能”。这次同时观察到了不读后续规则、读全仍重复状态、以及明确要求逐字保留却改动标点三类问题。继续增加禁词不足以解决它们。

- 不加载写作技能时，两端的新摘要仍附带“现场标定尚未进行”，说明这类写法不完全由本地技能引入。
- Claude 的入口读取组六次都成功读了入口与词表，却没有继续读取适用参考文件。不能把这组六次称为“完整加载技能”。
- 完整提供规则和词表后，Claude 两次摘要只有一次不再重复状态，另一次还将“不超过50 ms”缩成“50 ms要求”；Codex 两次都仍附带标定状态。当前规则不能认为稳定奏效。
- 只加标题时，Claude 完整规则组仍有一次将原文中文逗号改为英文逗号。原文保留需要确定的拼接与校验，不能以模型自称未改为依据。
- 这批60份输出都没有附带改写说明。与此前测试相比，业务提示现已明确“工具返回只供内部检查”，因此不能把这一现象单独归功于技能。

## 对照设计

换用温度采集模块、单通道帧差错率和器材室通知三份合成材料，不使用真实研究稿或私有样稿。每个条件在新会话中重复两次，第二次反转题目顺序。

第一批36份是加载诊断：无技能、要求读取入口并沿引用加载、直接提供完整规则。发现 Claude 直接收到规则后没有另读词表，因此这批保留作诊断，不用于严格的规则收益结论。

第二批24份补测将相同词表完整放入两组提示，只比较“无写作技能”和“完整提供当前适用规则”。业务问题和工具配置相同，评分要求不出现在提示中。

| 第二批结果 | 无写作技能 | 完整提供规则 |
|---|---|---|
| Claude：摘要信息取舍合格 | 0/2 | 1/2 |
| Claude：只加标题，原文保持 | 2/2 | 1/2 |
| Claude：只追加原句，原文保持 | 2/2 | 2/2 |
| Codex：摘要信息取舍合格 | 0/2 | 0/2 |
| Codex：只加标题，原文保持 | 2/2 | 2/2 |
| Codex：只追加原句，原文保持 | 2/2 | 2/2 |

这是逐份检查的结果，不是总体成功率、稳定胜率或模型排名。每个格子只有两次。

## 怎样判定

- 摘要先判断结论是什么。本题结论只比较书面参数中的标称刷新间隔，已经限定该范围时，不再机械附上现场标定状态；如果任务问实际可用性，该限制仍须保留。不能将本题判定推广成删除所有未完成状态。
- 原文保持按整份响应比较。允许标题与正文间、追加句前后的正常换行，不忽略原文内部标点、空格、公式、数字、语序或限制句变化。追加原句与上句同段不判错。
- 实际读取以成功返回的完整文件正文为证，不以出现路径、调用次数或模型登记的 `loaded_refs` 为证。内联正文只证明规则已提供，不证明模型照做。
- 当前助手已通读全部60份最终正文，判断另存于 `reviewed-diagnostic.json` 与 `reviewed-controlled.json`，未改写模型原始输出。机械生成的示范结果不计入模型成绩。

## 原文保留工具

新增 [exact_edit.py](../../writing-router/scripts/exact_edit.py)，通过[窄范围说明](../../writing-router/references/exact-edit.md)接入共同质量规则。仅用于正文逐字不动、开头加标题或末尾追加给定原句；不接管摘要、润色、重构或 Word。

工具从源文件字节构造结果，检查源版本，只创建新文件，回读并逐字节比较。保留 BOM、正文空格、公式和行序，拒绝已有目标、源版本变化及链接路径。用户只要正文时，不输出校验说明。

已用本轮两份原文覆盖 LF/CRLF、有无 BOM 共8种组合，均保持源文件不动；句序改动、数值变化和附加解释共24项故意破坏全部被拒绝。见 [工具实测回执](proof-roef6970/receipt.json)。这证明工具的指定操作有效，不证明日常助手已经稳定调用它。

## 证据与限制

- [补测完整输出](review-controlled.html)：同题、同次的两份结果放在一起；无技能与完整规则有明确标签，不混用三轮选择。
- [加载诊断完整输出](review-diagnostic.html)：保留入口漏读与词表漏读的诊断材料。
- [补测收集记录](collection-controlled.json)：24份齐全，无失败或缺测；规则与词表的实际提供方式逐项记录。
- [诊断收集记录](collection-diagnostic.json)：36份齐全，保留并排除最初两次 Codex 启动失败；它们在 API 调用前失败，修正本次命令参数后新建尝试，未覆盖旧记录。
- 冻结的 `snapshot/` 未修改。新工具与接入说明没有混入前述模型对照；工具实测单独记录。
- Claude 使用安全模式和空扩展设置，Codex 关闭自动技能目录、记忆等入口，不续用旧会话；这是 CLI 文件上下文诊断，不是日常原生 Skill 触发验收。
- `automatic_context_isolated=true` 的原始字段只检查自动技能目录和指定用户上下文项，不能解释为“没有任何宿主规则”。Codex 的大多数运行仍读取了本机和共享规则。第二批摘要两组均如此；个别标题运行没有读取。因此不跨宿主作因果比较，也不声称完全剥离全部系统背景。
- 模型回执为 `claude-opus-5/max` 与 `gpt-5.6-sol/max`，沿用现有上游。这些名称不构成对供应商后台模型身份的独立鉴定；现有证据也不能判断更换上游或模型是必要条件。
