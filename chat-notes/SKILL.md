# 对话经验整理

从本轮对话和实际改动中找出下次仍有用的新信息，核实事实并检查相关现有说明，分清规则缺失还是执行时遗漏。能改变下次判断或行动的新信息才值得记录。

优先更新已有文件：项目事实留在项目说明，跨项目方法归负责该行为的已有 Skill。按内容选择正文、参考、模板、脚本或测试；只有需要留存的新信息确实无法写入现有文件时，才考虑新建。

已有清晰规则直接沿用；规则冲突或结构妨碍执行时，通过删改、合并解决。按实际变化检查并更新受影响的用法、配置、接口、名称路径、架构图和上下游说明。

本地依据不足，或外部方案会影响技能改进选择时，通过 `web-access` 查上游并比较可复用部分，保留来源并遵守许可要求；安装或替换需有对应授权。

具体改动尚未获准时，简短说明值得改哪里、原因和改法。已有明确授权就完成相应修改；修改 Skill 后使用 `skill-creator` 检查受影响的内容，并按[发布说明](references/skill-edit-followup.md)自动提交、推送和双端同步，除非用户明确限定只改本地。

## 清场

交付结束、整理和记录完成后，主动盘点本任务生成的文件，并在已有清理授权内完成清场，不等用户再次提醒。本轮没有新经验，也照常清场。按明确的保留清单处理，不再以“必要验证材料”或“以后可能复核”为由笼统保留中间产物：

- **保留已确认的当前或最终版本**，以及用户明确指定保留、专门用于对比的少数版本。确认状态和对比用途以用户决定及现有交付记录为准，不能仅凭文件名含 final、latest 或版本号最高就认定已确认，也不能自行把旧稿列为对比版本。
- **清除其余过程产物**：未确认稿、候选稿、失败稿、中间版本、已被替代的旧版本，以及生成过程中的测试副本、预览、临时截图、转换文件、临时脚本、缓存和重复报告。曾经确认过但已被替代的版本，也只在明确指定用于对比时保留。
- 已确认成果所必需的图片、可编辑源文件和运行依赖随该成果保留；正式维护的源码及测试不属于临时脚本。仅用于过程检查的截图、PDF、日志或检查副本，不因曾被过程记录引用就自动保留。先把实际结果和必要的错误摘要并入现有记录，再清除过程文件并修正相关引用；记录明确区分历史检查结果和仍可复用的文件检查。
- 清场范围是本任务生成且已获准处理的产物。用户提供的原始输入、引用资料、其他任务文件及归属不明的文件不因本规则被删除。核对实际路径与归属后执行，优先采用可恢复方式；不能把整批中间文件转移到新的归档目录就算清场完成。
- 清场后检查保留成果及其依赖仍完整、引用仍有效，简要报告清除了哪些材料、保留了哪些交付和指定对比版本。确有未完成的清理，说明具体原因，不能把未执行写成已完成。

用户要求整理目录或命名时，遵循项目现有习惯和依赖关系，调整后修复引用；涉及多目录合并或迁移时使用 `project-organizer`。

需要后续恢复的未完成事项或异常，在本次获准维护的现有记录中简要说明状态、影响和恢复依据，解决后更新原记录。只审阅时在回复中说明。
