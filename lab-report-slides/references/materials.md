# 资料与选材

本文件负责事实、选材和图文证据；页面写法见 [中文表达](chinese-style.md)，确认与授权见 [主流程](../SKILL.md)。

## 采集本期记录

### 本期起止与去重

日报先定位上一份**已交付且与本次同一汇报范围**的汇报，读取其统计截止时间、正文及已有候选取舍，再固定本次采集截止时间。范围只看某项目时，不用其他项目的汇报推进它的统计边界。

- 优先使用上次记录中的统计截止点；没有精确时间时，从最后一次汇报覆盖的日期起重叠采集该日，逐项对照上一稿去重，保留汇报之后新增的进展。文件修改时间只能辅助定位，用户后来改稿、重导出或失败候选不能单独改变边界。
- 时间窗覆盖全部间隔日。例如上次截止于周五，本次周二汇报，就盘点这段期间的工作，不只查周二，也不只补周一。找不到可信的上次边界时先检查已有汇报记录，仍无法判断才问一个范围问题，不静默退回“今天”。
- 对照上一稿区分“已经汇报”“本期新增”“上次遗漏或明确留待后续汇报”。旧稿只是未展开的总览项已经汇报过，不原样再算一次；有新进展时合并说明变化。之前已明确排除或跳过的事项保持原取舍，除非本期有新的汇报价值或用户改选。
- 在现有过程记录或 manifest 中保存上次汇报路径、实际起止时间、边界依据和未汇报事项；本次正式交付后，该截止点才成为下次的接续依据。盘点范围与首页日期显示分开处理。

日报按两遍完成盘点，避免把“采集到的摘要”误当成“两次汇报之间的工作全集”。第一遍扫描时间窗内全部会话与其引用的项目；第二遍依据已发现的项目，检查本地项目记录的本期更新，并定向检查相关飞书文档/任务的本期文字或更新摘要。检查飞书只为发现与确认工作条目，不打开图片、附件或完整数据；这些素材留到展开事项与素材确认阶段。用户指定项目、来源或排除范围优先。若飞书不可访问，明确记录该来源未检查，不据此断言无更新。

先建立完整的内部候选账目，至少记录项目/事项、为什么做（记录里已有的原因）、本期动作、状态（有结果、有交付、正在做或只有计划）、证据来源、初步汇报价值及建议去向（首页、展开、留记录）。逐条检查会话和本地记录中出现的实质工作，并将飞书新增事项并入；对同一项目的重复事件合并，但不能因为已有一项显眼工作、候选很多、摘要很短或首页空间有限而停止发现。之后才按首页准入筛选；向用户展示什么、怎么问，见[日报流程](../SKILL.md#1-日报流程)。

周报沿用用户确认的范围，范围不明时先询问，不自行盘点后决定讲什么。随附采集器只读取本地会话文件，不主动联网；飞书检查使用当前可用的飞书连接器或已配置 CLI，仅在用户授权范围及相关项目内定向查询。Windows 需安装 `tzdata`；从技能根目录运行：

```text
python scripts/collect_sessions.py --since "<上次统计截止时间或重叠采集起日>" --until "<本次统计截止时间>" --out "<project-root>/过程文件/<任务>/brief.json"
python scripts/collect_sessions.py --mode week --out "<project-root>/过程文件/<任务>/brief.json"
```

起止时间支持 ISO 日期或带时区时间戳；省略 `--until` 时取采集时刻，窗口为起点包含、终点不包含。只有用户明确要求当天或固定日期时才用 `--mode today --date YYYY-MM-DD`；`--since` 不与 `--date` 混用。

指定项目加 `--project-root <project>`，只取该项目及子目录，不混入名称前缀相似的其他项目。已知素材目录用可重复的 `--asset-root <directory>`，已知照片用 `--context-image <photo>`；先从项目记录定位，不要求用户每天重新指定。

默认读取：

- Codex：`%USERPROFILE%/.codex/sessions/**/rollout-*.jsonl`，以及 `session_index.jsonl` 在时间窗口内更新的归档条目。按 session ID 匹配归档文件，不对整个归档目录执行 stat。仅用户要求排除归档时用 `--no-include-archived`。
- Claude Code：`%USERPROFILE%/.claude/projects/**/*.jsonl`。
- Cursor：`%USERPROFILE%/.cursor/projects/*/agent-transcripts/**/*.jsonl`，每轮保留用户请求和最终回答。项目目录按对话所在的文件夹名还原；找不到唯一对应的目录时不猜测，`project` 保留文件夹名，这类对话不会被 `--project-root` 选中。

自定义位置用 `--codex-root`、`--claude-root`、`--cursor-root`，不扫描其他账号；不需要 Cursor 时写 `--cursor-root=`。

事件时间转换为 `Asia/Shanghai`，跨日会话按实际事件纳入。按 `root_id` 归并，子智能体记录作为辅助证据，不列成独立工作。

采集器保留用户消息及有用结果，过滤系统提示、hidden reasoning、token telemetry、命令回显和工具内部信息，并遮盖常见凭据。结果关键词只用于找候选，不能替代科研价值判断。不要打印原始会话或放入 PPT；采集摘要只用于当前任务，不提交公开仓库。

采集为空时检查可读性和来源范围，再使用用户提供的记录与图件，不据此判断当天没有科研工作。

## 核实事实与状态

日报在展示第一页草稿前做一次首页事实级核实：核对拟入首页的每项工作属于哪个项目、为什么做、本期做了什么、得到的结果或交付，以及支持它的记录或产物。“为什么做”从本期记录和该项目已有的记录里找，只取其中已有的具体问题、要求或前序发现，不把泛泛背景当作原因，也不从常识推断；项目归属或原因查不到时，按[第一页怎么写](chinese-style.md#第一页怎么写)的“项目或原因查不到时”处理。只查使用首页文字所需的本地记录与产物，不延伸到图片搜索、飞书素材和完整数据复核。用户口头补充可说明工作存在；准备放入首页时，仍核对其涉及的本地状态和产物，不额外索要文件证明。

会话说明与项目记录、实际产物交叉核对，后续可靠证据和用户更正优先，删除已解决问题。有结果的工作按实际结果写；还在做的按正在做写，不写成结果；只有计划、还没动手的不算本期工作。下一步须为用户或项目记录已确定的安排。

区分方案、仿真、离线验证、原型和实测；软件通过不等于硬件通过，计划不等于结果。旧数据可用于本期分析，但采集与分析时期分别表达，不从文件时间或常识推断事实。核对具体参数的方法见逐页核对表，必要信息的取舍见中文表达参考。

## 首页准入

日报首页写本期实际做了、值得导师知道的科研和项目工作。下面三类都可以上首页：

- **有结果的**：确定了哪个方案、验证了什么现象、比较出什么差异、得到什么判断。
- **有交付的**：形成了可继续使用的正文、材料清单、核查结论或实验能力，包括帮老师写的申报书正文、资料检索和整理结果。
- **正在做的**：已经动手、有实质内容但还没做完的工作，例如正在制定的实验方案、正在逐条修改的审稿回复。

下面两类不上首页：

- **只有计划、还没动手的事**：列入“未放入首页”，用一句话说明目前只有计划。
- **纯操作**：排版、截图、入库整理、按钮修复、账号和一般软件排障，不进入首页，也不进入“未放入首页”。

“未放入首页”只列有汇报价值但没上首页的工作。首页文字怎么写见[第一页怎么写](chinese-style.md#第一页怎么写)。

## 决定讲什么、讲到什么程度

优先汇报有证据的结果或技术判断、研究问题与方法的实质推进、关键障碍，以及有科研价值的交付或实验能力。论文明确研究贡献、方案确定物理关系、程序实现新的实验能力，都可按实际状态纳入，不要求先有定量结果。

常规改字、格式、编译、保存重绘和检查次数通常简述或留记录。账号、代理、磁盘、一般软件排障和技能维护排除在候选、正文及附录之外；行政事项须代表科研或项目里程碑。实验代码按科研作用判断，不一概排除，也不罗列按钮和接口。

完整盘点入选工作，按科研问题归并重复运行。在已有过程记录中保留“工作、本期推进、来源、取舍及理由”，确定页面后补页码：

- **展开**：有总览之外值得解释或讨论的内容，并有材料支持。
- **总览简述**：值得交代进度，但无需展开，或用户指定简述。
- **留记录**：重复材料、内部执行检查及无关事项，保留原始依据。

已确认必须讲的内容不能遗漏，但盘点不等于全部展示；不按会话、图片、产物数量或固定每项目页数安排。仅在理解本期工作需要时回溯具体问题、需求或前序发现；关键前因缺失且影响理解时只问一个问题，其他工作继续，不强制追问动机或猜测原因。

## 复用与核对素材

展开事项确认后，补齐首页核实未覆盖的事实，并集中完成入选工作的素材核实。先查实验记录、会话引用及已有分析，再按项目定向补充结果图、实物照片、系统图和适用的历史对照。特别查找相关飞书文档中的测试照片、结果图和系统框图；飞书正文、表格和画板用对应技能实际读取，PPT/PDF 图件用相应技能提取并保留页码。展开页优先直接复用能说明本页内容的现有图件、原表和文档页；首次素材方案先列已有材料及最少必要处理，不先提新绘替代图。现稿及用户修改优先于过期副本。

图片搜索限于相关项目。采集器把 5 秒、2,000 个文件预算分配给各目录，排除依赖、技能资源和符号链接；不足时定向进入已知产物目录，不遍历同步盘。运行时图标、Logo 不作为实验素材，`role`、`period`、`status=unverified` 仅是候选标记。

素材按最少处理的顺序选用：原图原表直接使用；必要时裁去白边、放大相关区域或分页；已有文档可采用原页截图。材料过密时先调整展示范围，不把重画当作默认解法。展示审稿回复、申报书等较长材料的完成情况时，可在素材确认中提议导出原文PDF并缩略展示若干真实页面，同时保留完整正文及页码，不必另画框图或流程图。

默认不新绘系统框图、流程图、概念图或重绘结果曲线。只有现有材料确实无法表达必要内容，且用户明确要求或同意新绘时才制作；不因统一风格或追求图内可编辑而重画。PPT标题、正文及适用表格保持原生可编辑，原图可作为独立图片移动替换，图内像素不宣称可编辑。加工保留原件及关键标签，生成图片不替代实验或文献证据。

## 素材确认（日报第三道确认）

展开事项确认后，按事项展示候选素材，不制作最终图表、示意图或 PPTX。每项至少列出：

| 核对项 | 展示内容 |
|---|---|
| 页面重点 | 本项准备回答的研究问题、完成结果或工程判断 |
| 原始素材 | 文件路径、文档页码或数据文件；图片、文档页和结果图在对话中直接显示缩略图或可读页图，不能只给文件名、文件路径或链接；表格和数据展示关键列或结果预览 |
| 拟用方式 | 优先直接使用原图原表、必要裁切/分页、原文页面截图或仅文字说明；新绘仅列用户明确要求或同意的内容 |
| 派生内容 | 对裁切、重绘或新绘内容，说明依据的原始材料，以及准备新增的标题、分组、箭头、标注或结论 |
| 缺项与冲突 | 缺少的图、无法核实的小字、冲突的参数或仍需用户提供的材料 |

新绘示意图和重绘图表在用户批准前只提交生成方案，不生成最终素材。用户可按事项批准、替换、补充或跳过；只有全部展开事项明确为“直接使用”“批准派生”或“跳过”后，才允许进入排版和 PPTX 制作。未批准和已跳过的素材不得生成或放入成稿。

## 排版前逐页素材核对

在已有过程记录或素材清单中按页记录以下信息，供内部核对，不要求用户填写或逐页审批：

| 核对项 | 记录内容 |
|---|---|
| 页面重点 | 标题与拟用的一句结论；无配图页记录正文依据 |
| 图片来源 | 实际文件或文档入口、页码/图片位置、版本和内容哈希 |
| 对象与条件 | 图中设备或系统、测试位置、时间、驱动/本振/接收条件，以及仿真或实测状态 |
| 图内小字与参数 | 放大读取与结论相关的型号、端口、频率、单位、功率、带宽、状态和图例，与原记录对照 |
| 支持的结论 | 图直接显示什么，哪些判断还需要文字记录或对照证据；不把观察自动写成原因 |
| 核验状态 | 已核对、存在冲突或待核实，以及具体缺项与处理方式 |

实际查看每张候选图并与文字、记录交叉核对；相似文件名、外观或较新日期不能证明适用，旧台架照片也不因时间早而排除。放大读小字后，仍须确保成稿整页可读。裁切、换图或改结论后更新相关记录。来源、哈希和核查过程留在清单，不默认写上页面。

例如发射输入与接收本振频率须分别核实，不能把正文统一改过的频率套到所有端口。

冲突或缺图先查原记录及最新证据；手工稿也须核对参数和图注。仍无法核实且影响页面含义时只问关键缺口，其他页面继续。不用相似图、长段文字或占位图代替必要证据。用户允许留空时可保留插图区域，缺图记在内部清单并说明未完成，不在正文堆占位解释或当作完整结果交付。
