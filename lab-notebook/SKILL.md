# 实验准备与记录

把讨论形成的方案写成现场可执行的步骤，实验时在对应位置记录结果，让换电脑或换人的接续仍有依据。普通仿真日志和已有结果整理直接走记录流程，不要求补做实验规划。

## 开始与范围

1. 从用户指定位置或项目已有入口定位本次实验主记录，按需读取相关步骤和结果。沿用已有本地或飞书主稿；已有飞书方案时，详细操作和结果统一在飞书维护。确实没有且用户未指定在线位置时，用 [简短模板](assets/labbook-template.md) 在具体实验目录建立本地主稿，不默认创建全项目持续追加的 `labbook.md`。多处记录无法确定主稿且影响写入时，只确认主稿位置。
2. 续写前读取当前内容，保留用户手改和历史条目。默认用中文，沿用已有格式和目录，不自动重排旧记录。写前再次核对相关片段；出现并发修改时基于新内容合并，冲突未明不覆盖。
3. 实验正文开头简要写明目标和关键条件，已有内容不重复介绍。同一实验续做时更新对应步骤和批次；新的实验或测试轮次沿用项目已有产物结构分别保存，不向全项目总日志追加。用户要求停止时立即停止。
4. 按关键实验、重要修改或判断变化更新记录。讨论中的假设和建议不写成已批准方案；确认后的选择及时写入，结果产生后及时补充。普通操作不要求前后各写一遍，也不等全部工作结束才追记。

## 正文、入口与轮次材料

- 实验正文按步骤连贯呈现条件、操作、结果和结论。影响复现、结论或后续操作的重要失败及获准调整简要保留；正式结果表中的失败观测仍保留，不把每次报错和排查尝试逐条堆进正文。
- 本地入口只负责定位：优先在已有 README 放主稿链接和必要的数据位置；已有 `lab.md` 入口可沿用，不另建入口，也不在入口重复维护目标、结论、进度或详细操作。使用“直连比较实验方案”“本轮结果表”等链接名称，能定位具体步骤、文件或运行编号时不只给大目录。已有含正文的历史 `lab.md` 不自动拆分、删除或迁移；未获迁移授权时保留旧文，只维护定位链接，不再追加总日志。
- 入口按目录页写：用简短标题和链接说明“有什么、在哪里”，需要时注明“原始数据在实验室电脑”等获取信息。适用条件、验证限制和整理经过放在对应记录或恢复说明，不在入口重复铺陈“不能证明”“不代表”“本次未……”等防御性说明。会影响打开材料或选择下一步的实际缺项，直接写清具体问题；不把未经核实的位置或状态改成确定事实。
- 数据、配置、运行日志和排查依据归对应测试轮次，复用现有文件。日志未覆盖且对复现、判断或接续必要的信息，才补到该轮已有说明；没有合适载体时在该轮目录建简短排查 Markdown，不每失败一次新建文件。同一问题的连续尝试合并说明，保留关键条件变化、失败证据、处理结果及未决问题；跨轮排查互相引用，不复制整段经过。必要的轮次记录属于长期实验材料。
- 飞书暂不可达或回填受阻时，将已产生但尚未写入的信息留在对应轮次，注明目标文档、步骤和待回填内容，不另建长期同步正文。恢复后重读目标位置、合并并读回核对，标明已回填，避免重复追加。缺少当前方案时暂停依赖该方案的操作，不凭本地历史猜测继续实验。
- 没有飞书主稿时，本地具体实验正文承担相同职责；纯仿真和软件验证同样按具体测试保存，不强制创建飞书文档。

## 通用排版

本地轮次记录与飞书实验正文共用本节；规则用于指导写作，模板只展示结构，正文不另列“填写规则”。

- 参数与条件、测量结果、多项分析与判断、文件清单默认入表：条件用“参数｜单位｜内容”，结果用逐次结果表，分析用“项目｜单位｜内容”或“问题｜处理｜结果”，文件用“材料｜位置”。名称、来源、单位、精度、通道分行、缺失值及统计要求统一按 [实验指标表](../standardize-test-project/references/experiment-tables.md) 执行，按本实验选择指标。按行列参数时单设单位列，按列列参数时第二行写单位；一格一个参数，计划设定与实测结果分开，I/Q、译码前后、均值与标准差分别列项。
- 回填前读取对应步骤、完整批次及相邻内容，按用途归回已有表格，优先补行或更新单元格。同批同用途不另建小表或表外补充段，不同批次分别记录并沿用同类字段；逐次结果与统计汇总等不同用途不硬合。按实际内容选表，不强制凑齐四类表；简短仿真记录可只写一句结果和数据引用。见[续填示例](assets/labbook-template.md#已有批次继续回填示例)。
- 多项排查优先用“问题｜处理｜结果”表，同一问题的连续尝试合并，一格只说一个要点。数值对照另列参数或结果表，用测试编号对应；表格过宽时拆成设置表与结果表，沿用相同测量点或运行编号。
- 操作用编号列表，一条一个主要动作，接线、设置、采集分开。分析与判断默认并入对应分析表；一两句话能讲清且无需逐项比较时可作表注，下一步写具体动作。结果解释紧跟表格，趋势解释紧跟图，证据紧跟相关结论，不在正文重抄表内数值。
- 需要分工填写的操作单才标“（人写）”“（AI写）”：人工信息用“填写项｜内容”或“填写项｜单位｜内容”，内容格留空；AI填写的结果、图片和数据放在对应步骤后。照片、结果图和实际文件附件放在表外、紧跟对应内容。已有固定接线不重复留填写项。其他记录按实际内容命名小标题。
- 功率增量、偏差注明比较基准，首点无基准时留空。测量条件、统计口径和积分范围紧随相关表格，批次间条件差异如实注明。
- 结论直接写结果支持的判断，必要限制写具体事实，例如“本轮完成软件回放，实机效果待测”。保留真实反例、负收益及影响后续操作的限制，区分观察与推测；避免反复使用“不等于”“不代表”“不能证明”。
- 链接用有意义的名称，完整命令、配置和日志已有文件时直接引用；材料未覆盖的复现信息补入对应轮次。需要直观看到差异时嵌入关键图片，不在多个栏目重复同一产物。已上传附件改写为简短内容说明，不再要求提供同一文件；未上传的材料保留实际需求。
- 每段只说一件事，只写新增信息。正常检查保留在程序记录，正文简记异常、验收结果及必要交接状态；安全动作和操作条件照常保留。合并或移动内容后，删除原位置的重复标题和指路句，不在实验正文记录“已整理”“已集中到”等编辑经过。确有跨章节查阅需要时保留简短链接，不为链接单独成节。文档提取、整理日期、保留原值及未重跑等维护经过仅在需要追溯时放入来源或恢复说明，不在正文重复。

## 逐步准备实验

- 实验步骤按实际执行顺序组织，不按聊天讨论顺序或内容新增时间排列。每次新增、移动或修改步骤前，读取相关前后步骤，核对本步所需的设备验证、标定、输入条件和前置结果是否已在前面安排。新增内容插入对应操作位置，不默认追加到文末。写入后按操作者从头执行的顺序检查，同步修正章节编号、交叉引用和进入下一步的条件。
- 多阶段现场方案中，每个需要独立接线或信号路径的阶段至少配置一张对应的系统框图，放在该阶段操作附近。图中只保留设备、端口、信号流和必要参数；正文写操作、记录与判断，不复述图中的连接说明。写后逐阶段核对图、文、表的连接关系及参数是否一致。普通结果回填不因此补画板。
- 先读已有方案、结果及当前问题涉及的设备资料；涉及实物能力时配合 `lab-resources` 查来源。一次讨论一个影响做法的问题，能从资料查明的不重复问用户。
- 先拟好一个小实验的完整步骤，包括接线、设置、测量、记录及进入下一步的条件。起草技术方案或需要深入分析时，读取 `technical-writing` 中相关规则；普通结果回填和排查补记直接按本技能完成。经用户确认这部分正文后写入主文档，再展开下一部分；整体结构获认可后，仍须确认尚未讨论的具体正文，已确认内容直接沿用。
- 写明实际参数、测量点及顺序、每点采集次数和判断标准。已确定的数值直接写入；未知参数先查明或提出具体建议供用户判断，不自行补造。用户可在对话提供现场信息，由 AI 代填。
- 涉及可调器件时，写清起点、调节方向、观察仪表及读数、取点条件和要记录的实际设置。若测量点按输出读数的变化量确定，应从上一点读数出发，朝已确认方向调节；读数达到约定变化量时，记录当时的机械刻度或设定值。未经刻度与变化量的标定，不先选刻度再把它当作目标变化量；方向与读数的关系未查明时，不把“沿同一方向”等含糊表述写成操作指令。
- 尚未开始的实验可保留空白，随讨论和实测补充；整理文档不要求提前补齐后续章节，不自行补参数或新增测试。只有当前要执行的步骤依赖缺失条件时，才核查或请用户确认。
- 幅度核对类实验分别记录 I/Q 的幅度设定、实测峰峰值、实测 RMS 和带内积分功率，注明实际统计口径与积分范围；无关实验不强加这些项目。补算峰峰值使用对应次完整原始采集的 max(x)−min(x)，保留削顶等异常说明；缺少原始数据时留空，不用设定值替代或为补表重测。
- 保留公式、必要条件和操作动作，记录和判断跟随步骤；选做扫描和异常排查放在主流程之后。

## 现场推进与回填

- 先核对当前步骤及已批准条件；只有用户已授权上机且现有安全检查通过，才由 `link-test` 或项目程序执行仪器操作。写好方案本身不授权连接或开启仪器。
- 方案明确允许的调节和复测按约定执行并记录，不逐点重复询问。需要改变参数范围、次数、接线、处理方法或测试顺序时，先说明原因、拟改内容及影响；经用户确认后更新方案，再执行。不把建议提前写成当前操作指令。
- 异常可以先暂停，必要安全处置沿用仪器操作规则；暂停排查不等于获准更改方案继续测试。保留异常数据和已完成进度。
- 读取本次真实数据、配置和日志后，在对应步骤回填数值、判断、代表图片及可定位的数据引用，不用计划值、历史结果或推测代替实测。保留失败及获准调整的过程，不为使结果看起来完整而删掉不利记录。
- 每轮按本步骤判据判断继续还是排查；只有实际完成的步骤才记为完成。文档写入后读回核对，回填受阻时保留已保存的结果和待更新位置，不重跑测量来解决文档问题。
- 整理已填写表格时逐项搬移原值，保留精度、单位、统计口径、数据来源和图片。遇到参数矛盾或统计含义不明，先查对应采集与处理记录；缺少依据时保留原值和具体待核查项，不靠改措辞消除矛盾，不猜拆数据或把空白补为零。
- 不同模式、线缆或配置分别列批次，不覆盖旧结果或强行配成对照实验。正式对比结论放在各组之后。保留历史失败及被修正的判断，不把旧批次结论套用到新批次；改变工作点建议或科学判断前先核对依据，再请用户确认。

## 批次顺序与整节检查

- 按实际过程呈现条件、步骤、结果、分析和材料位置，图件仍紧跟对应结果；历史建议归原批次，不能混进当前工作点。旧计划与实际执行分开标明，不让已被替代的计划继续充当操作指令；调整依据缺失时查记录，不反推为已获批准。
- 普通回填检查完整相关批次；用户要求整节或全文整理时检查授权范围，不只检查刚改的段落。写前检查归属和顺序，写后读回核对：新内容是否归入原位置、旧位置是否仍重复；计划、实测和历史建议是否分清；数据矛盾是否有依据处理。同步核对数值、单位、批次、图片、附件及交叉引用。
- 重要异常保留影响、处理、最终状态与证据，未解决且影响下一步的问题留在对应步骤；保留有效差结果。未开始章节的空白不列为记录缺失，未经授权不补写或重排无关章节。

## 换电脑或对话接续

- 分析跨机实验数据前，检查实际项目根目录的 `config/data_receive.json`；已配置时按[实验数据接收](references/data-receive.md)核对目标批次的文件、冲突和参考依赖，需要时补收该批次。没有配置的电脑沿用现有材料获取方式，普通本地仿真记录不增加接收流程。
- 先沿本地入口定位主文档，读取当前步骤、上次停下的位置及相关结果，再按当前问题读取对应轮次的配置、日志、排查依据及必要代码版本和依赖；不默认通读所有历史。继续尚未完成的步骤，不重新规划整套实验或另建重复记录。沿用现有表格、单位和批次对应关系回填；需要调整表格结构时先说明，不自行改成大段流水记录。
- 只核对缺失或变化的信息：当前接线、设备占用、代码与依赖、实际控制能力及本轮操作授权。历史接线和上机授权不自动当作当前事实；能从现场已有配置和材料查明的不要求用户重新口述。
- 跨机材料用接续电脑可获取的仓库版本、附件或共享数据位置定位；旧电脑的绝对路径不能单独作为可用交接依据。缺少材料时说明具体缺项及影响，不凭旧环境验证结果声称现场已就绪。

## 随实验维护设备关联

- 涉及设备或模块的实验，新建、续写主记录时配合 `lab-resources` 查找并维护现有“测试与维护”索引：主记录链接或路径、所属项目、已实际参与的具体实物。同一云文档按稳定 token、本地按准确绝对路径查重，续写复用原索引。成员自行创建的文档在提供链接后补关联，不要求再上传实验资料。
- 接线、设置和结果写在实验正文，截图、数据及代码引用对应材料；详细排查留在测试轮次。设备索引只负责定位和关联，不自动复制正文，不删改既有测试、维修内容。按设备反查实验时沿同一关联读取原文档。
- 拟用设备不写成实际参与设备。同型号实物不明确时标为待核实；更换模块时在主记录记下变化，索引保留之前和本次实际参与的实物。
- 关联不扩大文档及附件权限。索引受阻不阻塞记录，待补关联项留在对应轮次；飞书不可达按上方待回填方式处理。恢复后先查重再补，不另建同步正文或定时任务。纯仿真等无实际设备参与的记录不强行关联设备。

## 飞书主记录

在线 Docx／Wiki 文档交给官方 `lark-doc`，文档画板交给官方 `lark-whiteboard`，按各自入口选择对应参考；联网按 `web-access` 处理。只读取当前操作需要的官方流程：

| 本次工作 | 官方交接入口 |
|---|---|
| 回填或修改已有文档 | `lark-doc` 的 `references/lark-doc-update.md`，读取当前正文及版本后局部更新 |
| 将已完整确定的内容原样导入新文档 | `lark-doc` 的“导入／空文档”入口 `references/lark-doc-create.md`，保留已确定的内容与格式 |
| 真正从零创作文档 | `lark-doc` 的 `references/lark-doc-create-workflow.md`，执行官方创建流程 |
| 操作飞书原生 Markdown 文件 | `lark-markdown`；本地 Markdown 记录本身不触发此分支 |

- 交接时传递已确认的正文、格式、目标位置和待办操作，沿用已有决定。官方创建流程需要的读者、结构等信息已有答案时直接复用；仍需创作的内容按创建流程处理，不标成原样导入来跳过流程。
- Docx 使用刚读取的基准 revision 和 block 局部追加或修改，保留人工新增内容和附件引用；版本冲突时重读合并，不能将旧草稿改用最新版本号强行覆盖。每轮写后读回，后续使用新的 block ID。
- 原生 Markdown 的 `+patch` 是完整下载后替换、再整文件覆盖，不是原子更新。发现远端变更先合并；无法安全排除并发覆盖时，保留待追加片段并说明冲突，不覆盖主记录。请求结果不明确时先读回，避免重复追加。
- 本地代码、数据和飞书记录互相引用即可，不自动同步两份正文。设备资料查询和阶段共享交给 `lab-resources`；共享时检查必要文件能否由获授权者从云端取得。

## 轮次补充记录

已有操作单时按步骤回填实验结果；必要的排查依据未被现有材料覆盖时，在对应轮次补记，用问题或关键变化作标题，时间按需注明：

- **操作与条件**：实际改了什么、测了什么，以及影响结果或复现的参数、单位、配置或代码版本。
- **结果与产物**：关键数值、统计口径、样本范围或失败现象，并链接实际数据、配置、日志或图件。
- **判断与后续**：结果支持什么判断、还有什么未确定；确有后续动作时再写。

这些是内容提示，按实际需要取用。开头简述本轮做了什么，注明仿真、离线回放或实测；同一问题的连续尝试合并更新，保留关键变化和失败依据。只有新结果或重要变化时才补记，当前进度在原处更新，重要中断及恢复经过保留在该轮材料中。

## 边界

- 仪器操作、读回验证和异常收尾由 `link-test` 或项目程序负责，本技能负责方案讨论、推进协调与主记录。仅准备方案或整理已有实验、仿真或分析记录时，不触发实际仪器操作，也不连接仪器。
- 只记录实际动作和已有材料支持的结果，保留失败、未完成和暂时判断。
- 本地或飞书主记录用于阅读和接力，复用既有运行日志与配置，不代替或删改原始数据、机器记录。
- 周报、跨项目复盘和汇报按用户另行提出的请求处理。需要 Word 时交给 [docx](../docx/SKILL.md)。
- 维护本技能时优先精简现有说明和模板，不另建记录状态机或默认增加自动化。
