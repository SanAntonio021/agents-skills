# 图片引用与图题门

Markdown 含科研图、照片、流程图或其他正式图片时，本门禁在 `CONTENT_FROZEN` 之前执行。它只核对内容与引用，不启动 Word，也不改变排版。

## 当前版本来源

多图项目应由图件工作流维护一份项目级 JSON 最终清单。清单中的 `status=confirmed` 路径是当前采用版本；单图 `record.md`、旧 manifest、文件名中的 `确认版` 或 `v3`、修改时间和 `final/` 目录都不能代替它。

清单缺失时，先由图件工作流根据用户明确确认重建；存在两个可能版本且确认记录不能消除歧义时，保持 `DRAFT`，只询问该图采用哪一版。不得为了继续导出而选择版本号最大或修改时间最新的文件。

## 冻结前检查

逐项检查：

1. 清单中的图片数量与本次文稿应出现的数量一致，每张图只有一个当前路径。
2. 图片按正文出现顺序排列；当前图号、需要调整的 Word 图号和正文交叉引用关系明确。
3. 每个引用路径都与清单逐字对应，文件存在，状态为 `confirmed`，SHA-256 和像素尺寸一致。
4. 引用路径不含 `working/`、`draft/`，也不指向被新版本取代的旧确认版。即使旧文件仍在 `final/` 中，也必须阻断。
5. 图片替代文字和紧随图片的题注均为 `图N 图题`；图题默认与当前对应正文标题逐字一致。用户确认过概括性图题时，清单必须记录例外。
6. 正文对图的引用能找到对应图片；图中主要模块、流程和核心技术在正文中有实际说明。
7. 文稿中没有“图建议”、待插图说明、候选版路径或其他图片占位内容。

任一项失败时保持 `DRAFT`，列出图号、文稿行号、当前值和期望值。修正 Markdown 或图件清单后重新检查；不能在 Word 生成阶段静默换图、改图题或补正文。

## 确定性检查

```powershell
python <skill-dir>/scripts/validate_figure_references.py `
  --manifest <project-final-manifest.json> `
  --project-root <project-root> `
  --json
```

默认检查清单中声明的全部 `markdown_references`。可重复使用 `--markdown <file.md>` 限定本次文稿。脚本核对路径、状态、哈希、尺寸、图号、替代文字、题注、引用数量和“图建议”残留；图片内容与正文对应关系仍需人工复核。

图件经用户重新确认时，先由图件工作流非覆盖地保存新文件并更新项目级最终清单，再修改 Markdown 引用并重跑本门禁。Word 中的图号需要重新编排时，先把映射写入清单或工作流记录，再由 `docx` 在新文件中处理。
