# 实验数据接收

本页指导 AI 获取分析材料，不写入实验正文。接收器是项目程序，后台运行不依赖本技能或对话保持开启。

## 定位与检查

1. 从项目 README 和本次数据位置确定实际项目根目录，读取 `config/data_receive.json` 的 `receiver` 入口及本机配置定位字段。该文件是发现入口，不代表本机已经部署；本机配置由 `local_config_env` 指定的环境变量或 `local_config` 路径定位，按实际环境展开。没有发现配置或本机配置尚不存在时，沿用已有数据、附件或共享位置，不创建配置、不安装定时任务。配置损坏或程序入口缺失时报告具体问题，不能当成已经检查通过。
2. 使用本机已有 Python，在项目根目录调用 `scripts/data_receive/receiver.py --config config/data_receive.json status --batch analysis/ID`；批次参数由实际分类及运行编号组成，例如 `analysis/ID` 或 `measurement/ID`。参数单独传递，不拼接不可信命令。读取程序返回的批次状态和缺项，而非只看退出码或目录是否存在；核对本机配置实际批准的来源和映射。
3. 核对本次分析需要的文件、接收校验状态、冲突，以及 `run_info.json` 的运行结束状态、文件清单和外部参考。检查真实文件是否可读，参考依赖是否在本机可获取；不得把实验室电脑的绝对路径直接视为本机文件。程序没有覆盖的依赖按真实配置继续查明。

## 按状态处理

| 当前状态 | 动作 |
|---|---|
| 所需文件已核验、无冲突且参考可用 | 使用对应版本分析，保留原批次及引用 |
| 尚未接收的文件缺少或云端批次待检查 | 在已有接收授权范围内执行 `scripts/data_receive/receiver.py --config config/data_receive.json once --batch analysis/ID`，完成后再次查询状态并检查文件；使用实际分类及编号，只补目标批次 |
| 已成功接收后被本地删除 | 不用普通补收绕过删除记录；说明缺少的材料，只有用户明确要求重新下载后才执行 `scripts/data_receive/receiver.py --config config/data_receive.json redownload --batch analysis/ID`，使用实际分类及编号 |
| 本地修改冲突或另存的云端新版 | 保留双方，不自行覆盖或选成同一版本；说明冲突文件及其对分析的影响，必要时请用户选择版本 |
| 已下载但待核验、文件仍变化或外部参考缺失 | 不将暂存文件当成正式完整材料；说明具体缺项。可继续不依赖缺项的分析，不能宣布批次完整 |
| 接收已暂停、鉴权失效、空间不足或状态库异常 | 报告接收器状态及项目已有处理入口，不自行解除暂停、清理文件、重建状态库或反复重试 |

失败、取消的实验同样是可用研究材料，不因实验结果差而跳过接收或删去记录。接收完成与实验成功分别判断；没有完整运行清单时，只能确认“当前云端文件已接收”，不能据此宣布整批实验材料齐全。

## 写回与边界

- 分析结果仍回填对应步骤和批次；数据位置引用实际安装文件及必要版本。正常的“已核验”“已补收”“未调用接收器”等过程只留程序日志，不写进实验正文，也不为它们另加表注或说明段。正文只保留会影响本次结果解释或后续动作的冲突、缺项及所选数据版本；不追加轮询、配置或写作规则。
- 不修改云端来源、不扫描其他备份副本、不上传或删除云端文件。跨机沿用项目相对入口和本机配置，不在技能中保存机器绝对路径或凭据。
- 本技能不安装后台任务、不部署实验室电脑的接收器、不连接仪器；单纯整理仿真记录仍可只写一句结果和数据引用。
