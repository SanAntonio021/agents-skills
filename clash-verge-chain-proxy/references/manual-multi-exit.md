# 手动多出口与多上游

适用于用户需要固定出口、手动切换供应商，并希望在同一家内自动选择节点的场景；不是所有链式
代理任务的默认架构。多条路径增加可选范围、方便对照诊断，不等于已经证明长期稳定性更好。
它们仍可能共用本机核心、TUN、DNS、物理网络或上游线路。

## 选择边界

网络传输顺序为“本机 -> 前置节点 -> 出口 -> 目标网站”；下面是策略引用关系，不能当作传输顺序：

```text
AI 规则 -> 出口选择 [select]
             |- Cli 的前置 [select] -> 上游 A / 上游 B 的节点组
             `- NOV 的前置 [select] -> 上游 A / 上游 B 的节点组

每个出口的上游节点组 [select]
  |- 自动 [url-test，候选为该出口经该供应商各节点的完整链]
  `- 单条完整链 [出口参数固定，dialer-proxy 固定为一个前置节点]

国外网站 [select]
  |- 仅走前置 [select] -> 上游 A / 上游 B 的裸节点组
  `- 出口选择 [复用 AI 的同一选择]
```

- 出口选择、每个出口的供应商选择、仅走前置的供应商选择均为 `select`。不在这些层添加
  `url-test`、`fallback`、跨供应商“自动”项或后台联动程序。
- 每家节点组可手动选一条链，也可选择该家内部的 `url-test`；需要按固定顺序容错时可使用
  家内 `fallback`。整家失效则保持失败，等用户手动换供应商；出口失效不得自动换出口。
- 对固定出口的完整链组，递归候选只能到达相同出口的代理；不得混入其他出口、裸节点或 DIRECT。
  `dialer-proxy` 指向裸前置是链的运输依赖，不是允许规则绕过出口的候选。
- `url-test` 比较延迟，不测下载带宽；完整链探测才能覆盖前置到出口这一段。探测参数与自然周期
  验收见 [延迟优先](url-test-latency-priority.md)。通用 204 成功不能代替 AI 服务专项验收。
- 使用固定出口服务也不天然保证 IP 永久不变；同一出口的多条路径仍需按回显比较验证一致性。

## 配置源与扩展模板

优先复用当前持久增强源或原生 YAML。生成时可使用一次性工具或已有订阅增强脚本，不新增常驻
联动服务。原生静态配置也可以按以下模板逐条展开；不要声称仅新增目录项就能自动生成全部组。

源文件留出明确注释区域：`上游清单`、`出口清单`、`自定义规则`、`生成的链与辅助组`。
以下是维护清单的字段约定，不是可直接交给 Mihomo 的配置：

```yaml
# 上游清单：复制一项；source 指向受保护的原始订阅或 provider 来源。
upstreams:
  - id: upstream-a
    label: 上游 A
    source: <本地来源标识>
# 出口清单：复制一项；凭据仅放在受保护的配置位置。
exits:
  - id: cli
    label: Cli · 圣何塞
    type: socks5
    server: <出口地址>
    port: 1080
    username: <账号>
    password: <密码>
# 自定义规则：记录目标策略；用户授权的例外先于宽泛 AI 进程规则。
custom_rules:
  - domain: <用户指定域名>
    policy: 仅走前置
```

维护清单须由现有生成流程显式展开，不能把上述自定义字段当作 Mihomo 自动支持的功能：

1. 按来源读取各上游的完整真实节点列表，给跨订阅节点加稳定且唯一的来源前缀；保留节点协议参数。
   来源分类不能依赖“名称含某关键词就属 A，其余全属 B”。排除信息条目、已注入的出口及旧链，
   对比来源集合与最终集合，检查缺失、多余和重复项。
2. 对每个“出口 × 上游 × 节点”克隆一个出口代理，账号地址相同，`dialer-proxy` 指向该单节点。
   再建立每个“出口 × 上游”的自动组和节点选择组，最后建立出口专属的供应商选择组。
3. 新增出口时扩展它的全部链与组，并将其供应商选择组加入 `出口选择`；新增上游时为每个出口
   增加对应链与组，同时扩展裸前置选择。删除时检查规则、组、dialer 引用，禁止悬空或循环。
4. 自定义例外在最前，随后为 AI 规则，再保留原国内、局域网和直连语义，普通国外规则走
   `国外网站`。默认 AI 仅指向 `出口选择`；例外须由用户明确指定，不把某次的域名当全局默认。

界面顺序建议：`国外网站`、`出口选择`、各出口的前置供应商选择、`仅走前置`；节点选择组靠后，
内部自动组可在当前版本支持时设 `hidden: true`。隐藏只影响展示，不是隔离候选的安全措施。
名称优先表达供应商和地区；内部唯一 ID 不强迫用户按编号理解线路。

各电脑共享配置结构、上游和规则；用 `profile: {store-selected: true}` 在本机保存选择。
不共享运行缓存或将当前 selector 值回写到共享源。相同稳定组名有利于恢复，但改名、换目录或
重新导入后仍须读回；新电脑无缓存时采用候选首项，部署前确认该初始出口符合预期。
凭据与私有订阅不能放进公开同步仓库；若生成配置含凭据，也必须按私有配置保护。

## 验收

- 静态检查组名唯一、引用完整无环、AI 规则优先、三类供应商选择均为 select；递归展开每个
  出口分支，确认候选没有跨出口或降级路径。用当前 Mihomo `-t` 检查生成 YAML。
- 在线验收分别读取持久源、最终生成配置和运行态；后处理脚本不能覆盖策略类型。结合目标请求
  和同一时段日志确认链。出口回显仅在内存比较，不记录真实 IP。
- 在隔离样本中验证单节点失效时家内自动切换、整家失效保持失败、出口失效保持失败；手动切换
  其他供应商后仍保持所选出口。模拟通过不能冒充真实供应商故障或长期稳定性验证。
- 分别验证国外网站两种模式，以及普通模式切换不影响 AI 的出口选择。临时改变线上 selector
  按 [网络诊断](network-diagnostics.md) 的并发保护规则恢复。
- 第二台电脑未实际验收前，只能说配置可同步，不能宣称跨电脑选择独立性已经验证。
