# Edge 中 Google 搜索位置的来源与出口验收

## 先确定授权边界

先把用户允许的修改范围写成清单。只允许 Edge 本机设置时，Google 账号、活动记录、家庭/工作地址、
Clash 节点和代理配置都属于范围外；这些来源即使被证明优先级更高，也只能报告，不能代用户修改。

## 分开判断六类来源

| 来源 | 可观察证据 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| Edge 浏览器定位权限 | 目标 Google origin 的 Geolocation 内容设置 | 页面是否获准请求设备位置 | `Allow` 不证明 Google 本轮实际采用设备位置 |
| Windows 定位 | 当前用户与系统的位置权限状态 | Edge 是否有机会取得系统位置 | 开启不证明 Google 页脚来自 Windows 定位 |
| Google 活动记录 | 页脚明确写“根据您的活动记录” | Google 本轮把历史活动作为位置来源 | 不能靠清 Edge 权限改变账号侧记录 |
| Google 地点/住址 | 页脚明确写“根据您的地点（住址）” | Google 本轮优先使用账号保存地点 | 代理出口正确也不会自动覆盖该账号来源 |
| 位置 Cookie | Google Cookie 中可明确识别的 `UULE` 等位置项 | 浏览器侧可能保存了短期精确位置提示 | 普通 Google 登录 Cookie 或整站数据不能一概当位置缓存删除 |
| IP 推断 | Edge 自有 tab 的出口回显与页脚明确的 IP 来源提示 | 本轮页面可能按浏览器实际出口推断位置 | 节点名和其他进程的出口不能代替 Edge 实测 |

权限状态只是能力证据。页脚中“根据您的活动记录”“根据您的地点（住址）”或 IP 来源提示，才是 Google
本轮选择来源的直接页面证据。页脚未标来源时保持不确定，不凭结果城市反推唯一来源。

## 最小 Edge 本机顺序

1. 只读记录 Edge 实际 profile、Google Geolocation 权限、Windows 定位权限和当前页面页脚。
2. 用 Edge 的 task 自有 tab 访问出口回显服务；响应只保存在内存中用于对照，不用节点名称替代。
3. 在同一时段读取 Mihomo 服务日志，定位该次 `msedge.exe` 连接的 `using` 分组与候选。
4. 若页脚指向活动记录或地点/住址，直接判定账号来源优先；Edge 本机范围内不能把它改成 IP 自动定位。
5. 只有证据指向浏览器侧位置缓存时，才检查可识别的 Google 位置 Cookie。优先只删除位置项；无法精确
   识别、工具只能清整站数据或操作可能导致退出登录时停止并报告，不做全量清理。
6. Edge 定位权限变更只影响以后页面调用设备定位，不等于清除活动记录、账号地点、Cookie 或 IP 推断。

## 同一时间窗口绑定代理证据

出口回显、Google 页脚和 Mihomo 日志必须来自同一次或紧邻的一组请求。记录浏览器、目标 URL、时间和
日志行；不要拿早先的出口测试解释后来页面的位置。

- `using <ordinary group>[<NOV chain>]` 证明该次请求命中了完整 NOV 链，再用 Edge 出口回显确认最终出口。
- `using <ordinary group>[<plain node>]` 证明该次请求已经降级到裸节点；此时页脚出现裸节点出口城市并不
  代表 Google 定位异常。
- 节点名称中的城市只描述标签，不能证明最终公网出口城市。IP 地理库冲突时保留冲突，不挑一个符合预期的库。

如果普通流量组是 `fallback`，且候选同时含 NOV 完整链和普通裸节点，那么单次命中 NOV 只证明当时可用。
它不能证明后续仍固定 NOV；健康检查失败时组会自动降级，出口可变化。固定出口是成功标准时，候选配置中
存在裸节点就应报告“出口不稳定”，除非用户另行授权修改代理设计。

## 结论分级

- **完整通过**：同一时段 Edge 出口回显符合目标出口，日志命中完整目标链，Google 页脚明确采用 IP 或
  页面位置已与该出口一致，并且没有更高优先级的活动记录/地点来源证据。
- **代理通过、Google 定位失败**：Edge 出口与完整链证据通过，但页脚仍明确来自活动记录或地点/住址，
  或页面位置仍与出口不一致。不要把代理层通过写成整体完成。
- **出口不稳定**：本次命中目标链，但活动 `fallback` 包含裸节点降级候选；单次通过不支持“固定出口”。
- **失败或不确定**：Edge 出口不符、日志命中裸节点、三类证据不在同一时间窗口，或页脚来源无法识别。

用户限制不允许处理造成失败的高优先级来源时，以相应分级结束并说明边界，不继续扩大修改范围。
