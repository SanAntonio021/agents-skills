# 输出文件所有权与非破坏性整理

科研图目录常同时保存历史定稿、其他课题图和本轮候选图。目录名称是 `final` 不表示其中所有文件都由当前任务管理，也不授权代理整理既有资产。

## 所有权判定

- 任务开始前已存在的文件视为用户资产。
- 当前任务新生成、复制或编辑出的文件才属于本轮可管理集合。
- 用户明确点名要求替换、移动、重命名或归档的既有文件，才进入本轮可管理集合。
- 无法确认来源时按既有用户资产处理。

未经用户明确授权，不得对既有用户资产执行：

- 删除
- 移动或归档
- 重命名
- 覆盖
- 改写内容或元数据

## 开始任务前

写入 `prompt/`、`working/` 或 `final/` 前，先只读列出目标目录已有文件。至少记录路径、大小和修改时间；高风险整理任务再记录哈希。

发现目标文件已存在时，不自动覆盖。使用新文件名或请求用户确认。

## 原始图与处理版

生成接口、宿主工具或网页实际提供的自然尺寸结果先作为来源文件保存。目标尺寸是生成约束，不是自动后处理授权；返回尺寸不符时，只记录偏差并保留原图。只有用户明确同意后，才能另存裁切、缩放、拉伸、补边、扩图或合成后的处理版。

- `original`：未经裁切、缩放、拉伸、补边、扩图或合成的实际返回文件。能够取得服务器文件字节时，副本必须与来源逐字节一致。
- `processed`：经用户明确授权后产生的派生版本。不得覆盖原图，也不得在记录或回复中称为原始生成图。
- 浏览器自然尺寸像素导出是重新编码结果，不属于服务器原始文件；仍须保留其未再处理的导出版，并在 `record.md` 中写清来源类型。

原图和处理版同时交付时，manifest 使用对象条目记录角色和各自尺寸。旧的纯文件名数组继续兼容：

```json
{
  "files": [
    {
      "name": "scene-original.png",
      "role": "original",
      "width": 1672,
      "height": 941
    },
    {
      "name": "scene-processed.png",
      "role": "processed",
      "width": 2048,
      "height": 1152
    }
  ]
}
```

## 最终交付

“用户要求 N 张图”约束本轮交付清单，不约束一个已存在目录中的历史文件总数。

优先顺序：

1. 在 `record.md` 中维护本轮交付文件清单。
2. 用 `verify-output.js --manifest <manifest.json>` 只验证清单中的文件。
3. 目录存在其他 PNG 时，将其报告为 `extra_files`，不移动、不删除，也不把它们视为本轮失败。
4. 用户明确要求物理隔离时，新建任务级目录，例如 `final/<task-slug>/`。
5. 用户明确要求清理既有目录时，先列出拟移动文件和目标路径，得到确认后再执行。

manifest 示例：

```json
{
  "files": [
    "fig1_final.png",
    "fig2_final.png"
  ]
}
```

统一尺寸的旧清单可以继续使用字符串条目和全局 `--width/--height`。对象条目中的逐文件尺寸优先于全局尺寸，适合原图与处理版尺寸不同的交付。

### 多图项目的唯一最终清单

同一项目包含多张图，或由多个对话分别修改图片时，在项目图件根目录维护一份项目级 JSON 最终清单。它是“当前采用哪一版”的唯一机器可读入口；各单图 `record.md`、旧 manifest 和历史 `final` 文件继续保留，但只作为过程证据。

- 每张图只能有一个 `status=confirmed` 的当前路径。
- 至少记录图号、图题、当前路径、SHA-256、像素尺寸、用户确认状态和正文引用位置；需要统一改图号时另记目标图号。
- 图题默认与当前正文标题逐字一致；用户确认过概括性图题时，在条目中写明例外和依据。
- 不按文件名中的 `v2`、`v3`、`确认版`，不按修改时间，也不按文件位于 `final/` 就判断哪一版更新。
- 用户确认新版本后，先非覆盖地保存文件，再原子更新项目级清单并重算哈希；清单通过后才能改 Markdown 引用。
- 清单缺失或互相冲突时，先根据用户明确确认和当前已批准正文重建。仍有两个可能版本时停止选择，只询问这一个版本问题。

项目级条目示例：

```json
{
  "number": 17,
  "title": "实时波束解算与控制技术",
  "status": "confirmed",
  "path": "figures/图17/final/图17_实时波束解算与控制技术_确认版_v3.png",
  "sha256": "<64位SHA-256>",
  "width": 1536,
  "height": 1024,
  "markdown_references": [
    {
      "document": "课题4.md",
      "display_number": 17
    }
  ]
}
```

验证示例：

```powershell
node <skill-dir>/scripts/verify-output.js `
  --dir <final-dir> `
  --manifest <manifest.json> `
  --expected-count 2 `
  --json
```

## 允许归档的范围

可直接移入 `working/` 或本轮归档区的内容仅限：

- 本轮生成的过程候选图
- 本轮生成后被用户明确否定的版本
- 本轮创建且已被新版本替代的临时遮罩、裁剪和诊断图

历史定稿、其他课题图、来源不明文件不属于“过程版本”。

## 冲突处理

如果目录总数与用户要求不一致：

1. 不做任何文件移动。
2. 验证本轮 manifest。
3. 报告额外文件名称及其“非本轮管理”状态。
4. 只有用户明确要求目录清理时，才提出可逆的移动方案。

如果已经误移动既有文件，立即停止后续整理，保留路径映射和哈希；先向用户说明，再经用户确认执行原位恢复。
