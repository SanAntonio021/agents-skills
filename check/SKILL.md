# 核查外部说法

用 `$check <说法或链接>` 核查可外部验证的观点、数据、参数或判断。目标是让用户知道哪些部分可以采信、哪些部分尚未证实，以及下一步怎样以最低成本降低关键不确定性。

## 路由边界

先判断请求的主要问题。下列情况不要在本技能内展开完整分析，直接说明转交目标和理由：

- 实验设计、对照设置、统计效力、结果可重复性或证据质量：转交 `rigor-check`。
- 指标是否可实现、验收口径、工程余量或性能拆解：转交 `target-feasibility`。
- 需要持续积累横纵向证据、建立项目基线或定期更新结论：转交 `baseline-research`。
- 多条技术路线存在实质取舍，需要比较代价、风险和反对意见：转交 `steelman`。

普通的单条外部说法核查留在本技能内。不要把人生选择、人格或天赋判断包装成可核查的事实。

## 工作方法

1. 明确核查对象。保留原话、参数、版本、时间范围和使用场景；链接内容要以链接实际页面或原始文件为准。
2. 拆分主张。分别标注：
   - **事实**：可由原始数据、标准、论文、官方记录或可复现测量验证。
   - **推论**：由事实推到结论时增加的假设、外推或因果解释。
   - **价值判断**：取决于目标、风险偏好、成本或约束，不能用单一事实判真伪。
3. 查证事实。优先原始来源、标准正文、论文原文、官方数据库、完整实验记录和可复现数据；二手解读只作线索。需要联网时先使用 `web-access`，并标出每项证据的来源和发布日期或数据年份。
4. 检查适用范围。逐项核对时间是否过期、测试或使用条件、样本来源与大小、统计口径、定义和单位是否一致。缺失的条件不能默认成立。
5. 处理冲突。列出相互矛盾的证据、各自的条件和质量；判断冲突是来自不同对象、不同时间、不同测量方法，还是同条件下的真正矛盾。不要以投票方式消除冲突。
6. 给出可执行结论。对每条核心事实给出高、中、低或不足以判断的可采信度；推论要写明成立前提，价值判断要写成取舍而非事实结论。
7. 给出一个最低成本核验动作。优先能直接改变当前结论的原始来源、版本记录、定义页、数据表或小范围复测，不建议泛泛的“多查资料”。

来源不足、无法访问原始材料或关键定义缺失时，明确写“证据不足以判断”，并说明缺少什么；不得用常识补全证据链。

## 输出结构

按以下结构输出，篇幅随问题复杂度调整：

```markdown
## 核查对象
原说法、时间范围、使用场景与待判问题。

## 主张拆分
| 类型 | 内容 | 当前状态 |
| --- | --- | --- |
| 事实 | ... | 已证实 / 未证实 / 证据不足 |
| 推论 | ... | 前提是否成立 |
| 价值判断 | ... | 取舍与约束 |

## 证据与条件
关键来源、发布时间或数据年份、适用条件、样本口径，以及冲突或缺口。

## 可采信度
高 / 中 / 低 / 不足以判断，并说明决定该等级的证据。

## 结论
直接回答原说法在当前条件下能否采信；把推论和价值判断与事实结论分开。

## 最低成本核验动作
一项最小、可执行、能改变结论的核验动作。
```
