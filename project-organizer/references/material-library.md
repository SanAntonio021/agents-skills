# 资料库登记衔接

本约定只在用户已指定或项目已配置资料库时使用；分类、路径及确认要求来自该资料库的 README/AGENTS，不在通用技能内写本机路径、人员、成果或指标。

## 归属与登记

- 明确属于项目、公司或提交包的文件随完整材料保存。跨主题查找通过登记关联，不为每种材料类型复制一份，不把图片、论文或演示从必要依赖中抽走。
- 沿用现有人工主登记及稳定编号。文件登记描述实际位置、类型、主题、所属主体、版本和确认状态；引用登记关联文件编号、具体章节/页码/批次、可支持的内容、条件及核实状态。机器迁移清单是操作依据，不另当一套日常维护的登记。
- 文件发生移动时保留编号，更新实际路径及受影响的引用；新文件再分配新编号。缺失记录不能凭旧路径重造另一个身份，须先查来源映射。
- 不把文件名、修改时间、最高版本号、哈希一致或用户确认正文当作实际提交、证书核验或实测依据。未知版本或引用状态标待核实，后续使用时核对并回填。
- 已提交材料包内承担提交上下文的重复附件保留，只有核对内容后才登记为相同材料副本；不能仅凭同名去重。散落副本的退役仍受具体授权和恢复检查约束。
- 既有飞书、Zotero等登记继续承担原有职责，通过标识或链接关联，不默认复制在线正文或重建其数据库，不扩大访问权限。

## 执行与验收

1. 先展示实际来源、目标、登记变更、依赖、清理范围和恢复方式；用户明确要求清单确认时，在授权覆盖前不执行搬动或关联清理。复用已有准确授权，不反复确认同一范围。
2. 迁移仍走主技能的完整性、哈希、Git恢复、引用修复及真实使用检查。材料内容未知可登记待核实；归属或依赖不明、文件锁定、未下载完整、特殊路径未解析属于对应迁移的未完成项，不以待核实标签绕过保护。
3. 验收原文件处置、编号唯一性、实际路径可达、引用编号存在、正式入口无过程目录依赖；按真实任务验证一次跨目录查找。核验失败保留原件和恢复材料。
4. 分别报告登记完成、迁移完成、内容核实及旧位置退役状态。普通任务完成不自动归入资料库；由项目约定的收尾入口承接。
