# 资料型项目布局参考

本文件是 `merge` 模式的可选设计参考，不是固定模板。先读实际内容，展示目录树；复用已明确的项目名称、分类、根目录文件、层级和独立子项目，仅询问未决取舍。目录设计与整合、清理范围可以一次确认，工具将具体内容绑定到计划。

## 适用场景

当多个来源属于同一个长期工程或研究项目，且来源主要由交付物、代码、实验、论文和资料组成时，可以先提出浅层方案。它适合减少没有语义价值的套壳目录，不适合把互相独立的项目平铺混合。

## 脱敏示例

下面的名称只是说明材料边界的示例；没有内容的分类不创建，项目可以使用中文或其他短名称。

```text
Project/
├── README.md、项目规则、常用交付物和人工入口
├── code/                         现行代码（如有）
├── hardware/                     器件、配置和采购资料（如有）
├── 实验/                        既有实验及数据内部关系（如有）
├── 论文/<论文名>/               主稿、图源和相关写作材料（如有）
└── 过程文件/本次整理/           清单、被改写原件、准备内容及检查记录
```

## 设计原则

- 常用交付物可按已确认设计放根目录；普通资料原则上只保留一层短分类。
- 实验和原始数据按已有运行关系归拢，不猜测批次归属。新输出沿用 `standardize-test-project` 已确认的 simulation、measurement、analysis、checks 分工，不借整理迁移历史结果格式。
- 论文材料按实际工程保持可编辑、可编译；实验原始数据不默认复制为长期论文副本。正式提交版本等确需冻结的材料保留其明确用途，不把所有旧目录都包装为历史版本。
- 文献继续由 Zotero 管理；本次只整理已有论文工作区材料和引用，不默认新增本地文献与精读副本。
- 当前说明与记录合并到新入口，更新实际路径；保留历史事实和独有信息，旧文件经覆盖检查及新入口验证后退役。
- 代码、实验、论文和审计可以保留必要内部层级；普通资料的浅层规则不应压平这些结构。
- 只创建有内容的目录，旧套壳目录、额外空目录和未批准例外在验收时失败。

## 过程材料与验收

清单、恢复副本和检查记录放在 `过程文件/整理主题/`，不再建立一套日常旧项目。只将这一本轮专用子树排除出业务目录比较，不跳过整个 `过程文件/`；已有其他任务材料照常保护。显式外部过程目录也可沿用。

`mapping_rules` 表达原样映射，`integration_manifest` 表达改写和合并的输入、输出与内容去向。最终目录树由实际输出形成；新入口使用检查通过、内容完整、已处理旧入口退役才算完成。用户明确要求只读或分阶段确认时按该要求执行。
