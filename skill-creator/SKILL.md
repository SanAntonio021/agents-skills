# 技能创建与修改

先读取当前任务、技能源码、已有决定与材料，复用准确授权；只问无法自行查明且会改变目标、范围或结果的关键问题。保留原名称、专业能力、来源许可及用户修改，修改已有技能时直接维护正确源码，发布交给 `agent-rules`。

## 根据实际影响选择验证

- **文字整理**：含义不变的精简、引用移动或格式修改，核对含义、引用和格式。不能只按字数判断：一句触发、授权或完成条件的修改也属于行为变化。
- **行为修改**：改变触发、提问、授权、执行或完成条件时，独立子智能体实际试跑代表性任务，检查动作与成果。推演和格式检查不能代替行为验收。
- **效果比较**：需要判断新版是否更好时做新旧对照；新建技能需要证明额外价值时与不加载技能比较。重复试跑、扩大样本和盲评用于解决已有疑问，不默认全套运行。
- **新建技能**：明确用途与触发，按实际任务选择最少必要内容，并试跑代表性任务。普通业务任务中遇到困难，不自动新建或安装技能。

## 工作步骤

1. 读当前文件及相关规则，判断实际改动范围。已有要求足够时直接工作，不重复访谈或逐阶段确认。
2. 准备最小修改，保留必要参考、脚本接口和来源；编写方法见 [编写与结构](references/authoring.md)。
3. 按上面的影响选择验证。优先使用现有用例，补本次变化涉及的场景；行为试跑与对照方法见 [实际评测](references/evaluation.md)。
4. 检查执行记录与实际产物，修复已发现问题后复查受影响部分。必要检查通过且请求完成即可交付；有新问题才继续迭代。
5. 默认在对话中分点说明关键差异、样例和限制，不要求另开网页或最终签字。大量成果逐件比较或用户指定时使用现有查看器；只有需要安装包时才打包。

## 独立试跑

测试执行者使用新上下文，只接收任务、准确的被测技能路径及必要材料，不接收修改讨论、预期答案或评分标准。明确允许写入的临时范围；涉及删除、投稿、仪器或配置时用隔离样本或模拟环境。主智能体根据实际动作、产物和原稿状态验收，而不是只读执行者的“通过”结论。

普通行为测试使用实际运行该技能的模型；中文文风效果评测默认 Opus 4.6，模型身份与上游调用别名按 [中文文风评测](references/chinese-style-evaluation.md) 核对。对照双方使用相同模型、材料、工具和权限。

直接指定加载技能后执行，验证的是行为；普通请求是否会自动加载技能，需要另外的触发测试。现有触发脚本使用 Claude，不能用其结果声称验证了 Codex/Astra 自动触发，详见 [触发优化与工具](references/tooling.md)。

## 受阻与完成

- 工具、环境或独立执行通道不可用时，继续可完成的源码及静态检查，明确保留相关未验证项；只暂停依赖该项的验收，不以推演冒充实际试跑。
- 区分结构检查、行为试跑、效果对比和运行副本生效。调用成功不代表质量提高；缺少的耗时或 Token 数据标为未知，不估造数字。
- 测试执行者完成指定业务任务即可，不为一次测试再建立技能维护循环；维护技能本身的测试只在实际被改的下层技能上执行必要业务试跑。
- 过程材料沿用共享规则的 `过程文件/任务主题/`，不默认生成额外报告、查看器或安装包。源码提交和运行时发布按实际请求分别完成。
- 保留上游 Apache-2.0 许可和接受历史。上游能力继续可用，本地默认流程以本入口为准；更新先比较差异，避免覆盖本地定制。
