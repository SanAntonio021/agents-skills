# SSD 数据盘迁移

本指引用于加装 SSD 后复制数据盘、让新盘接替原盘符，以及在布局允许时把旧数据分区空间扩给 C 盘。沿用技能入口的授权和资料保护要求；仅评估时只读检查，已批准的范围连续完成，只有新增范围或改变处理方式才需要用户决定。系统盘克隆、重装系统和移动 EFI／恢复分区另行评估，不套用数据盘复制流程。

## 1. 检查磁盘与依赖

先用只读后台接口读取当前磁盘、分区和卷信息，形成来源、目标及预期布局的对应表。记录下列事实，后续修改前重新读取：

- 物理磁盘的 `UniqueId`、序列号、型号、容量和分区样式；磁盘编号可能变化，不能单独作为身份。
- 分区 GUID（适用时）、所在磁盘、偏移、大小、类型和当前盘符；卷的标识、文件系统、健康状态及剩余空间。没有 GUID 时按磁盘身份、偏移和大小联合定位，身份仍有歧义就暂停该对象的修改。
- Windows／启动分区、EFI／恢复分区、页面文件，以及目标盘已有内容。初始化、格式化和 GPT／MBR 转换只对已核实且获准的目标执行，不能因为盘符看起来空闲就格式化；不为合并空间转成动态磁盘。
- 数据盘上的软件、服务、计划任务、启动项、同步根目录、数据库、路径链接和加密状态。只核对解锁与恢复条件，不读取或输出恢复密钥。

检查目标可用空间能容纳实际需复制的数据、必要的权限／链接结构和已知增量。容量、逻辑文件大小与实际占用分开记，不能用占位文件显示大小当作已在本地的数据量。

迁移可直接复制目录，不要求打压缩包。先按离线数据字节数、文件数量和两端能力估计耗时范围，说明这是估计；首轮复制后用实际处理量与耗时更新剩余时间，单列小文件、核验和需用户重启的时间。不要用 SSD 标称顺序速度承诺全程速度。

复用当前任务的过程目录保存必要的布局快照、复制摘要、差异清单、云文件例外，以及本次将修改的页面文件／启动项／服务原状态。不要备份整套无关配置。让新盘接替原盘符通常有助于保留路径，但软件注册、许可、卷标识及服务依赖仍须验收，不能保证全部软件免重装。

## 2. 首轮复制并保留来源

使用适用的系统或应用复制接口；不把 `Invoke-StorageCleanup.ps1` 的归档／删除流程当作卷迁移工具。大批数据可先复制已稳定的普通文件，让有活动写入的部分留到最后补拷。

- 默认复制后保留来源，不默认使用 `robocopy /MIR`、`/PURGE`、`/MOV` 或 `/MOVE`；这些选项可能删除目标或来源。先检查目标已有文件，冲突项留待比较，不覆盖目标独有或较新的资料。
- 保留必要的空目录、时间、属性、数据流及权限；根据实际需要和权限选择复制参数。Robocopy 的默认文件复制不含 ACL，不能仅凭文件内容存在宣称权限已迁移。对权限错误有限重试并列出失败项，不把拒绝访问当成成功跳过。
- 先枚举硬链接、符号链接、junction 和其他重解析点，记录类型及目标。避免跟随链接复制到范围外或循环；不能把所有重解析点按普通目录展开，也不能一概排除后宣称完整迁移。按必要链接清单保留或重建，并核验实际解析位置；硬链接只在同一卷内建立。
- 活动数据库使用应用支持的一致性备份／导出，或正常退出后补拷；单独复制正在变化的数据库文件不算完成。
- 汇总扫描、复制、跳过和失败的文件数及字节数。Robocopy 应结合退出码与日志解释结果：返回值大于等于 8 表示至少有复制失败，小于 8 仍可能有额外文件或不匹配，不能仅凭退出码验收。

### 云文件与占位文件

先读 [副本与云端核验](backup-verification.md#云端备份语义)，区分普通离线文件、同步副本和按需占位文件。扫描占位文件时优先读元数据，递归内容读取或哈希可能触发下载，不为计算总大小或校验而整盘读回。

用户选择仅保留云端时，把准确范围列为云文件例外，核对账号、远端路径、对象标识、版本／大小、上传完成和本地未上传修改。若云端将成为唯一副本，仍须有实际恢复测试；记录测试覆盖，不能把少数样本可恢复写成全部文件已读回。云端记录缺失、待上传或恢复证据不足的成员继续保留来源，只暂停依赖它们的删除。

云文件例外不等于迁移成功或删除授权。先确认新位置可用客户端支持的方式重新挂载／关联同步根目录；复制占位元数据不等于复制了文件内容，也不保证新位置能够访问云端。避免将本地移动或删除传播成云端删除。同步状态证据和实际恢复证据分别记录。

## 3. 暂停写入并完成补拷

首轮复制后，按已授权的迁移范围查明仍会写入来源的应用及守护程序。先保存正在编辑的工作，再通过正常后台退出接口暂停相关写入；不能把迁移授权扩展为强杀用户任务。只有应用确实没有后台方法且需要界面控制时，遵循当前 Computer Use 授权规则。

退出后重新检查进程、服务、守护程序和文件占用。程序被自动拉起时，先核实已有授权是否覆盖其守护或自启设置，记录修改前值；没有适用接口就给出明确的用户退出步骤，同时继续不依赖此项的复制。不要通过强停服务来绕过锁；也不要反复要求用户批准同一已授权动作。

暂停成功后比较首轮以来的新建、修改、缺失和目标较新文件，再补拷准确范围；同大小和时间相同不能单独证明内容相同。目标较新或两边都修改时保留两份并查明权威版本，不直接覆盖。补拷后重新检查写入和差异；若仍有变化，保留该项并只重做受影响部分。

验收应覆盖所有必要本地成员、空目录、失败／排除项及必要链接和权限。先做全范围元数据对照，再对新改动、冲突、关键资料及待删来源的必要保留副本核对内容和适用 SHA-256，沿用备份核验标准。记录核验数量、字节数、方法和未覆盖项；抽样或单轮补拷的哈希结果不能表述成全盘哈希一致。没有足够替代副本证据的必要成员仍保留在来源。

## 4. 换盘符、删除旧分区与扩容

先区分复制、换盘符、删除旧分区和扩容的实际授权。已批准完整准确方案时连续执行；仅批准复制时不能删除来源。最终补拷及适用副本核验完成、必要本地成员无未解决差异、云文件例外有证据和后续访问方式后，才能进入相应破坏性步骤。

1. 每次修改前重新核对物理磁盘和分区身份、当前盘符、页面文件及活动写入；不要按旧截图、旧磁盘编号或重启前的盘符执行。
2. 需要让新盘接替原数据盘盘符时，先把旧卷改成已核实空闲的临时盘符，再让目标卷接替原盘符，尽可能保留旧卷供切换后核验。盘符已被其他卷占用时先查明身份，不自动移走无关卷。
3. 新路径验证后，再按授权删除准确的旧数据分区；若布局或系统依赖使旧卷无法暂存，保留来源，先解决具体阻碍。删除前再次确认全部必要成员的独立保留依据及当前身份，不清空整块磁盘，也不附带删除恢复材料。
4. 扩容 C 盘前核对同一物理磁盘上 C 分区之后是否紧邻未分配空间、文件系统是否支持及当前可扩展上限。新 SSD 的剩余空间不能直接并到另一块磁盘的 C 盘；隔着 EFI／恢复分区时不删除或移动它们来强行扩容，说明阻碍并给出保留现布局或另行评估的选择。

遇到权限或自动审批策略拒绝时，保留实际状态和具体原因，不换 shell、工具或提权路径重试同一被拒绝的操作。只对受阻步骤给出按已核实磁盘身份定位的最短手动步骤，并说明该步会修改什么；用户完成后从后台重新读取布局再继续。不要把后台没执行写成等待重启生效。

## 5. 重启后恢复与验收

页面文件按 [页面文件检查](windows-and-wiztree.md#pagefile-inspection)处理，绝不直接删除 `pagefile.sys`。记录配置和当前生效位置的区别，只在确实需要时安排完整 Windows 重启，并在重启后读取实际状态。

恢复任务时先核对当前物理磁盘、分区、卷及盘符映射，再检查上轮完成证据；不要因“已重启”重跑旧的复制、换盘符或删除脚本。来源／目标盘符已互换时，仍按原磁盘身份识别方向，防止反向覆盖。若旧分区已删除，停止引用其盘符作为迁移来源。

只恢复本次为迁移改动的设置，依据修改前快照和用户最终选择核对页面文件、应用自启、服务和计划任务；本来禁用的无关项继续保持原状，不批量启用。设置恢复后检查实际配置、启动结果和必要的云端关联，不以“已发出启动命令”替代运行证据。

完成时核验并报告：

- 磁盘布局、身份、容量、健康状态及最终盘符；EFI／恢复分区仍在，C 盘实际扩容量与新盘占用分开列。
- 普通文件及最后补拷的核验范围、必要链接／权限、软件路径和代表性应用启动结果；未覆盖部分明确标出。
- 云文件例外的范围、远端状态、新入口和恢复测试覆盖；云端保留不能写成完整离线迁移。
- 本次改变的页面文件／启动项／服务恢复结果，以及是否还有明确需要重启的配置。没有待生效改动或待验收重启时，直接说明无需再重启。

仅余未解决成员时报告部分完成，保留相应来源和证据，不以空间目标或用户着急为由跳过验收。必要恢复副本和独有日志保留；冗余过程文件另按已授权的清理范围处理，移入回收站不计作释放空间。
